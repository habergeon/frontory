# 광고 운영 점검

## 사이트 코드에 반영한 범위

AdSense 게시자 계정은 `ca-pub-2698855152594465`입니다. 홈에는 계정 확인 메타 태그를 유지하고 `/ads.txt`에 게시자 정보를 공개합니다. 홈과 코드 실습은 같은 HTML 문서를 사용하므로 해당 문서에는 광고 실행 스크립트를 넣지 않습니다.

현재 광고 태그를 넣는 페이지는 다음 네 개입니다. 문서의 설명과 실행 결과를 확인한 범위부터 운영하며, 다른 강의에 광고를 추가하려면 콘텐츠와 화면을 먼저 검토합니다.

- `/learn/javascript/javascript-step-02/`
- `/learn/css/css-step-04/`
- `/learn/react/react-step-03/`
- `/learn/gsap/gsap-step-02/`

전체 목차, 시리즈 목차, 나머지 강의, 소개·개인정보·404에는 광고 실행 스크립트가 없습니다. 태그가 있는 네 페이지도 사이트 승인이나 실제 광고 노출을 보장하지 않습니다. 다른 사람이 저장소를 복제해 운영한다면 본인 계정으로 바꾸거나 광고 태그·계정 메타·ads.txt를 제거해야 합니다.

공개 안내 주소는 [개인정보](https://frontory.pages.dev/privacy/)와 [소개·문의](https://frontory.pages.dev/about/)입니다. 개인정보 문의는 `hefa91@gmail.com`으로 받습니다.

## AdSense 계정에서 확인할 항목

저장소에는 AdSense 계정 설정이나 관리자 로그인 정보가 없습니다. 아래 항목은 운영자가 관리 화면에서 확인해야 합니다. 문서를 배포했다는 이유로 이 설정까지 완료된 것으로 처리하지 않습니다.

1. **사이트 상태:** 사이트 목록의 `frontory.pages.dev`에서 연결 확인, `ads.txt` 인식과 심사 상태를 확인합니다. 승인 전에는 실제 광고 표시를 기대값으로 검사하지 않습니다.
2. **동의 메시지:** 개인정보 보호 및 메시지에서 공개 개인정보 URL을 등록하고 필요한 메시지를 발행합니다. EEA·영국·스위스 사용자에게 개인 맞춤 광고를 제공하려면 Google 인증 CMP와 IAB TCF 요건을 확인해야 합니다. 비개인 맞춤 광고를 선택해도 필요한 쿠키 동의가 자동으로 해결되지는 않습니다. 해당 지역의 신규 방문에서 동의·거부·선택 변경이 실제로 작동하는지 검사합니다.
3. **광고 형식:** 자동 광고 미리보기에서 코드 블록, 표, 이전·다음 링크, 실습 열기 버튼이 가려지지 않는지 확인합니다. 처음에는 화면을 덮는 형식을 끄고 필요한 본문 광고부터 검토하는 편이 좋습니다. 실제 광고가 나온 뒤 모바일에서도 확인하되 자신의 광고를 클릭하지 않습니다.
4. **제외 경로:** 계정의 페이지 제외를 추가로 사용한다면 `/`는 해당 페이지만, `/about/`, `/privacy/` 등은 필요한 범위로 지정합니다. `/` 아래 전체를 제외하면 학습 문서까지 제외됩니다. `#학습ID` 주소는 Auto ads의 페이지 제외에 사용할 수 없으므로 실습 보호는 현재 코드의 스크립트 분리로 처리합니다.
5. **분석 설정:** 홈·실습의 GA4는 광고 태그와 별개입니다. GA4의 향상된 측정, 데이터 공유, 광고 개인화와 보관 설정을 확인하고 개인정보 안내와 맞춥니다. AdSense의 동의 메시지를 발행해도 광고 태그가 없는 실습 화면의 분석 동의까지 자동 적용됐다고 판단하지 않습니다.
6. **데이터 처리 안내:** 허용한 광고 제공업체와 호스팅 로그 설정, 문의 이메일의 처리 방법이 공개 안내와 맞는지 확인합니다. 서비스 설정을 바꾸면 안내도 갱신합니다.

## 배포 후 확인

`pnpm test`, `pnpm build`, `pnpm check:deploy`로 생성 문서와 광고 경로, 배포 파일 한도를 검사합니다. 운영 주소에서는 `/ads.txt`의 일반 텍스트 응답, 두 안내 페이지의 HTML 응답, 홈의 계정 메타 태그, 네 강의의 광고 스크립트와 footer 링크를 확인합니다. 실제 광고의 배치와 동의 동작은 HTML 검사만으로 판정하지 않습니다.

심사 결과가 콘텐츠 부족이라면 문서 수만 늘리지 말고 설명·코드·실행 결과·문제 해결이 부족한 강의부터 보완합니다. 대표 강의 네 개의 확인 기록은 [예제 검증 기록](example-verification.md)에 있습니다. 다른 640개 단위를 같은 깊이로 검토했다는 뜻은 아닙니다.
