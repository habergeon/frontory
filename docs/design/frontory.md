# Frontory 초기 기반

## 목적과 범위

Frontory는 기술별 Series, Learn → Experiment → Build → Archive 방향을 채택한다. 기존 WebGL 실습을 유지하며 다른 기술의 계획과 실험 기록을 한곳에서 탐색한다. 현재는 단일 Vite 앱을 유지한다. 실행기가 여러 개로 분화할 때 apps/packages 경계를 도입하며 지금 빈 패키지와 의존성을 미리 만들지 않는다.

## 정보 구조

- 분야 → 기술 시리즈 → 학습 단계 → 단위 문서·실습·기록.
- WebGL은 기존 4단계·28단위를 유지한다. 나머지 22개 시리즈는 기초 이해·변수 실험·응용과 검증의 3단위다.
- 각 시리즈 README와 단위별 폴더를 둔다. 폴더에는 추후 작은 예제·이미지·기록을 함께 추가할 수 있다.
- 준비된 문서와 실행 예제의 상태를 구분한다. 실행 가능 예제는 WebGL 첫 장면 하나다.

## 탐색 UX

기존 select 대신 분야·검색 가능한 시리즈 카드, 순서가 보이는 단계 카드, 현재 단계의 번호 있는 목차와 이전·다음 버튼을 제공한다. 단계 카드에는 완료 수를 표시하며 색 외에 숫자·텍스트·aria-current로 현재 위치를 전달한다. 긴 목차는 접을 수 있다. 좁은 화면에서는 단계와 시리즈 카드를 줄바꿈하고 기존 실습 3분할은 탭을 유지한다.

완료 여부는 사용자가 직접 표시한다. 코드 수정·문서 열람·현재 단위 번호로 학습 완료를 추정하지 않는다. Draft의 optional progress는 not-started/in-progress/completed이며 이전 저장본은 미시작으로 읽되 코드·필기는 유지한다.

## 호환성과 저장

기존 localStorage 키와 WebGL 단위 ID, 개발 origin을 유지한다. Frontory JSON v2는 전체 94개 단위를 포함한다. WebGL JSON v1은 28개 단위만 복원하고 새 시리즈의 내용을 합쳐 보존한 뒤 한 번에 저장한다. 저장 실패 시 기존 데이터가 유지되며 성공 후 Workspace를 다시 마운트하여 화면 캐시를 갱신한다. 파일 내용이 미래 카탈로그와 다를 경우 묵시적으로 버리지 않고 거부한다. 후속 카탈로그 확장은 명시적 마이그레이션이 필요하다.

## 실행기 경계

React는 플랫폼 UI이고 실제 장면은 sandbox iframe에서 실행한다. Monaco의 JS/TS 검사를 계속 사용한다. Vue SFC, React JSX, WebGPU/WGSL은 각각 별도 빌드·worker·지원 확인 설계가 필요하다. 현재 준비 중 시리즈에 가짜 실행 코드를 넣지 않는다. iframe CSP와 브라우저 보안 설정은 유지한다.

## 검증 기준

기존 ID와 기록 보존, 신구 백업 형식 검증, 진행 상태 저장, 목차·문서 링크, 새 시리즈의 필기, 첫 장면 실행, 모바일 키보드 탐색을 확인한다. 테스트와 빌드가 통과해도 다른 GPU·브라우저에서의 실행을 보장하지 않는다.
