# About Frontory and contact

Frontory is a learning space for reading frontend concepts, changing example code, and recording what you observe. It focuses on checking how the screen and values change when you change one condition, rather than simply reading an explanation and moving on.

## What can you learn?

There are 23 series and 644 learning units, covering HTML, CSS, and JavaScript through UI frameworks, graphics, animation, and testing. A unit does not guarantee a day's workload or a level of proficiency. Check the prerequisites and choose the topics you need.

Each unit has goals, concepts, exercises, variables to observe, and completion criteria. Linked examples are starting points for experiments and may not be complete solutions to the exercises. The guides distinguish examples that run in the browser from those requiring a separate project. In particular, the available scope of features such as WebGPU depends on browser and device support.

## Experiments to read first

These four documents explain example behavior and distinguish values verified during execution from expected values for further experiments.

- [JavaScript: string input and number conversion (Korean)](../labs/fundamentals/javascript/units/02/README.md) — Explore why an empty string should not be accepted as valid input even though it converts to 0.
- [CSS: the box model and measured size (Korean)](../labs/fundamentals/css/units/04/README.md) — Calculate and compare why an element with a width of 200px measures 244px.
- [React: events and state snapshots (Korean)](../labs/frameworks/react/units/03/README.md) — Check why updating state three times in the same click can produce either 1 or 3.
- [GSAP: starting and target values (Korean)](../labs/animation/gsap/units/02/README.md) — Observe the movement ranges of to, from, and fromTo separately from styles immediately after creation.

## Documentation and verification scope

AI tools help write and revise the documents and examples. Technical explanations link to official documentation or web standards. When execution has been checked, the input conditions and verification scope are recorded too. Calculated expectations are distinguished from values observed in the browser.

Checking that an example opens and cleans up, clicking a particular button, and completing an entire exercise are different checks. Verifying some execution paths does not guarantee that all browsers and inputs work. If results differ under the documented conditions, send the execution environment and reproduction steps. Revisions and code history are available in the public repository.
