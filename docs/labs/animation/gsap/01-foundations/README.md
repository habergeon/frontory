# GSAP · 01 Tween과 Timeline

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: Tween과 시간 모델 · 편집 가능한 예제 · 저장 ID: `gsap-01`

## 목표와 학습 후 역량

- 학습 결과: Tween의 역할을 설명한다. 입력 사례: 카드 3개와 재생 버튼.
- 산출물: 진행도 0·0.5·1의 위치 표. 재생 헤드 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

DOM·CSS transform, 시간를 이해하고 기존 시작 예제의 입력과 출력을 읽을 수 있다.

## 핵심 개념과 설명

### Tween

tween은 두 값 사이를 보간한다. timeline은 여러 변화의 시간 관계를 묶는다.

### 재생 헤드

재생 위치가 현재 장면을 정한다. 같은 위치를 다시 방문해 상태를 비교할 수 있다.

## 실습 준비

기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-1.js에 카드 세 개를 gsap.timeline에 넣고 play/pause/reverse 버튼을 연결한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 카드 3개와 재생 버튼. 기준: 1초. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-1.md에 남긴다.
3. 변경 변수: duration. 변경값: 2초. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 진행도 0·0.5·1의 위치 표. 확인할 가설: 종료 위치는 같고 이동 시간만 길어진다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| duration | 1초 | 2초 | 종료 위치는 같고 이동 시간만 길어진다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 진행도 0·0.5·1의 위치 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: Tween, 재생 헤드. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 Tween 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 카드 3개와 재생 버튼.
2. 변경 변수: duration. 확인할 가설: 종료 위치는 같고 이동 시간만 길어진다. 실제 결과가 가설과 일치했는가? 재생 헤드 관점에서 근거를 설명하라.
