# GSAP · 01 Tween과 Timeline

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 기초 이해 · 문서·필기 제공 / 내장 실행 예제 제공

## 목표와 학습 후 역량

재생 위치를 바꿔도 카드 상태가 일관된다. 이를 자신의 말로 설명하고 작은 결과물로 재현하는 것이 목표입니다.

## 선수 지식

DOM·CSS transform, 시간.

## 핵심 개념과 설명

tween은 값의 변화를, timeline은 시간상의 관계를 표현합니다. duration과 easing을 분리해서 관찰합니다.

## 실습 준비

이 단위는 Frontory에서 대표 예제를 편집하고 실행할 수 있습니다. 문서의 확장 과제는 직접 구현하세요. JSX·Vue SFC·Svelte 컴포넌트를 그대로 입력하는 범용 컴파일러는 아니며 지원 범위는 아래 연결된 예제 안내에 명시합니다.

## 실습 과제

1. 공식 참고에서 이번 개념과 API의 입력·출력을 찾아 필기에 요약합니다.
2. 세 개 카드의 순차 이동을 timeline으로 구성하고 재생·정지·되감기를 연결하세요.
3. 아래 변수 중 하나만 바꾸기 전에 예상 결과를 적고, 실행 후 스크린샷·로그 또는 측정값과 비교합니다.
4. 원래 조건으로 되돌려 같은 결과를 재현하고 오류·지원 제한도 남깁니다.

## 관찰할 변수

duration, ease, overlap. 비교 시 다른 변수와 브라우저·viewport 조건은 고정합니다.

## 완료 조건

- [ ] 재생 위치를 바꿔도 카드 상태가 일관된다.
- [ ] 최소 두 조건의 예상과 실제 결과를 구분해 기록했다.
- [ ] 오류 또는 경계 조건 한 가지를 재현하고 복구 방법을 적었다.
- [ ] 실제로 수행한 내용을 기준으로 완료 상태를 직접 표시했다.

## 자가 점검

1. Tween과 Timeline에서 입력이 결과로 이어지는 경로를 설명할 수 있나요?
2. duration, ease, overlap 중 어떤 변수가 예상과 다르게 동작했으며 이유는 무엇인가요?
3. 재생 위치를 바꿔도 카드 상태가 일관된다. 이 조건이 깨지는 사례와 확인 방법은 무엇인가요?
