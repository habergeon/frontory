# GSAP · 14 Scroll과 수명주기

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 스크롤과 수명주기 · 편집 가능한 예제 · 저장 ID: `gsap-02`

## 목표와 학습 후 역량

- 학습 결과: 기존 예제 범위의 역할을 설명한다. 입력 사례: 재마운트 5회와 resize.
- 산출물: 이벤트 횟수와 전체 설명 표시 기록. 정리 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

13단위 「Refresh와 측정 시점」의 레이아웃 변경 및 Refresh 실습 결과를 준비한다.

## 핵심 개념과 설명

### 기존 예제 범위

gsap-02는 기본 scroll 이벤트와 timeline을 사용한다. ScrollTrigger를 실행하는 미리보기가 아니다.

### 정리

이벤트 제거와 스타일 복원을 함께 수행한다. 모션 감소에서는 정적인 설명을 제공한다.

## 실습 준비

기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-14.js에 기존 gsap-02를 읽고 별도 앱에 resize·dispose·모션 감소 분기를 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 재마운트 5회와 resize. 기준: 꺼짐. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-14.md에 남긴다.
3. 변경 변수: 모션 감소, 변경값: 켜짐. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 이벤트 횟수와 전체 설명 표시 기록. 확인할 가설: 모션 없이 설명이 남고 이벤트가 중복되지 않는다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                           |
| --------- | --------- | --------- | ----------------------------------------------- |
| 모션 감소 | 꺼짐      | 켜짐      | 모션 없이 설명이 남고 이벤트가 중복되지 않는다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 이벤트 횟수와 전체 설명 표시 기록. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 기존 예제 범위, 정리. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 기존 예제 범위 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 재마운트 5회와 resize.
2. 변경 변수: 모션 감소. 확인할 가설: 모션 없이 설명이 남고 이벤트가 중복되지 않는다. 실제 결과가 가설과 일치했는가? 정리 관점에서 근거를 설명하라.
