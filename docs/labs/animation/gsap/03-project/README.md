# GSAP · 28 모션 설계와 검증

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 모션 시스템 검증 · 편집 가능한 예제 · 저장 ID: `gsap-03`

## 목표와 학습 후 역량

- 학습 결과: 정보 계층의 역할을 설명한다. 입력 사례: 키보드·빠른 10회 입력·재마운트 5회.
- 산출물: 입력·접근성·정리·프레임 검증 보고서. 종합 검증 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

27단위 「실패 경로의 해제」의 자원 목록 및 반복 해제 실습 결과를 준비한다.

## 핵심 개념과 설명

### 정보 계층

움직임은 현재 단계와 다음 조작을 알려야 한다. 읽기와 입력을 방해하면 줄여야 한다.

### 종합 검증

키보드와 모션 감소는 서로 다른 실패를 찾는다. 측정과 정리 기록으로 설계 선택을 설명한다.

## 실습 준비

기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-28.js에 기존 gsap-03을 출발점으로 학습 단계 모션 시스템과 보고서를 완성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 키보드·빠른 10회 입력·재마운트 5회. 기준: 기본 거리. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-28.md에 남긴다.
3. 변경 변수: 모션. 변경값: 거리 0. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력·접근성·정리·프레임 검증 보고서. 확인할 가설: 기능과 내용 및 포커스가 보존된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 모션 | 기본 거리 | 거리 0 | 기능과 내용 및 포커스가 보존된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력·접근성·정리·프레임 검증 보고서. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 정보 계층, 종합 검증. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 정보 계층 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 키보드·빠른 10회 입력·재마운트 5회.
2. 변경 변수: 모션. 확인할 가설: 기능과 내용 및 포커스가 보존된다. 실제 결과가 가설과 일치했는가? 종합 검증 관점에서 근거를 설명하라.
