## 선수 지식

## 핵심 개념과 설명

### from과 to

to는 현재 값에서 목표로 이동한다. from은 지정값에서 기존 상태로 돌아온다.

### 초기 적용

from 계열은 생성 시 스타일에 영향을 줄 수 있다. 첫 화면의 깜박임을 따로 확인한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-2.js에 gsap.to/from/fromTo를 세 카드에 적용한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 초기 x=40 카드. 기준: to. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-2.md에 남긴다.
3. 변경 변수: API. 변경값: fromTo. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 생성 직후와 종료 후 transform 표. 확인할 가설: 명시한 시작값으로 이동 구간이 바뀐다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| API | to | fromTo | 명시한 시작값으로 이동 구간이 바뀐다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 생성 직후와 종료 후 transform 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: from과 to, 초기 적용. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

2. 변경 변수: API. 확인할 가설: 명시한 시작값으로 이동 구간이 바뀐다. 실제 결과가 가설과 일치했는가? 초기 적용 관점에서 근거를 설명하라.
