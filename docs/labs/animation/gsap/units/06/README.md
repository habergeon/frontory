# GSAP · 06 Label과 겹침

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: Tween과 시간 모델 · 편집 가능한 예제 · 저장 ID: `gsap-step-06`

## 목표와 학습 후 역량

- 학습 결과: Label의 역할을 설명한다. 입력 사례: intro·ready label.
- 산출물: 동작별 시작·끝 시간표. 상대 위치 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

5단위 「Stagger 순서」의 시작 간격 및 순서 실습 결과를 준비한다.

## 핵심 개념과 설명

### Label

label은 시간에 의미 있는 이름을 붙인다. 단계 버튼은 숫자 대신 이름으로 이동할 수 있다.

### 상대 위치

상대 위치는 앞 동작과 간격을 표현한다. 음수 간격은 동작을 겹친다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-6.js에 addLabel과 상대 위치로 제목·카드·버튼 timeline을 구성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: intro·ready label. 기준: 0초. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-6.md에 남긴다.
3. 변경 변수: 겹침. 변경값: -0.3초. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 동작별 시작·끝 시간표. 확인할 가설: 순서를 유지하며 전체 길이가 줄어든다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 겹침 | 0초 | -0.3초 | 순서를 유지하며 전체 길이가 줄어든다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 동작별 시작·끝 시간표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: Label, 상대 위치. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 Label 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: intro·ready label.
2. 변경 변수: 겹침. 확인할 가설: 순서를 유지하며 전체 길이가 줄어든다. 실제 결과가 가설과 일치했는가? 상대 위치 관점에서 근거를 설명하라.
