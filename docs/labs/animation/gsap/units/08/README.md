## 목표와 학습 후 역량

- 학습 결과: Context의 역할을 설명한다. 입력 사례: 기존 inline transform 카드.
- 산출물: 마운트 전후 스타일 표. Revert 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

7단위 「재생 제어판」의 Progress 및 동기화 실습 결과를 준비한다.

## 핵심 개념과 설명

### Context

context는 생성한 애니메이션을 묶는다. 컨테이너로 선택자 범위를 제한할 수 있다.

### Revert

revert는 이전 스타일을 복원한다. kill만으로 동일한 복원을 보장하지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-8.js에 mount에 gsap.context를 만들고 dispose에 revert를 연결한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 기존 inline transform 카드. 기준: kill. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-8.md에 남긴다.
3. 변경 변수: 정리 방식, 변경값: revert. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 마운트 전후 스타일 표. 확인할 가설: 이전 inline 스타일이 복원된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설          |
| --------- | --------- | --------- | ------------------------------ |
| 정리 방식 | kill      | revert    | 이전 inline 스타일이 복원된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
