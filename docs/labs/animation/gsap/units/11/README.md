# GSAP · 11 Scrub 추종

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 스크롤과 수명주기 · 문서 기반 직접 구현 · 저장 ID: `gsap-step-11`

## 목표와 학습 후 역량

- 학습 결과: Scrub의 역할을 설명한다. 입력 사례: 짧은 스크롤 후 정지.
- 산출물: 입력 정지와 모션 정지 시각. 읽기 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

10단위 「ScrollTrigger 등록」의 플러그인 및 경계 실습 결과를 준비한다.

## 핵심 개념과 설명

### Scrub

scrub은 스크롤 진행도를 모션에 연결한다. 숫자 값은 목표를 따라가는 시간을 둔다.

### 읽기

추종 중에도 내용을 읽을 수 있어야 한다. 텍스트 존재를 진행도에 종속시키지 않는다.

## 실습 준비

기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-11.js에 scrub true와 0.5를 비교하고 정지 뒤 진행도를 기록한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 짧은 스크롤 후 정지. 기준: true. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-11.md에 남긴다.
3. 변경 변수: scrub. 변경값: 0.5. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력 정지와 모션 정지 시각. 확인할 가설: 스크롤 정지 뒤 추종 구간이 생긴다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| scrub | true | 0.5 | 스크롤 정지 뒤 추종 구간이 생긴다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력 정지와 모션 정지 시각. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: Scrub, 읽기. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 Scrub 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 짧은 스크롤 후 정지.
2. 변경 변수: scrub. 확인할 가설: 스크롤 정지 뒤 추종 구간이 생긴다. 실제 결과가 가설과 일치했는가? 읽기 관점에서 근거를 설명하라.
