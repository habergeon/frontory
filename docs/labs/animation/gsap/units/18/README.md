# GSAP · 18 키보드 단계 이동

단계: 입력과 접근성 · 편집 가능한 예제 · 저장 ID: `gsap-step-18`

## 목표와 학습 후 역량

- 학습 결과: 동등한 조작의 역할을 설명한다. 입력 사례: 마우스와 키보드 탐색.
- 산출물: 현재 단계와 activeElement 표. 포커스 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

17단위 「Pointer와 QuickTo」의 입력 빈도 및 QuickTo 실습 결과를 준비한다.

## 핵심 개념과 설명

### 동등한 조작

native button은 Enter와 Space를 지원한다. 포인터 없이 같은 단계로 이동할 수 있어야 한다.

### 포커스

화면 이동과 포커스 이동은 별개다. 숨겨진 단계에 포커스를 남기지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-18.js에 이전·다음 버튼으로 timeline label과 현재 제목을 갱신한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 마우스와 키보드 탐색. 기준: 마우스. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-18.md에 남긴다.
3. 변경 변수: 입력. 변경값: 키보드. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 현재 단계와 activeElement 표. 확인할 가설: 동일 단계에 도달하고 포커스가 유지된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입력 | 마우스 | 키보드 | 동일 단계에 도달하고 포커스가 유지된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 현재 단계와 activeElement 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 동등한 조작, 포커스. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 동등한 조작 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 마우스와 키보드 탐색.
2. 변경 변수: 입력. 확인할 가설: 동일 단계에 도달하고 포커스가 유지된다. 실제 결과가 가설과 일치했는가? 포커스 관점에서 근거를 설명하라.
