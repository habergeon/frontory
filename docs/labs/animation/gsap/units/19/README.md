# GSAP · 19 모션 감소 대체

단계: 입력과 접근성 · 편집 가능한 예제 · 저장 ID: `gsap-step-19`

## 목표와 학습 후 역량

- 학습 결과: 사용자 선호의 역할을 설명한다. 입력 사례: 세 단계 전환.
- 산출물: 단계 내용과 버튼 작동 표. 즉시 상태 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

18단위 「키보드 단계 이동」의 동등한 조작 및 포커스 실습 결과를 준비한다.

## 핵심 개념과 설명

### 사용자 선호

모션 감소는 큰 이동을 줄이라는 신호다. 정보 자체를 없애라는 뜻은 아니다.

### 즉시 상태

모션을 생략해도 최종 상태는 적용한다. 완료 콜백에만 기능을 두면 누락될 수 있다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-19.js에 reduced-motion 분기에서 gsap.set으로 최종 스타일을 적용한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 세 단계 전환. 기준: 180px. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-19.md에 남긴다.
3. 변경 변수: 이동 거리, 변경값: 0px. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 단계 내용과 버튼 작동 표. 확인할 가설: 내용과 완료 상태가 그대로 유지된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설               |
| --------- | --------- | --------- | ----------------------------------- |
| 이동 거리 | 180px     | 0px       | 내용과 완료 상태가 그대로 유지된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 단계 내용과 버튼 작동 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 사용자 선호, 즉시 상태. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 사용자 선호 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 세 단계 전환.
2. 변경 변수: 이동 거리. 확인할 가설: 내용과 완료 상태가 그대로 유지된다. 실제 결과가 가설과 일치했는가? 즉시 상태 관점에서 근거를 설명하라.
