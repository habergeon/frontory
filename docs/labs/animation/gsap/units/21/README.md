## 목표와 학습 후 역량

- 학습 결과: 합성의 역할을 설명한다. 입력 사례: 카드 3개와 6개.
- 산출물: 자식 시작 시각과 전체 길이. Defaults 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

20단위 「완료 콜백과 중단」의 완료 의미 및 요청 세대 실습 결과를 준비한다.

## 핵심 개념과 설명

### 합성

자식 timeline은 작은 동작의 책임을 갖는다. 부모는 상대 순서를 정한다.

### Defaults

defaults는 반복 설정을 줄인다. 특수 동작은 해당 위치에서 덮어쓴다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-21.js에 제목·카드·안내 timeline 함수를 부모에 추가한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 카드 3개와 6개. 기준: 3개. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-21.md에 남긴다.
3. 변경 변수: 카드 수. 변경값: 6개. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 자식 시작 시각과 전체 길이. 확인할 가설: 자식 길이 변화가 부모 길이에 반영된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 카드 수 | 3개 | 6개 | 자식 길이 변화가 부모 길이에 반영된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 자식 시작 시각과 전체 길이. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 합성, Defaults. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 합성 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 카드 3개와 6개.
2. 변경 변수: 카드 수. 확인할 가설: 자식 길이 변화가 부모 길이에 반영된다. 실제 결과가 가설과 일치했는가? Defaults 관점에서 근거를 설명하라.
