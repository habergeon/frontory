# GSAP · 27 실패 경로의 해제

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 모션 시스템 검증 · 편집 가능한 예제 · 저장 ID: `gsap-step-27`

## 목표와 학습 후 역량

- 학습 결과: 자원 목록의 역할을 설명한다. 입력 사례: 정상·예외·중복 dispose.
- 산출물: 경로별 잔여 등록 수. 반복 해제 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

26단위 「모션 토큰」의 의미 및 변경 영향 실습 결과를 준비한다.

## 핵심 개념과 설명

### 자원 목록

이벤트·ticker·timeline은 각각 정리가 필요하다. 초기화 실패도 일부 자원을 남길 수 있다.

### 반복 해제

dispose는 두 번 호출되어도 안전해야 한다. 생성 수와 정리 수를 비교한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 gsap-01·02·03은 시작 예제다. 새 단위는 별도 로컬 GSAP 프로젝트에서 작성한다. gsap-02 미리보기는 기본 scroll 이벤트를 사용하며 ScrollTrigger는 외부 프로젝트에서 설치·등록한다. CSP와 iframe 격리는 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-27.js에 mount 중간 예외를 주입하고 dispose에서 등록 자원을 해제한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 정상·예외·중복 dispose. 기준: 정상. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-27.md에 남긴다.
3. 변경 변수: 초기화. 변경값: 중간 예외. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 경로별 잔여 등록 수. 확인할 가설: 실패 뒤에도 반복 작업이 남지 않는다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 초기화 | 정상 | 중간 예외 | 실패 뒤에도 반복 작업이 남지 않는다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 경로별 잔여 등록 수. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 자원 목록, 반복 해제. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 자원 목록 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 정상·예외·중복 dispose.
2. 변경 변수: 초기화. 확인할 가설: 실패 뒤에도 반복 작업이 남지 않는다. 실제 결과가 가설과 일치했는가? 반복 해제 관점에서 근거를 설명하라.
