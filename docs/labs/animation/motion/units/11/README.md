## 선수 지식

10단위 「AnimatePresence 기초」의 Presence 및 경계 배치 실습 결과를 준비한다.

## 핵심 개념과 설명

### 동시 전환

sync 모드는 등장과 퇴장을 함께 허용한다. 두 화면이 겹칠 수 있다.

### 순차 전환

wait는 한 자식 전환의 순서를 조정한다. 여러 목록 항목의 일반 정렬 해결책으로 쓰지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 motion-01·02·03은 Motion JS animate 기반의 제한된 예제다. React layout·AnimatePresence·hooks는 별도 로컬 React 프로젝트에 motion을 설치하고 motion/react에서 가져와 실습한다. 편집기에서 JSX가 바로 실행된다고 가정하지 않으며 CSP와 격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-11.tsx에 단일 상세 카드 전환에 mode sync와 wait를 비교한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: A→B 선택. 기준: sync. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-11.md에 남긴다.
3. 변경 변수: mode, 변경값: wait. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 등장·퇴장 순서 로그. 확인할 가설: B 등장이 A 퇴장 뒤로 이동한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| mode | sync | wait | B 등장이 A 퇴장 뒤로 이동한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 동시 전환, 순차 전환. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
