## 핵심 개념과 설명

### 포인터 상태

whileHover는 포인터 피드백을 준다. 터치와 키보드에는 같은 이벤트가 없을 수 있다.

### Focus

whileFocus와 focus-visible 스타일은 키보드 경로를 드러낸다. 시각 효과만으로 선택 상태를 전달하지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 motion-01·02·03은 Motion JS animate 기반의 제한된 예제다. React layout·AnimatePresence·hooks는 별도 로컬 React 프로젝트에 motion을 설치하고 motion/react에서 가져와 실습한다. 편집기에서 JSX가 바로 실행된다고 가정하지 않으며 CSP와 격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-15.tsx에 카드 버튼에 whileHover·whileFocus와 명시적 선택 텍스트를 둔다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 마우스 진입과 Tab. 기준: 포인터. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-15.md에 남긴다.
3. 변경 변수: 입력, 변경값: 키보드. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 두 입력의 강조와 선택 표시 표. 확인할 가설: 키보드에서도 조작 대상을 확인한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
