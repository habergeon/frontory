## 목표와 학습 후 역량

- 학습 결과: 명시적 순서의 역할을 설명한다. 입력 사례: 가운데 카드를 한 칸 위로 이동.
- 산출물: 입력 방식별 ID 배열. 동등한 대안 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

18단위 「관성과 탄성」의 Momentum 및 Elastic 실습 결과를 준비한다.

## 핵심 개념과 설명

### 명시적 순서

데이터 배열이 순서의 기준이다. 드래그 결과도 같은 배열을 갱신해야 한다.

### 동등한 대안

위·아래 버튼은 포인터 없이 재정렬하게 한다. 변경 결과를 텍스트로 알려야 한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 motion-01·02·03은 Motion JS animate 기반의 제한된 예제다. React layout·AnimatePresence·hooks는 별도 로컬 React 프로젝트에 motion을 설치하고 motion/react에서 가져와 실습한다. 편집기에서 JSX가 바로 실행된다고 가정하지 않으며 CSP와 격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-19.tsx에 카드에 위·아래 버튼과 순서 상태 안내를 추가한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 가운데 카드를 한 칸 위로 이동. 기준: drag. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-19.md에 남긴다.
3. 변경 변수: 조작, 변경값: 위 버튼. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력 방식별 ID 배열. 확인할 가설: 두 방식이 같은 순서 배열을 만든다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설              |
| ---- | --------- | --------- | ---------------------------------- |
| 조작 | drag      | 위 버튼   | 두 방식이 같은 순서 배열을 만든다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력 방식별 ID 배열. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 명시적 순서, 동등한 대안. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
