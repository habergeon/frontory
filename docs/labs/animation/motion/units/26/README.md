## 핵심 개념과 설명

### 렌더 비용

React 렌더와 애니메이션 프레임은 다른 작업이다. 두 지표를 구분해서 관찰한다.

### 실측

카드 수 증가는 레이아웃 비용을 바꿀 수 있다. 자동으로 더 빠르다고 결론내리지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 motion-01·02·03은 Motion JS animate 기반의 제한된 예제다. React layout·AnimatePresence·hooks는 별도 로컬 React 프로젝트에 motion을 설치하고 motion/react에서 가져와 실습한다. 편집기에서 JSX가 바로 실행된다고 가정하지 않으며 CSP와 격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-26.tsx에 Profiler와 Performance로 재정렬을 기록한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 카드 20개와 100개. 기준: 20개. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-26.md에 남긴다.
3. 변경 변수: 카드 수, 변경값: 100개. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 렌더 수·프레임 분포 기록. 확인할 가설: 측정된 비용과 병목이 달라질 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수    | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                |
| ------- | --------- | --------- | ------------------------------------ |
| 카드 수 | 20개      | 100개     | 측정된 비용과 병목이 달라질 수 있다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
