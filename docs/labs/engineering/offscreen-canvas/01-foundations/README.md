# OffscreenCanvas · 01 Canvas 제어권 이전

## 목표와 학습 후 역량

지원·미지원 경로 모두 빈 화면 없이 안내한다. 이를 자신의 말로 설명하고 작은 결과물로 재현하는 것이 목표입니다.

## 선수 지식

Canvas 2D·Web Workers.

## 핵심 개념과 설명

transferControlToOffscreen은 Canvas 제어를 분리합니다. DOM 측 크기·입력 정보는 메시지로 전달해야 합니다.

## 실습 준비

이 단위는 Frontory에서 대표 예제를 편집하고 실행할 수 있습니다. 문서의 확장 과제는 직접 구현하세요. JSX·Vue SFC·Svelte 컴포넌트를 그대로 입력하는 범용 컴파일러는 아니며 지원 범위는 아래 연결된 예제 안내에 명시합니다.

## 실습 과제

1. 공식 참고에서 이번 개념과 API의 입력·출력을 찾아 필기에 요약합니다.
2. feature detection 후 Worker에 Canvas를 전달하고 미지원 시 메인 스레드 Canvas로 대체하세요.
3. 아래 변수 중 하나만 바꾸기 전에 예상 결과를 적고, 실행 후 스크린샷·로그 또는 측정값과 비교합니다.
4. 원래 조건으로 되돌려 같은 결과를 재현하고 오류·지원 제한도 남깁니다.

## 관찰할 변수

지원 여부, 초기 크기. 비교 시 다른 변수와 브라우저·viewport 조건은 고정합니다.

## 완료 조건

- [ ] 지원·미지원 경로 모두 빈 화면 없이 안내한다.
- [ ] 최소 두 조건의 예상과 실제 결과를 구분해 기록했다.
- [ ] 오류 또는 경계 조건 한 가지를 재현하고 복구 방법을 적었다.
- [ ] 실제로 수행한 내용을 기준으로 완료 상태를 직접 표시했다.

## 자가 점검

1. Canvas 제어권 이전에서 입력이 결과로 이어지는 경로를 설명할 수 있나요?
2. 지원 여부, 초기 크기 중 어떤 변수가 예상과 다르게 동작했으며 이유는 무엇인가요?
3. 지원·미지원 경로 모두 빈 화면 없이 안내한다. 이 조건이 깨지는 사례와 확인 방법은 무엇인가요?
