단계: 크기와 입력 동기화 · 편집 가능한 예제 · 저장 ID: `offscreen-canvas-02`

## 목표와 학습 후 역량

- 학습 결과: 단위 계약의 역할을 설명한다. 입력 사례: 빠른 resize 중 중앙 선택.
- 산출물: 크기 seq·선택 ID·선명도 기록. 순서 보존 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

13단위 「Pointer Capture와 취소」의 Capture 및 Cancel 실습 결과를 준비한다.

## 핵심 개념과 설명

### 단위 계약

크기·DPR·포인터는 같은 좌표 기준으로 해석해야 한다. Worker는 DOM 배치를 추측하지 않는다.

### 순서 보존

최신 resize seq와 입력 시점을 함께 기록한다. 오래된 크기가 최신 선택을 덮으면 안 된다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-14.js에 기존 offscreen-canvas-02를 확장해 ResizeObserver·seq·로컬 입력을 통합한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 빠른 resize 중 중앙 선택. 기준: 1. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-14.md에 남긴다.
3. 변경 변수: DPR, 변경값: 2. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 크기 seq·선택 ID·선명도 기록. 확인할 가설: 선명도와 선택 위치가 유지된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설          |
| ---- | --------- | --------- | ------------------------------ |
| DPR  | 1         | 2         | 선명도와 선택 위치가 유지된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 크기 seq·선택 ID·선명도 기록. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 단위 계약, 순서 보존. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

2. 변경 변수: DPR. 확인할 가설: 선명도와 선택 위치가 유지된다. 실제 결과가 가설과 일치했는가? 순서 보존 관점에서 근거를 설명하라.
