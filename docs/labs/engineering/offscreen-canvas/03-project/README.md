- 학습 결과: 분리 효과의 역할을 설명한다. 입력 사례: resize·입력·종료·재실행·미지원.
- 산출물: 입력 지연·프레임·정리·fallback 보고서. 완료 조건 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

27단위 「실험 결과 정리」의 분포 및 한계 실습 결과를 준비한다.

## 핵심 개념과 설명

### 분리 효과

Worker는 메인에서 렌더 작업을 옮긴다. GPU 작업 자체를 없애는 것은 아니다.

### 완료 조건

응답성뿐 아니라 종료와 재실행도 기능이다. 오류와 미지원 경로까지 결과를 남긴다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-28.js에 기존 offscreen-canvas-03을 참고해 두 모드 입자 장면과 평가 보고서를 완성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: resize·입력·종료·재실행·미지원. 기준: 메인. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-28.md에 남긴다.
3. 변경 변수: 렌더 모드. 변경값: Worker. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력 지연·프레임·정리·fallback 보고서. 확인할 가설: 동일 장면에서 효과와 비용을 근거로 선택한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 렌더 모드 | 메인 | Worker | 동일 장면에서 효과와 비용을 근거로 선택한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력 지연·프레임·정리·fallback 보고서. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 분리 효과, 완료 조건. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
