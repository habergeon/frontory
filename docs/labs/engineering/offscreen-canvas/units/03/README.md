# OffscreenCanvas · 03 초기화 핸드셰이크

단계: 제어권과 첫 렌더 · 문서 기반 직접 구현 · 저장 ID: `offscreen-canvas-step-03`

## 목표와 학습 후 역량

- 학습 결과: Ready의 역할을 설명한다. 입력 사례: 초기화 직후 색 변경.
- 산출물: 메시지 순서와 첫 적용 색상. 대기 입력 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

2단위 「렌더러 계약」의 순수 상태 및 소유 범위 실습 결과를 준비한다.

## 핵심 개념과 설명

### Ready

Canvas 전달 뒤 바로 입력을 보내면 초기화 전 도착할 수 있다. ready 응답으로 준비 상태를 알린다.

### 대기 입력

준비 전 입력은 보류하거나 마지막 값만 저장한다. 무한 대기에는 오류 경로가 필요하다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-3.js에 init·ready·error 메시지와 준비 전 마지막 입력 보관을 구현한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 초기화 직후 색 변경. 기준: ready 뒤. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-3.md에 남긴다.
3. 변경 변수: 입력 시점. 변경값: ready 전. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 메시지 순서와 첫 적용 색상. 확인할 가설: 준비 후 마지막 입력이 반영된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입력 시점 | ready 뒤 | ready 전 | 준비 후 마지막 입력이 반영된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 메시지 순서와 첫 적용 색상. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: Ready, 대기 입력. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 Ready 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 초기화 직후 색 변경.
2. 변경 변수: 입력 시점. 확인할 가설: 준비 후 마지막 입력이 반영된다. 실제 결과가 가설과 일치했는가? 대기 입력 관점에서 근거를 설명하라.
