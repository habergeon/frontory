## 핵심 개념과 설명

### Context

getContext는 요청한 종류를 만들지 못할 수 있다. null을 정상 렌더러처럼 사용하면 안 된다.

### 복구 Canvas

이미 이전한 HTML Canvas는 그대로 재이전하지 않는다. 새 DOM Canvas로 대체해 fallback을 만든다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-4.js에 Worker getContext 결과를 검사하고 실패를 메인으로 보낸다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 강제 context 실패. 기준: 정상. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-4.md에 남긴다.
3. 변경 변수: 초기화, 변경값: 실패 주입. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 실패 안내와 대체 Canvas 렌더 결과. 확인할 가설: 새 Canvas에서 메인 렌더가 복구된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
