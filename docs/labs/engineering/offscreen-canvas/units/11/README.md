## 목표와 학습 후 역량

- 학습 결과: 로컬 좌표의 역할을 설명한다. 입력 사례: 중앙·네 모서리 클릭.
- 산출물: 입력 좌표와 선택 입자 ID. 스케일 일치 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

10단위 「DPR 변경 감지」의 환경 변화 및 해상도 상한 실습 결과를 준비한다.

## 핵심 개념과 설명

### 로컬 좌표

clientX/Y는 viewport 기준이다. Canvas rect의 위치를 빼 로컬 CSS 좌표로 바꾼다.

### 스케일 일치

렌더가 CSS 단위이면 포인터에 DPR을 다시 곱하지 않는다. 중복 배율은 선택 위치를 어긋나게 한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-11.js에 getBoundingClientRect로 좌표를 바꾸고 Worker에 pointer 메시지를 보낸다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 중앙·네 모서리 클릭. 기준: 1. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-11.md에 남긴다.
3. 변경 변수: DPR, 변경값: 2. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력 좌표와 선택 입자 ID. 확인할 가설: 같은 화면 위치에서 같은 입자를 선택한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| DPR | 1 | 2 | 같은 화면 위치에서 같은 입자를 선택한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력 좌표와 선택 입자 ID. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 로컬 좌표, 스케일 일치. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
