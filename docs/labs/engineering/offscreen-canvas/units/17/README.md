## 목표와 학습 후 역량

- 학습 결과: Pause의 역할을 설명한다. 입력 사례: 2초 정지 후 재개.
- 산출물: 정지 중 프레임 수와 재개 위치. 시간 기준 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

16단위 「입자 데이터 배치」의 TypedArray 및 소유권 실습 결과를 준비한다.

## 핵심 개념과 설명

### Pause

정지는 상태를 보존하면서 프레임 예약을 멈춘다. 종료와 달리 Canvas 소유권은 유지된다.

### 시간 기준

재개 시 이전 타임스탬프를 재설정한다. 정지 시간을 이동 시간으로 더하면 점프가 생긴다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-17.js에 pause/resume 메시지와 마지막 시각 초기화를 구현한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 2초 정지 후 재개. 기준: 이전 값 유지. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-17.md에 남긴다.
3. 변경 변수: 재개 시각. 변경값: 초기화. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 정지 중 프레임 수와 재개 위치. 확인할 가설: 재개 첫 프레임의 큰 점프가 줄어든다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건

- [ ] 필수 산출물: 정지 중 프레임 수와 재개 위치. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: Pause, 시간 기준. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
