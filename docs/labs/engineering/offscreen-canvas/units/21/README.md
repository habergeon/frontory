## 목표와 학습 후 역량

- 학습 결과: 오류 구분의 역할을 설명한다. 입력 사례: 초기 오류와 렌더 중 오류.
- 산출물: 오류 안내·선택 모드·장면 보존 표. 대체 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

20단위 「재시작 Canvas」의 재이전 제한 및 재시작 상태 실습 결과를 준비한다.

## 핵심 개념과 설명

### 오류 구분

렌더 계산 오류와 Worker 로딩 오류는 원인이 다르다. 메인에서 상태를 복구할 책임이 있다.

### 대체

오류 뒤 새 Canvas의 메인 렌더러로 전환할 수 있다. 이미 이전된 context를 되찾는 방식은 아니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-21.js에 worker.onerror 및 error 메시지에서 fallback 재초기화를 수행한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 초기 오류와 렌더 중 오류. 기준: 초기화. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-21.md에 남긴다.
3. 변경 변수: 실패 시점, 변경값: 렌더 중. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 오류 안내·선택 모드·장면 보존 표. 확인할 가설: 두 경로 모두 안내와 조작이 복구된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 실패 시점 | 초기화 | 렌더 중 | 두 경로 모두 안내와 조작이 복구된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 오류 안내·선택 모드·장면 보존 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 오류 구분, 대체. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 오류 구분 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 초기 오류와 렌더 중 오류.
2. 변경 변수: 실패 시점. 확인할 가설: 두 경로 모두 안내와 조작이 복구된다. 실제 결과가 가설과 일치했는가? 대체 관점에서 근거를 설명하라.
