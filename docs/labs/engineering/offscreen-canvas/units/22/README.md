- 산출물: 표시·폐기·close 횟수. 자원 수명 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

21단위 「Worker 장애 복구」의 오류 구분 및 대체 실습 결과를 준비한다.

## 핵심 개념과 설명

### 프레임 전달

OffscreenCanvas 결과를 ImageBitmap으로 넘길 수 있다. 직접 제어권 이전과 다른 출력 방식이다.

### 자원 수명

bitmap을 표시한 뒤 더 쓰지 않으면 닫는다. 전달 속도가 표시 속도를 넘으면 큐를 제한한다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-22.js에 Worker의 transferToImageBitmap과 메인의 bitmap 표시 경로를 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 연속 프레임 30개. 기준: 즉시. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-22.md에 남긴다.
3. 변경 변수: 소비 속도. 변경값: 느리게. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 표시·폐기·close 횟수. 확인할 가설: 느린 소비에서도 대기 bitmap 수가 제한된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
