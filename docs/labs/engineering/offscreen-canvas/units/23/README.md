- 산출물: 중단 안내와 장면 재생성 기록. 복구 자료 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

22단위 「ImageBitmap 전달」의 프레임 전달 및 자원 수명 실습 결과를 준비한다.

## 핵심 개념과 설명

### 손실

렌더 context는 환경에 따라 손실될 수 있다. 이벤트 지원 여부와 실제 경로를 구분한다.

### 복구 자료

장면 상태와 자원 생성 정보를 보관해야 다시 그릴 수 있다. Canvas 픽셀만으로 원래 상태를 복원하기 어렵다.

## 실습 준비

기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-23.js에 contextlost/contextrestored 처리와 초기화 함수 재호출 경로를 작성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 지원 환경의 손실 또는 명시적 실패 주입. 기준: 상태 보관 없음. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-23.md에 남긴다.
3. 변경 변수: 복구 상태. 변경값: 상태 보관. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 중단 안내와 장면 재생성 기록. 확인할 가설: 재생성 뒤 같은 장면 데이터를 그릴 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건

- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 손실, 복구 자료. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
