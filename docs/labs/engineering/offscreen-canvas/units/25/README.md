- 학습 결과: 픽셀 비용의 역할을 설명한다. 입력 사례: 동일 장면과 두 DPR.
- 산출물: 픽셀 수·프레임 분포 표. 측정 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

24단위 「요청과 화면 지연」의 시각 반영 및 측정 구분 실습 결과를 준비한다.

## 핵심 개념과 설명

### 픽셀 비용

DPR 증가는 저장소 픽셀 수를 제곱으로 늘린다. 입자 수와 별도로 영향을 준다.

### 측정

Worker 분리가 GPU 비용을 없애지는 않는다. 두 모드에서 같은 해상도를 사용한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-25.js에 입자 수를 고정하고 DPR별 프레임 duration을 수집한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 동일 장면과 두 DPR. 기준: 1. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-25.md에 남긴다.
3. 변경 변수: DPR, 변경값: 2. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 픽셀 수·프레임 분포 표. 확인할 가설: 픽셀 수가 네 배가 되고 비용이 달라질 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| DPR | 1 | 2 | 픽셀 수가 네 배가 되고 비용이 달라질 수 있다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 픽셀 수·프레임 분포 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 픽셀 비용, 측정. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 픽셀 비용 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 동일 장면과 두 DPR.
2. 변경 변수: DPR. 확인할 가설: 픽셀 수가 네 배가 되고 비용이 달라질 수 있다. 실제 결과가 가설과 일치했는가? 측정 관점에서 근거를 설명하라.
