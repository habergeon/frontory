# OffscreenCanvas · 27 실험 결과 정리

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 응답성 비교 프로젝트 · 편집 가능한 예제 · 저장 ID: `offscreen-canvas-step-27`

## 목표와 학습 후 역량

- 학습 결과: 분포의 역할을 설명한다. 입력 사례: 반복 실행 3회.
- 산출물: 조건과 원시값을 포함한 비교 표. 한계 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

26단위 「메인 스레드 경쟁 실험」의 경쟁 작업 및 공정한 비교 실습 결과를 준비한다.

## 핵심 개념과 설명

### 분포

평균만으로 순간 정지를 볼 수 없다. 중앙값과 긴 프레임을 함께 정리한다.

### 한계

장치·브라우저·전력 상태가 결과에 영향을 준다. 측정하지 않은 환경으로 결론을 확장하지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 offscreen-canvas-01·02·03은 지원 브라우저에서 사용하는 시작 예제다. 새 단위는 별도 로컬 HTTP 프로젝트의 메인·Worker 파일에서 구현한다. API와 context 지원을 확인하고 이전 실패 시 새 Canvas의 메인 fallback을 제공한다. CSP와 격리는 유지하며 성능 수치를 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-27.js에 결과 JSON을 모아 모드·입자 수·DPR별 비교 표를 작성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 반복 실행 3회. 기준: 메인 먼저. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-27.md에 남긴다.
3. 변경 변수: 실행 순서, 변경값: Worker 먼저. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 조건과 원시값을 포함한 비교 표. 확인할 가설: 워밍업이나 순서 효과를 확인할 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건   | 예상할 변화·검증 가설                  |
| --------- | --------- | ----------- | -------------------------------------- |
| 실행 순서 | 메인 먼저 | Worker 먼저 | 워밍업이나 순서 효과를 확인할 수 있다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 조건과 원시값을 포함한 비교 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 분포, 한계. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 분포 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 반복 실행 3회.
2. 변경 변수: 실행 순서. 확인할 가설: 워밍업이나 순서 효과를 확인할 수 있다. 실제 결과가 가설과 일치했는가? 한계 관점에서 근거를 설명하라.
