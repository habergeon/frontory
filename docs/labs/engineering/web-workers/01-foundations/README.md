# Web Workers · 01 메시지와 실행 경계

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 메시지와 실행 문맥 · 편집 가능한 예제 · 저장 ID: `web-workers-01`

## 목표와 학습 후 역량

- 학습 결과: Worker 문맥의 역할을 설명한다. 입력 사례: ID와 정수 배열 3개.
- 산출물: 요청별 합계와 UI 입력 반응 기록. 요청 식별 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

JavaScript 비동기·TypedArray를 이해하고 기존 시작 예제의 입력과 출력을 읽을 수 있다.

## 핵심 개념과 설명

### Worker 문맥

Worker는 메인 스레드와 별도 문맥에서 실행된다. DOM 갱신은 메시지를 받은 메인 측이 담당한다.

### 요청 식별

완료 순서는 요청 순서와 다를 수 있다. 입력·결과·오류에 requestId를 유지한다.

## 실습 준비

기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-1.js에 main.js와 worker.js를 만들고 new Worker 및 postMessage로 합계를 요청한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: ID와 정수 배열 3개. 기준: 100개. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-1.md에 남긴다.
3. 변경 변수: 배열 길이. 변경값: 100000개. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 요청별 합계와 UI 입력 반응 기록. 확인할 가설: 계산 중에도 메인 입력 처리가 가능해야 한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건
