## 목표와 학습 후 역량

- 학습 결과: 태그의 역할을 설명한다. 입력 사례: 정상·누락 ID·문자열 배열.
- 산출물: 입력별 수락·거부 표. 검증 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

2단위 「모듈 Worker 로딩」의 Module Worker 및 로딩 실패 실습 결과를 준비한다.

## 핵심 개념과 설명

### 태그

type은 메시지의 의미를 구별한다. 모든 메시지를 같은 데이터 모양으로 해석하면 오류가 난다.

### 검증

Worker 수신 값도 검증해야 한다. requestId와 배열 타입을 확인한 후 계산한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-3.js에 run·result·error 메시지 구조와 수신 검사 함수를 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 정상·누락 ID·문자열 배열. 기준: 정수 배열. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-3.md에 남긴다.
3. 변경 변수: 입력. 변경값: 잘못된 객체. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 입력별 수락·거부 표. 확인할 가설: 잘못된 요청만 거부하고 다음 요청은 처리한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입력 | 정수 배열 | 잘못된 객체 | 잘못된 요청만 거부하고 다음 요청은 처리한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 입력별 수락·거부 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 태그, 검증. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 태그 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 정상·누락 ID·문자열 배열.
2. 변경 변수: 입력. 확인할 가설: 잘못된 요청만 거부하고 다음 요청은 처리한다. 실제 결과가 가설과 일치했는가? 검증 관점에서 근거를 설명하라.
