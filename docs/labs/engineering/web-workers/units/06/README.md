## 선수 지식

5단위 「TypedArray와 Buffer」의 View 및 Offset 실습 결과를 준비한다.

## 핵심 개념과 설명

### 작업 오류

계산 예외는 요청 단위 실패다. Worker 자체의 로딩·실행 오류와 구별한다.

### 정리

실패한 요청도 pending 목록에서 제거한다. 다른 유효 요청은 계속 처리할 수 있다.

## 실습 준비

기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-6.js에 try/catch에서 requestId가 있는 error 응답을 만들고 메인 pending을 정리한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 0·음수·허용 초과 크기. 기준: 허용 범위. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-6.md에 남긴다.
3. 변경 변수: 크기. 변경값: 상한 초과. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 요청별 상태와 pending 크기. 확인할 가설: 실패 뒤 pending이 남지 않는다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
