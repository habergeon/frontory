## 핵심 개념과 설명

### 분리

Worker는 CPU 작업을 메인 이벤트 루프에서 옮긴다. 전체 계산 시간을 줄인다는 보장은 없다.

### 기준 실험

동일 입력과 계산을 메인·Worker에 사용해야 한다. UI 입력 반응과 결과 정확도를 함께 기록한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-7.js에 계산 함수를 공유하고 실행 모드 및 클릭 카운터를 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 같은 배열과 계산 중 클릭. 기준: 메인. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-7.md에 남긴다.
3. 변경 변수: 모드, 변경값: Worker. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 두 모드의 합계·입력 지연. 확인할 가설: 정확도는 같고 입력 지연 양상이 달라질 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 모드 | 메인 | Worker | 정확도는 같고 입력 지연 양상이 달라질 수 있다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 두 모드의 합계·입력 지연. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 분리, 기준 실험. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
