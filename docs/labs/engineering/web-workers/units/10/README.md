## 핵심 개념과 설명

### 왕복 소유권

Worker가 받은 버퍼를 다시 이전할 수 있다. 어느 시점에 누가 소유하는지 명시해야 한다.

### 풀 상태

available·inFlight 상태를 구분하면 중복 사용을 막는다. 반환 전에는 UI가 원본 view를 읽지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-10.js에 Worker가 배열을 갱신한 뒤 buffer를 transfer로 반환하도록 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 버퍼 2개와 연속 요청. 기준: 1개. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-10.md에 남긴다.
3. 변경 변수: 버퍼 수, 변경값: 2개. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 요청별 소유자와 값 변화 표. 확인할 가설: 동시에 사용할 수 있는 버퍼 수가 제한된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수    | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                     |
| ------- | --------- | --------- | ----------------------------------------- |
| 버퍼 수 | 1개       | 2개       | 동시에 사용할 수 있는 버퍼 수가 제한된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 요청별 소유자와 값 변화 표. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 왕복 소유권, 풀 상태. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
