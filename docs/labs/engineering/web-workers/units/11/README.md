## 핵심 개념과 설명

### 최신 요청

검색 같은 UI는 최신 입력 결과만 필요하다. 먼저 시작한 작업이 늦게 끝날 수 있다.

### 계산 취소 구별

오래된 결과를 무시해도 계산은 계속될 수 있다. 비용 절감과 화면 정합성을 구별한다.

## 실습 준비

기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-11.js에 latestRequestId와 응답 ID를 비교하고 폐기 횟수를 센다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 큰 작업 뒤 작은 작업. 기준: 완료 뒤. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-11.md에 남긴다.
3. 변경 변수: 요청 간격. 변경값: 빠른 연속. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 응답 순서와 화면에 채택된 ID. 확인할 가설: 오래된 결과가 최신 화면을 덮지 않는다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건

- [ ] 필수 산출물: 응답 순서와 화면에 채택된 ID. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 최신 요청, 계산 취소 구별. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
