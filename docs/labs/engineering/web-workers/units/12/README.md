## 선수 지식

11단위 「오래된 결과 거부」의 최신 요청 및 계산 취소 구별 실습 결과를 준비한다.

## 핵심 개념과 설명

### 이벤트 루프

긴 동기 루프 동안 cancel 메시지를 처리할 수 없다. 작업을 나누어 이벤트 루프에 제어를 돌려줘야 한다.

### 취소 지점

chunk 사이에 취소 플래그를 검사한다. Promise microtask만 반복하는 것으로 메시지 처리를 보장하지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-12.js에 배열을 chunk로 계산하고 setTimeout으로 다음 chunk를 예약하며 cancel을 처리한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 계산 중 cancel 요청. 기준: 1000개. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-12.md에 남긴다.
3. 변경 변수: chunk 크기, 변경값: 100000개. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 취소 확인 시점과 처리 원소 수. 확인할 가설: 큰 chunk에서 취소 반응이 늦어질 수 있다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수       | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                    |
| ---------- | --------- | --------- | ---------------------------------------- |
| chunk 크기 | 1000개    | 100000개  | 큰 chunk에서 취소 반응이 늦어질 수 있다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 취소 확인 시점과 처리 원소 수. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 이벤트 루프, 취소 지점. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
