## 핵심 개념과 설명

### 보고 빈도

매 원소마다 메시지를 보내면 통신량이 커진다. 진행도는 chunk 경계 등으로 제한한다.

### 단조 증가

한 요청의 진행도는 완료까지 감소하지 않아야 한다. 요청 ID가 바뀌면 새 진행도로 초기화한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-15.js에 완료 원소 수를 progress 메시지로 보내고 최신 ID만 표시한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 100개 chunk의 작업. 기준: 매 chunk. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-15.md에 남긴다.
3. 변경 변수: 보고 주기, 변경값: 10 chunk마다. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 메시지 수와 진행률 순서. 확인할 가설: 메시지는 줄고 최종 100%는 유지된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 보고 주기 | 매 chunk | 10 chunk마다 | 메시지는 줄고 최종 100%는 유지된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
