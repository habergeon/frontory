## 선수 지식

17단위 「Worker Pool」의 병렬성 및 유휴 배정 실습 결과를 준비한다.

## 핵심 개념과 설명

### 완료 순서

짧은 작업이 먼저 끝날 수 있다. 화면이 제출 순서를 요구하면 별도 조립이 필요하다.

### 인덱스

작업 index로 결과 슬롯을 정한다. 완료 개수로 위치를 정하면 결과가 섞인다.

## 실습 준비

기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-18.js에 각 요청에 index를 넣고 Promise 결과를 슬롯별로 모은다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 크기가 다른 배열 4개. 기준: 도착 순서. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-18.md에 남긴다.
3. 변경 변수: 표시 정책. 변경값: 제출 순서. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 제출·완료·표시 순서 표. 확인할 가설: 계산 완료가 뒤섞여도 출력 배열은 안정적이다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수
