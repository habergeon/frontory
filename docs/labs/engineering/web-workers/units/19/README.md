## 핵심 개념과 설명

### 시간 제한

timeout은 응답이 늦다는 판단이다. Worker 계산이 자동 중단되는 것은 아니다.

### 완료 단일화

한 요청은 한 번만 완료되어야 한다. timeout 뒤 늦은 응답은 폐기한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-19.js에 요청별 타이머와 settled 검사를 만들고 늦은 응답을 주입한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 정상·지연·중복 응답. 기준: 충분히 길게. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-19.md에 남긴다.
3. 변경 변수: 제한 시간, 변경값: 지연보다 짧게. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 요청별 완료 횟수와 pending 크기. 확인할 가설: 실패는 한 번만 기록되고 늦은 응답은 무시된다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
