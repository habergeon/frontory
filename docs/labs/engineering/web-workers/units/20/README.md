## 핵심 개념과 설명

### Worker 장애

error 이벤트는 여러 진행 작업에 영향을 줄 수 있다. 해당 Worker에 배정된 요청을 찾아야 한다.

### 재시도

재시도는 부작용 없는 작업에서 신중히 한다. 횟수 상한이 없으면 장애 루프가 된다.

## 실습 준비

기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-20.js에 특정 입력에서 오류를 발생시키고 pool 교체 및 한 번 재시도를 구현한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 정상 작업과 장애 작업. 기준: 0회. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-20.md에 남긴다.
3. 변경 변수: 재시도 상한. 변경값: 1회. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 교체 횟수·최종 오류·완료 ID. 확인할 가설: 무한 재생성 없이 결과 또는 오류로 끝난다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건

- [ ] 필수 산출물: 교체 횟수·최종 오류·완료 ID. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
