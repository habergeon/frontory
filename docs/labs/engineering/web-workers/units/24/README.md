## 선수 지식

23단위 「공유 메모리 조건」의 격리 및 대체 실습 결과를 준비한다.

## 핵심 개념과 설명

### 경쟁

공유 메모리는 복사 없이 같은 저장소를 본다. 동시 갱신에는 경쟁 조건이 생긴다.

### Atomics

Atomics는 공유 정수 접근의 동기화를 제공한다. 메인 스레드를 블로킹하는 대기 방식은 피한다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 기존 web-workers-01·02·03은 시작 예제이며 새 과제는 별도 로컬 HTTP 프로젝트의 main.js와 worker.js로 작성한다. CSP와 iframe 격리를 유지한다. SharedArrayBuffer는 자신이 통제하는 외부 서버의 COOP·COEP 조건을 확인하며 미충족 시 transfer 경로를 사용한다. 성능 수치는 직접 측정한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 src/day-24.js에 격리된 외부 프로젝트의 Worker 두 개에서 Atomics.add 카운터를 비교한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 각 Worker 10000회 증가. 기준: 일반 읽기·쓰기. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-24.md에 남긴다.
3. 변경 변수: 갱신. 변경값: Atomics.add. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 최종 카운터와 기대값 20000. 확인할 가설: 원자적 경로에서 증가분이 유실되지 않는다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
