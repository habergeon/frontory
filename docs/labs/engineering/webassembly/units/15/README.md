## 목표와 학습 후 역량

- 학습 결과: 덮어쓰기의 역할을 설명한다. 입력 사례: 음수·0·양수 배열.
- 산출물: 모든 원소의 기대·실제 값. 반복 조건 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

14단위 「배열과 경계 비용」의 메모리 배치 및 View 수명 실습 결과를 준비한다.

## 핵심 개념과 설명

### 덮어쓰기

transform은 입력 메모리를 직접 수정한다. 원본이 필요한 비교에는 복사본이 필요하다.

### 반복 조건

변환된 결과를 다시 입력하면 계산 값이 계속 커진다. 반복마다 원본을 복원해야 공정하다.

## 실습 준비

iframe 미리보기는 WebAssembly.Memory와 JS 기준 계산 실험이며 실제 Wasm 모듈 실행으로 표시하지 않는다. 실제 모듈 실습은 별도 Node 22+ 또는 통제한 로컬 웹 프로젝트에서 한다. 기존 src/labs/webassembly-02·03의 kernel.wat·kernel.wasm·benchmark.mjs를 사용하며 WAT 수정 시 공식 wat2wasm 도구로 다시 빌드한다. CSP·격리를 완화하지 않고 측정값은 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 day-15.mjs에 기존 transform(0,n) 전 source를 set하고 JS의 2x+1 결과와 비교한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 음수·0·양수 배열. 기준: 없음. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-15.md에 남긴다.
3. 변경 변수: 입력 복원. 변경값: 반복마다 복원. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 모든 원소의 기대·실제 값. 확인할 가설: 반복마다 동일한 계산을 비교한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입력 복원 | 없음 | 반복마다 복원 | 반복마다 동일한 계산을 비교한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 모든 원소의 기대·실제 값. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 덮어쓰기, 반복 조건. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 덮어쓰기 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 음수·0·양수 배열.
2. 변경 변수: 입력 복원. 확인할 가설: 반복마다 동일한 계산을 비교한다. 실제 결과가 가설과 일치했는가? 반복 조건 관점에서 근거를 설명하라.
