## 목표와 학습 후 역량

- 학습 결과: 캐시의 역할을 설명한다. 입력 사례: 정상 버전과 오래된 바이너리.
- 산출물: 소스 해시·바이너리 해시·검사 결과. 버전 처리 근거를 코드와 연결해 설명한다.

## 선수 지식

21단위 「Worker와 Wasm」의 실행 위치 및 전송 비용 실습 결과를 준비한다.

## 핵심 개념과 설명

### 캐시

컴파일된 모듈을 재사용하면 준비 비용을 줄일 수 있다. 소스 변경 후 이전 바이너리를 쓰면 검증이 틀린다.

### 버전

소스·바이너리·빌드 도구 버전을 함께 기록한다. 파일 이름만 같다고 같은 코드라고 보지 않는다.

## 실습 준비

iframe 미리보기는 WebAssembly.Memory와 JS 기준 계산 실험이며 실제 Wasm 모듈 실행으로 표시하지 않는다. 실제 모듈 실습은 별도 Node 22+ 또는 통제한 로컬 웹 프로젝트에서 한다. 기존 src/labs/webassembly-02·03의 kernel.wat·kernel.wasm·benchmark.mjs를 사용하며 WAT 수정 시 공식 wat2wasm 도구로 다시 빌드한다. CSP·격리를 완화하지 않고 측정값은 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 day-22.mjs에 별도 앱에 모듈 버전 메타데이터를 두고 빌드 후 export 검사를 수행한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 정상 버전과 오래된 바이너리. 기준: 새 빌드. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-22.md에 남긴다.
3. 변경 변수: 바이너리. 변경값: 이전 빌드. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 소스 해시·바이너리 해시·검사 결과. 확인할 가설: 버전 불일치를 발견해 비교 대상에서 제외한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.
