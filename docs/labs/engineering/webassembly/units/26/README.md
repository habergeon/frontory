## 핵심 개념과 설명

### 정확도 우선

성능 비교 전에 출력 계약이 같아야 한다. 빈 배열과 음수도 정상 범위에 포함할지 정한다.

### 오차 기준

정수는 비트 폭을 맞추고 실수는 허용 오차를 정한다. 임의 오차 허용으로 버그를 숨기지 않는다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. iframe 미리보기는 WebAssembly.Memory와 JS 기준 계산 실험이며 실제 Wasm 모듈 실행으로 표시하지 않는다. 실제 모듈 실습은 별도 Node 22+ 또는 통제한 로컬 웹 프로젝트에서 한다. 기존 src/labs/webassembly-02·03의 kernel.wat·kernel.wasm·benchmark.mjs를 사용하며 WAT 수정 시 공식 wat2wasm 도구로 다시 빌드한다. CSP·격리를 완화하지 않고 측정값은 직접 기록한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 day-26.mjs에 node:assert로 빈·단일·경계 길이·음수 입력을 JS 기준과 비교한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 0·1·1003 길이 배열. 기준: 작은 정수. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-26.md에 남긴다.
3. 변경 변수: 데이터, 변경값: 경계 정수. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 사례별 PASS 또는 실패 차이. 확인할 가설: 수치 계약이 어긋난 경우를 드러낸다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수   | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설               |
| ------ | --------- | --------- | ----------------------------------- |
| 데이터 | 작은 정수 | 경계 정수 | 수치 계약이 어긋난 경우를 드러낸다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 사례별 PASS 또는 실패 차이. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 정확도 우선, 오차 기준. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 정확도 우선 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 0·1·1003 길이 배열.
2. 변경 변수: 데이터. 확인할 가설: 수치 계약이 어긋난 경우를 드러낸다. 실제 결과가 가설과 일치했는가? 오차 기준 관점에서 근거를 설명하라.
