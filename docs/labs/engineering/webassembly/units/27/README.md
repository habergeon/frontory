## 선수 지식

26단위 「경계값 정확도」의 정확도 우선 및 오차 기준 실습 결과를 준비한다.

## 핵심 개념과 설명

### 재현성

런타임·장치·입력 크기는 결과를 바꾼다. 결과 수치에 환경을 붙여야 한다.

### 채택 기준

속도 외에 빌드·배포·복구 비용도 고려한다. 작은 입력에서 이점이 없을 수 있다.

## 실습 준비

iframe 미리보기는 WebAssembly.Memory와 JS 기준 계산 실험이며 실제 Wasm 모듈 실행으로 표시하지 않는다. 실제 모듈 실습은 별도 Node 22+ 또는 통제한 로컬 웹 프로젝트에서 한다. 기존 src/labs/webassembly-02·03의 kernel.wat·kernel.wasm·benchmark.mjs를 사용하며 WAT 수정 시 공식 wat2wasm 도구로 다시 빌드한다. CSP·격리를 완화하지 않고 측정값은 직접 기록한다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 별도 실습 프로젝트의 day-27.mjs에 원시 결과 JSON과 환경 정보를 모아 선택 근거 표를 만든다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 작은·중간·큰 배열. 기준: 작게. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-27.md에 남긴다.
3. 변경 변수: 입력 크기. 변경값: 크게. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 조건별 정확도·총비용·유지보수 판단. 확인할 가설: 이점이 생기는 조건과 없는 조건을 구분한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 완료 조건

- [ ] 필수 산출물: 조건별 정확도·총비용·유지보수 판단. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고, 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 재현성, 채택 기준. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.
