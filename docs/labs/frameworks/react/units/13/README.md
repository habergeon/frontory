# React · 13 요청 경합과 취소

## 목표와 학습 후 역량

- 최종 검색어 B와 결과 id가 일치한다.
- 제거 후 완료된 응답이 화면 갱신을 요청하지 않는다.

## 선수 지식

13단위는 12단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 응답 순서

요청을 보낸 순서와 응답 순서는 다를 수 있습니다. 최신 입력에 대응하는 결과만 화면에 반영해야 합니다.

### 취소와 무시

AbortController는 지원하는 요청을 중단합니다. 이미 완료된 처리까지 막으려면 활성 플래그나 요청 id 검사가 필요할 수 있습니다.

## 실습 준비

별도 React Vite 프로젝트의 JSX 실습입니다. Node와 패키지 버전·lockfile을 기록하고 프로젝트 개발 서버에서 실행하세요. 내장 편집기는 범용 JSX 컴파일러가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/Search.jsx에 query 의존 Effect와 AbortController를 작성하세요.
2. src/fakeSearch.js에서 A 응답 800ms·B 응답 100ms를 재현하세요.
3. A 직후 B를 입력하고 cleanup 및 최신 요청 검사로 B 결과가 유지되게 하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 응답 지연 | A 100ms·B 100ms | A 800ms·B 100ms | 늦은 A가 최신 B 결과를 덮지 않는다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
