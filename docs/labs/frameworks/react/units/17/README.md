## 목표와 학습 후 역량

- A와 B의 문자열이 섞이지 않는다.
- key 변경 시 초기화되는 필드를 두 개 이상 구분한다.

## 선수 지식

17단위는 16단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 트리 정체성

같은 위치의 같은 컴포넌트는 상태를 보존합니다. key를 바꾸면 새 컴포넌트로 취급해 로컬 상태가 초기화됩니다.

### 영속 초안

사라지는 에디터보다 오래 살아야 하는 데이터는 상위 저장소가 소유합니다. 커서 위치 같은 임시 UI 상태는 에디터에 남길 수 있습니다.

## 실습 준비

별도 React Vite 프로젝트의 JSX 실습입니다. Node와 패키지 버전·lockfile을 기록하고 프로젝트 개발 서버에서 실행하세요. 내장 편집기는 범용 JSX 컴파일러가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/NoteEditor.jsx에 단위 key와 로컬 커서 표시를 추가하세요.
2. App의 draftsById에 실제 문자열을 저장하세요.
3. A 입력→B 입력→A 복귀 후 문자열과 로컬 상태의 차이를 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 에디터 key | 고정 | unitId | 로컬 UI는 초기화되지만 상위 초안은 보존된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
