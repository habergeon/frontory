# React · 20 전환과 지연된 결과

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 필기 보존과 렌더 측정 · 문서 기반 직접 구현 · 저장 ID: `react-step-20`

## 목표와 학습 후 역량

- 입력창에 마지막 문자열이 정확히 남는다.
- 지연 중임을 표시하고 최종 결과가 최신 입력과 일치한다.

## 선수 지식

20단위는 19단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 긴급 입력

입력 문자열은 사용자가 즉시 확인할 값입니다. 비용 큰 결과 갱신과 같은 우선순위로 다룰 필요는 없습니다.

### 지연된 값

useDeferredValue는 이전 값을 잠시 보여 주며 새 결과 렌더를 준비합니다. 느린 자식을 memo로 감싸고 다른 props도 안정적으로 유지해야 긴급 입력 렌더에서 자식 작업을 건너뛸 수 있으며 debounce와는 다릅니다.

## 실습 준비

별도 React Vite 프로젝트의 JSX 실습입니다. Node와 패키지 버전·lockfile을 기록하고 프로젝트 개발 서버에서 실행하세요. 내장 편집기는 범용 JSX 컴파일러가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/LargeList.jsx에 5000개 제목 필터를 만들고 memo로 감싸세요. 목록 데이터와 이벤트 props의 참조를 안정적으로 유지하세요.
2. 부모에서 useDeferredValue로 query를 지연하고 memo 경계 안의 LargeList에 deferredQuery를 전달하세요. 이 실습은 React Compiler 자동 메모이제이션을 가정하지 않습니다.
3. CPU 지연 조건에서 memo 없는 대조군과 비교하세요. 입력 10회의 반응, 목록 렌더 로그, 지연 표시와 최종 검색 결과를 기록하세요.
