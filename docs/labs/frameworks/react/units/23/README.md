## 목표와 학습 후 역량

- DOM 카드 행이 50개 이하이다.
- 필터 변경 후 빈 잘못된 페이지에 머무르지 않는다.

## 선수 지식

23단위는 22단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### DOM 비용

많은 행은 React 계산뿐 아니라 레이아웃과 DOM 메모리를 늘립니다. 화면에 필요한 범위를 제한하면 다른 비용도 바뀝니다.

### 페이지와 접근성

페이지 나누기는 구현과 키보드 탐색을 단순하게 유지합니다. 항목 수와 현재 범위를 알려 사용자가 위치를 파악하게 합니다.

## 실습 준비

별도 React Vite 프로젝트의 JSX 실습입니다. Node와 패키지 버전·lockfile을 기록하고 프로젝트 개발 서버에서 실행하세요. 내장 편집기는 범용 JSX 컴파일러가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/PagedList.jsx에 페이지당 50개와 이전·다음 버튼을 구현하세요.
2. 1000개 카드를 필터링한 뒤 slice하고 전체 결과 수를 표시하세요.
3. 마지막 페이지에서 필터를 바꿔 현재 페이지를 유효 범위로 조정하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 페이지 크기 | 1000개 | 50개 | DOM 행 수가 최대 50개로 줄고 전체 결과 수는 유지된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건
