## 선수 지식

26단위는 25단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 사용자 계약

테스트는 내부 Hook 이름보다 사용자가 입력하고 보는 결과를 확인합니다. 구현을 바꿔도 계약이 같으면 검증을 유지할 수 있습니다.

### 격리

테스트마다 저장소와 입력 데이터를 초기화해야 결과가 독립적입니다. 시간을 기다리는 대신 화면 조건으로 완료를 판단합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 React Vite 프로젝트의 JSX 실습입니다. Node와 패키지 버전·lockfile을 기록하고 프로젝트 개발 서버에서 실행하세요. 내장 편집기는 범용 JSX 컴파일러가 아닙니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 프로젝트 tests/notes.spec.js에 카드 추가·토글·단위 전환 흐름을 작성하세요.
2. A와 B 초안·빈 검색·요청 역전의 기대 출력도 검증하세요.
3. 저장소를 비운 새 컨텍스트에서 각 시나리오를 다시 실행하세요.

## 관찰할 변수

| 초기 저장소 | 빈 저장소 | A 초안 있음 | 초기 기대값만 달라지고 이후 편집 계약은 같다. |
