# Svelte · 06 keyed each와 카드 정체성

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 컴파일과 runes 기초 · 문서 기반 직접 구현 · 저장 ID: `svelte-step-06`

## 목표와 학습 후 역량

- 역순 정렬 후 A가 원래 카드 id에 남는다.
- 삭제한 카드의 로컬 입력이 다른 카드로 이동하지 않는다.

## 선수 지식

6단위는 5단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 키 있는 반복

{#each items as item (item.id)}는 데이터 id와 컴포넌트를 연결합니다. 순서가 바뀌어도 같은 항목을 추적할 수 있습니다.

### 로컬 입력

행 내부 입력 상태는 데이터와 연결되어야 합니다. key가 불안정하면 정렬 후 다른 카드에 입력이 붙을 수 있습니다.

## 실습 준비

별도 Svelte 5 Vite 프로젝트에서 .svelte 파일을 컴파일해 실행합니다. 패키지 버전과 lockfile을 기록하세요. Frontory의 Svelte 미리보기는 실제 writable와 명시적 DOM 어댑터이며 .svelte 컴파일러나 runes 실행기가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/CardRow.svelte에 로컬 메모 input을 추가하세요.
2. CardList.svelte에서 id를 key로 사용하는 each를 작성하세요.
3. 첫 카드에 A를 입력하고 역순 정렬한 뒤 A가 붙은 id를 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| key | 배열 순번 | item.id | 정렬 뒤 메모가 같은 카드에 남는다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
