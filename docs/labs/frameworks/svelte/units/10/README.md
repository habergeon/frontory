단계: 컴포넌트 계약과 Effect · 문서 기반 직접 구현 · 저장 ID: `svelte-step-10`

## 목표와 학습 후 역량

- 두 표현의 카드 id 순서가 같다.
- 상세 표현에만 완료 설명이 추가된다.

## 선수 지식

10단위는 9단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### snippet

snippet은 재사용할 마크업 조각을 정의합니다. 매개변수로 데이터를 받고 {@render}로 표시합니다.

### 구성 경계

목록 계산과 행 표시를 분리하면 같은 데이터를 다른 형태로 보여 줄 수 있습니다. 표시 조각이 원본 데이터를 변경하지 않게 합니다.

## 실습 준비

별도 Svelte 5 Vite 프로젝트에서 .svelte 파일을 컴파일해 실행합니다. 패키지 버전과 lockfile을 기록하세요. Frontory의 Svelte 미리보기는 실제 writable와 명시적 DOM 어댑터이며 .svelte 컴파일러나 runes 실행기가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/CardList.svelte에 행 snippet prop을 받는 구조를 만드세요.
2. 부모에서 compact와 detailed snippet을 각각 정의하세요.
3. 같은 필터 결과에 두 snippet을 적용하고 id·개수 일치를 확인하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 행 표시 | compact | detailed | 카드 개수와 순서는 같고 표시 정보만 달라진다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
