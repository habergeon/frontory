# Svelte · 17 Context로 작업공간 연결

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: store와 작업공간 상태 · 문서 기반 직접 구현 · 저장 ID: `svelte-step-17`

## 목표와 학습 후 역량

- 각 트리에서 최신 문자열이 함께 보인다.
- 다른 트리의 초안이 변경되지 않는다.

## 선수 지식

17단위는 16단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### Context

setContext와 getContext는 컴포넌트 트리 안에서 의존성을 전달합니다. 전역 단일 저장소와 달리 트리마다 범위를 나눌 수 있습니다.

### 반응형 객체

Context에 반응형 객체를 전달하면 소비자는 그 객체를 읽습니다. 참조를 통째로 바꾸는 대신 공유 계약을 유지하는 방법을 정합니다.

## 실습 준비

별도 Svelte 5 Vite 프로젝트에서 .svelte 파일을 컴파일해 실행합니다. 패키지 버전과 lockfile을 기록하세요. Frontory의 Svelte 미리보기는 실제 writable와 명시적 DOM 어댑터이며 .svelte 컴파일러나 runes 실행기가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/Workspace.svelte에서 Symbol 키로 notes 객체와 update 함수를 setContext하세요.
2. 깊은 NoteEditor.svelte에서 getContext로 읽으세요.
3. 중첩 Workspace 두 개에서 같은 id를 편집하고 분리 여부를 확인하세요.
