# Svelte · 21 key 블록과 초안 보존

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: store와 작업공간 상태 · 문서 기반 직접 구현 · 저장 ID: `svelte-step-21`

## 목표와 학습 후 역량

- A와 B 초안이 섞이지 않는다.
- key 변경 뒤 편집 횟수가 초기값이다.

## 선수 지식

21단위는 20단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 재생성

{#key unitId}는 값이 바뀔 때 블록을 재생성합니다. 로컬 상태를 의도적으로 초기화할 때 사용할 수 있습니다.

### 보존 위치

단위별 초안은 key 블록 바깥에 두어야 전환에도 남습니다. 커서나 임시 패널 상태는 별도 초기화 정책을 정합니다.

## 실습 준비

별도 Svelte 5 Vite 프로젝트에서 .svelte 파일을 컴파일해 실행합니다. 패키지 버전과 lockfile을 기록하세요. Frontory의 Svelte 미리보기는 실제 writable와 명시적 DOM 어댑터이며 .svelte 컴파일러나 runes 실행기가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. src/App.svelte에서 draftsById를 만들고 Editor를 {#key unitId}로 감싸세요.
2. 문자열은 부모에 저장하고 에디터의 로컬 편집 횟수를 표시하세요.
3. A→B→A로 전환해 초안과 편집 횟수를 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| key | 고정 값 | unitId | 초안은 남지만 로컬 편집 횟수는 초기화된다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
