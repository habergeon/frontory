## 목표와 학습 후 역량

- 두 데이터 크기의 입력 10회 기록이 있다.

## 선수 지식

25단위는 24단위 결과물과 실험 기록을 이어 사용합니다.

## 핵심 개념과 설명

### 컴파일 산출물

소스 길이와 브라우저가 실행하는 결과는 다릅니다. 빌드 결과를 보고 어떤 코드와 의존성이 포함되는지 확인합니다.

### 공정한 측정

같은 데이터·입력·빌드 모드에서 비교해야 합니다. React의 Profiler 수치를 Svelte 전체 렌더 시간과 같은 지표로 취급하지 않습니다.

## 실습 준비

별도 Svelte 5 Vite 프로젝트에서 .svelte 파일을 컴파일해 실행합니다. 패키지 버전과 lockfile을 기록하세요. Frontory의 Svelte 미리보기는 실제 writable와 명시적 DOM 어댑터이며 .svelte 컴파일러나 runes 실행기가 아닙니다. Frontory 내장 실행 예제가 없는 확장 단위이며 아래 파일은 외부 실습 프로젝트에 작성합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 외부 프로젝트를 빌드하고 dist 자산 크기와 설정을 notes/build.md에 기록하세요.
2. 100개와 1000개 카드에서 같은 필터 입력 10회를 측정하세요.
3. 브라우저 성능 기록에서 스크립트·레이아웃 구간을 구분하세요.

## 관찰할 변수

| --- | --- | --- | --- |
| 카드 수 | 100개 | 1000개 | 갱신 비용 변화를 측정하며 선형 증가를 가정하지 않는다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
