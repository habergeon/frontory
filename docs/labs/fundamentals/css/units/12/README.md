## 핵심 개념과 설명

### 명시 배치

grid-area로 시각적 영역을 지정할 수 있습니다. 시각 순서 변경이 DOM 읽기 순서를 바꾸지는 않습니다.

### 순서 일치

키보드와 보조 기술의 순서를 함께 확인합니다. order나 영역 배치로 논리 흐름을 뒤집지 않도록 합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구로 확인하세요. 별도 폴더의 index.html에 콘텐츠를 만들고 link rel="stylesheet"로 실습 CSS를 연결하세요. 개발자 도구에서 뷰포트·계산 스타일·성능 기록을 확인합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. index.html에 탐색·본문·보조 영역과 링크 6개 조건의 콘텐츠를 준비하고 grid-areas.css를 연결하세요.
2. header·nav·main·aside를 영역으로 배치하고 좁은 화면용 한 열 배치를 작성하세요.
3. 탐색·본문·보조 영역과 링크 6개 조건으로 실행하세요. 확인할 결과: 두 화면의 시각 순서와 Tab 순서를 비교한다. 최종 배치에서 주요 내용의 논리 순서가 유지된다. 예상과 실제 결과는 구분해 기록하세요.

## 연결된 예제와 실행 범위

[예제 원본](../../../../../../src/labs/css-step-12/example.js) · [실행 환경과 제한](../../../../../examples.md)

실제 CSS 문서를 렌더하고 DOM 치수와 계산 스타일을 검사합니다. Shadow DOM에서 문서 body/html 선택자를 범위화합니다. @media는 외부 미리보기 viewport에 반응하며 폭 슬라이더는 컨테이너만 변경합니다. 네트워크·폼 이동·iframe 실행은 제한됩니다.
