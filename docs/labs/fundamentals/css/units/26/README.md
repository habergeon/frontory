## 핵심 개념과 설명

### 렌더링 단계

속성 변화는 스타일·레이아웃·페인트·합성에 서로 다른 영향을 줄 수 있습니다. 실제 경로는 브라우저와 요소 조건에 따라 확인합니다.

### 측정 비교

같은 요소 수와 지속 시간으로 비교해야 합니다. transform이 언제나 비용이 없다고 단정하지 않습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구로 확인하세요. 별도 폴더의 index.html에 콘텐츠를 만들고 link rel="stylesheet"로 실습 CSS를 연결하세요. 개발자 도구에서 뷰포트·계산 스타일·성능 기록을 확인합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. index.html에 카드 50개, 지속 시간 500ms, 같은 브라우저 조건의 콘텐츠를 준비하고 render-cost.css를 연결하세요.
2. 같은 카드 이동을 width 변경과 transform 변경으로 구현하고 성능 기록을 각각 수집하세요.
3. 카드 50개, 지속 시간 500ms, 같은 브라우저 조건으로 실행하세요. 확인할 결과: 두 기록에서 Layout·Paint 구간을 구분한다. 동일 조건의 기록 2개와 관찰 한계를 남긴다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 변경 속성 | width | transform | 실행 전 가설: 레이아웃 작업량이 줄어들 수 있다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 연결된 예제와 실행 범위

[예제 원본](../../../../../../src/labs/css-step-26/example.js) · [실행 환경과 제한](../../../../../examples.md)

실제 Layout/Paint/Composite 비용은 DevTools Performance로 두 조건을 각각 기록하세요. 미리보기는 비용을 자동 추론하지 않습니다. Shadow DOM에서 문서 body/html 선택자를 범위화합니다. @media는 외부 미리보기 viewport에 반응하며 폭 슬라이더는 컨테이너만 변경합니다. 네트워크·폼 이동·iframe 실행은 제한됩니다.


원본 코드·기록은 자동으로 덮어쓰지 않습니다. 기존 예제를 초기화할 때도 필기는 유지됩니다.
