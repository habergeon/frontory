## 핵심 개념과 설명

### 렌더링 단계

속성 변화는 스타일·레이아웃·페인트·합성에 서로 다른 영향을 줄 수 있습니다. 실제 경로는 브라우저와 요소 조건에 따라 확인합니다.

### 측정 비교

같은 요소 수와 지속 시간으로 비교해야 합니다. transform이 언제나 비용이 없다고 단정하지 않습니다.

## 실습 준비

문서 안내형 단위이며 전용 내장 실행 예제는 제공하지 않습니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구로 확인하세요. 별도 폴더의 index.html에 콘텐츠를 만들고 link rel="stylesheet"로 실습 CSS를 연결하세요. 개발자 도구에서 뷰포트·계산 스타일·성능 기록을 확인합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. index.html에 카드 50개, 지속 시간 500ms, 같은 브라우저 조건의 콘텐츠를 준비하고 render-cost.css를 연결하세요.
2. 같은 카드 이동을 width 변경과 transform 변경으로 구현하고 성능 기록을 각각 수집하세요.
3. 카드 50개, 지속 시간 500ms, 같은 브라우저 조건으로 실행하세요. 확인할 결과: 두 기록에서 Layout·Paint 구간을 구분한다. 동일 조건의 기록 2개와 관찰 한계를 남긴다. 예상과 실제 결과는 구분해 기록하세요.
