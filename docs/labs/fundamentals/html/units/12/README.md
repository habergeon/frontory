## 핵심 개념과 설명

### 입력 의미

type은 네이티브 UI와 검증 규칙에 영향을 줍니다. 숫자로 보인다고 전화번호를 number로 지정하지 않습니다.

### 자동 완성

autocomplete 토큰은 입력 목적을 전달합니다. 사용자 입력 부담을 줄이되 실제 필드 의미와 맞춰야 합니다.

## 실습 준비

문서 안내형 단위이며 전용 내장 실행 예제는 제공하지 않습니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구로 확인하세요. 별도 폴더에 HTML과 필요한 이미지·미디어 파일을 직접 준비하고 로컬 HTTP 서버로 여세요. Elements·접근성 패널과 실제 키보드 조작으로 확인합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. input-types.html 파일에 이메일, 전화번호, 학습 분 입력 조건을 준비하세요.
2. email·tel·number 입력과 적절한 autocomplete·inputmode를 작성하세요.
3. 이메일, 전화번호, 학습 분 입력 조건으로 실행하세요. 확인할 결과: 세 필드의 label과 name이 각각 연결된다. 올바른 이메일과 잘못된 이메일의 validity를 비교한다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 이메일 type | text | email | 실행 전 가설: 잘못된 이메일 형식에 제약 오류가 생길 것이다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
