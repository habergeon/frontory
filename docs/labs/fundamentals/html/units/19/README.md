## 핵심 개념과 설명

### 소스 후보

srcset은 해상도 또는 폭별 이미지 후보를 제공합니다. 브라우저는 화면 조건과 후보 정보를 함께 판단합니다.

### 표시 크기

sizes는 폭 기술자 후보를 선택할 때 예상 표시 폭을 알려줍니다. CSS의 실제 표시 크기와 어긋나면 불필요한 다운로드가 생길 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구로 확인하세요. 별도 폴더에 HTML과 필요한 이미지·미디어 파일을 직접 준비하고 로컬 HTTP 서버로 여세요. Elements·접근성 패널과 실제 키보드 조작으로 확인합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. responsive-images.html 파일에 좁은 화면과 넓은 화면, 캐시 비운 요청 조건을 준비하세요.
2. 폭이 다른 이미지 3개와 srcset·sizes를 작성하고 currentSrc와 요청 크기를 확인하세요.
3. 좁은 화면과 넓은 화면, 캐시 비운 요청 조건으로 실행하세요. 확인할 결과: 두 화면의 currentSrc와 실제 표시 폭을 기록한다. 모든 후보에 동일한 의미의 alt를 유지한다. 예상과 실제 결과는 구분해 기록하세요.

## 연결된 예제와 실행 범위

[예제 원본](../../../../../../src/labs/html-step-19/example.js) · [실행 환경과 제한](../../../../../examples.md)

300/600/1200w SVG 후보가 실제 srcset으로 선택됩니다. sizes와 DPR 및 미리보기 viewport가 선택에 영향을 줍니다. data URL은 네트워크 전송량 비교용이 아닙니다. Shadow DOM에서 문서 body/html 선택자를 범위화합니다. @media는 외부 미리보기 viewport에 반응하며 폭 슬라이더는 컨테이너만 변경합니다. 네트워크·폼 이동·iframe 실행은 제한됩니다.


원본 코드·기록은 자동으로 덮어쓰지 않습니다. 기존 예제를 초기화할 때도 필기는 유지됩니다.
