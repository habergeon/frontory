## 핵심 개념과 설명

### 저장 관계

타입 매개변수로 저장과 조회의 타입 관계를 표현합니다. 저장 문자열은 조회 때 다시 검증해야 합니다.

### 구조 검사

JSON.parse 결과를 unknown으로 받아 가드로 확인합니다. null과 배열 내부 필드까지 검사해야 신뢰할 수 있습니다.

## 실습 준비

Frontory의 기존 미리보기는 제한된 시작 예제이며 전체 과제의 완성본이 아닙니다. 추가 파일과 기능은 별도 로컬 프로젝트에서 직접 구현하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. storage-boundary.ts 파일에 정상 배열, 빈 배열, null, 숫자 title 조건을 준비하세요.
2. save<T>와 검증 함수를 받는 load<T>를 만들고 Note 배열 가드를 연결하세요.
3. 정상 배열, 빈 배열, null, 숫자 title 조건으로 실행하세요. 확인할 결과: 네 입력의 허용·거부 결과를 남긴다. 유효한 반환값에서 Note 필드를 단언 없이 사용한다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| JSON 필드 | 문자열 title | 숫자 title | 실행 전 가설: 복원 결과가 오류로 분류될 것이다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
