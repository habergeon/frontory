## 핵심 개념과 설명

### 대체 가능한 구현

같은 인터페이스를 만족하는 DOM과 Canvas 구현을 교체합니다. 구현별 세부 자원은 각 구현이 소유합니다.

### 통합 검증

strict 검사와 실제 동작 검사는 서로 다른 실패를 찾습니다. 둘의 결과를 나눠 기록해야 합니다.

## 실습 준비

Frontory의 기존 미리보기는 제한된 시작 예제이며 전체 과제의 완성본이 아닙니다. 추가 파일과 기능은 별도 로컬 프로젝트에서 직접 구현하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. main.ts 파일에 두 구현 교체 5회, dispose 중복 호출 조건을 준비하세요.
2. mount/dispose 계약으로 DOMPlugin과 CanvasPlugin을 연결하고 선택 UI에서 교체하세요.
3. 두 구현 교체 5회, dispose 중복 호출 조건으로 실행하세요. 확인할 결과: 두 구현이 strict 타입 검사를 통과한다. 5회 교체 후 중복 이벤트가 없고 dispose 2회가 안전하다. 예상과 실제 결과는 구분해 기록하세요.
