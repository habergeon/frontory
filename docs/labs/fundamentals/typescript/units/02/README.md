## 핵심 개념과 설명

### 컴파일 옵션

strict는 여러 엄격한 검사를 묶어 켭니다. 옵션 변경 전후의 진단은 프로젝트 버전과 함께 기록합니다.

### 타입 제거

타입 표기는 출력 JavaScript에서 제거됩니다. 컴파일 성공과 런타임 성공은 별도로 검사합니다.

## 실습 준비

문서 안내형 단위이며 전용 내장 실행 예제는 제공하지 않습니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. tsconfig.json 파일에 타입 없는 매개변수와 null 대입 조건을 준비하세요.
2. strict와 noEmit을 설정하고 명시하지 않은 함수 매개변수를 고친 뒤 실행용 출력도 비교하세요.
3. 타입 없는 매개변수와 null 대입 조건으로 실행하세요. 확인할 결과: 설치한 tsc 버전과 두 설정의 진단을 남긴다. 수정 후 tsc --noEmit 오류가 0개다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| strict | false | true | 실행 전 가설: 암묵적 any와 null 관련 진단이 늘어날 수 있다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
