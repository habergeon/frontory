## 핵심 개념과 설명

### 선택 속성

optional 속성은 누락될 수 있습니다. 읽을 때 undefined 가능성을 처리해야 합니다.

### 구조적 호환

타입은 필요한 구조를 기준으로 호환성을 판단합니다. 새 객체 리터럴에는 초과 속성 검사도 적용됩니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. note.ts 파일에 정상 객체, tag 없음, titel 오타 조건을 준비하세요.
2. Note의 id·title·optional tag를 정의하고 누락·오타 객체를 대입하세요.
3. 정상 객체, tag 없음, titel 오타 조건으로 실행하세요. 확인할 결과: tag 없는 객체를 안전하게 표시한다. 오타 객체의 진단 위치와 수정 결과를 남긴다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 속성 이름 | title | titel | 실행 전 가설: 필수 속성 누락 또는 초과 속성 진단이 날 것이다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
