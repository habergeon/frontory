## 핵심 개념과 설명

### 상태별 필드

성공 상태에만 data를 두면 불가능한 조합을 줄입니다. loading에 이전 데이터가 필요한지는 별도 설계 결정입니다.

### 전이 함수

이벤트를 받아 다음 상태를 반환하면 전이 규칙을 모을 수 있습니다. 허용하지 않는 전이는 명시적으로 처리합니다.

## 실습 준비

문서 안내형 단위이며 전용 내장 실행 예제는 제공하지 않습니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. request-state.ts 파일에 idle에서 시작·성공, 시작·실패 두 경로 조건을 준비하세요.
2. start·resolve·reject 이벤트로 상태를 전환하고 UI 문자열을 계산하세요.
3. idle에서 시작·성공, 시작·실패 두 경로 조건으로 실행하세요. 확인할 결과: 성공과 실패 경로의 상태 순서를 남긴다. loading에 error 필드를 잘못 넣으면 컴파일에 실패한다. 예상과 실제 결과는 구분해 기록하세요.
