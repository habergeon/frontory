## 핵심 개념과 설명

### 읽기 전용

readonly는 해당 참조를 통한 대입을 제한합니다. 다른 가변 참조나 런타임 코드의 변경까지 막지는 않습니다.

### 복사 갱신

새 배열과 객체를 반환하면 이전 상태 보존을 검사할 수 있습니다. 중첩 readonly 여부는 별도 타입으로 정합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. readonly.ts 파일에 메모 두 개와 중첩 meta 필드 조건을 준비하세요.
2. readonly Note 배열을 받는 toggle 함수를 새 객체 반환 방식으로 작성하세요.
3. 메모 두 개와 중첩 meta 필드 조건으로 실행하세요. 확인할 결과: 직접 대입 진단을 기록한다. 갱신 뒤 원본 완료 값과 길이가 같다. 예상과 실제 결과는 구분해 기록하세요.
