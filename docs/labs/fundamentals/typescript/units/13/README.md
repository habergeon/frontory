## 핵심 개념과 설명

### 제네릭 제약

extends로 함수가 필요한 구조를 제한합니다. 제약보다 더 구체적인 호출 타입은 반환에서 유지할 수 있습니다.

### 과도한 계약

사용하지 않는 필드를 요구하면 재사용 범위가 줄어듭니다. 구현에 필요한 최소 속성만 제약합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. constraints.ts 파일에 메모 객체, 사용자 객체, id 없는 객체 조건을 준비하세요.
2. id가 있는 객체를 색인하는 함수를 작성하고 추가 필드 타입을 유지하세요.
3. 메모 객체, 사용자 객체, id 없는 객체 조건으로 실행하세요. 확인할 결과: 두 종류의 객체에서 추가 필드 타입이 유지된다. id 없는 입력의 진단을 기록한다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 입력 구조 | id 있음 | id 없음 | 실행 전 가설: 제약 위반으로 호출이 거부될 것이다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
