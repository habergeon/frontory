## 핵심 개념과 설명

### 계약 검사

satisfies는 값이 계약을 만족하는지 검사합니다. 값 자체의 추론 정보를 가능한 범위에서 유지합니다.

### 타입 주석

명시 타입 주석은 변수가 보이는 계약을 정합니다. 리터럴 보존이 필요하면 as const와의 조합도 비교합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. config.ts 파일에 정상 테마와 잘못된 속성 이름 조건을 준비하세요.
2. 테마 설정을 타입 주석과 as const satisfies로 각각 선언해 키와 값 사용을 비교하세요.
3. 정상 테마와 잘못된 속성 이름 조건으로 실행하세요. 확인할 결과: 잘못된 키가 컴파일에서 거부된다. 올바른 설정의 리터럴 추론을 기록한다. 예상과 실제 결과는 구분해 기록하세요.
