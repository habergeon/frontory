## 핵심 개념과 설명

### 문자열 계약

템플릿 리터럴 타입으로 허용할 문자열 조합을 정합니다. 임의 문자열의 런타임 내용은 여전히 검사가 필요합니다.

### 이벤트 대응

이벤트 이름과 payload 타입을 맵으로 연결합니다. 이름과 값이 따로 넓어지면 관계가 사라질 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. event-names.ts 파일에 titleChanged 문자열과 잘못된 숫자 payload 조건을 준비하세요.
2. 메모 필드의 Changed 이름을 만들고 이름별 payload를 받는 함수를 작성하세요.
3. titleChanged 문자열과 잘못된 숫자 payload 조건으로 실행하세요. 확인할 결과: 서로 다른 이벤트 2개의 payload 타입을 구분한다. 이름 오타와 payload 오류를 각각 기록한다. 예상과 실제 결과는 구분해 기록하세요.

## 관찰할 변수

| 변수    | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                                                                                      |
| ------- | --------- | --------- | ---------------------------------------------------------------------------------------------------------- |
| payload | 문자열    | 숫자      | 실행 전 가설: titleChanged 호출이 거부될 것이다. 다른 조건은 고정하고 실행 후 실제 결과를 따로 기록합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
