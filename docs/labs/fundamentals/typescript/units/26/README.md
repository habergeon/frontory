## 핵심 개념과 설명

### 실패 기대

@ts-expect-error는 다음 줄의 오류를 기대합니다. 오류가 사라지면 불필요한 지시문이라는 진단으로 계약 변화를 알립니다.

### 양방향 검증

정상 사례와 거부 사례를 함께 검사합니다. 오류를 모두 무시하면 계약 약화를 놓칩니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트에서 직접 구현하고 브라우저 개발자 도구와 tsc --noEmit로 확인하세요. 별도 TypeScript 프로젝트에서 설치한 tsc 버전을 기록하세요. tsconfig.json에 strict를 켜고 tsc --noEmit으로 검사한 뒤, 실행 실습은 컴파일 출력 또는 로컬 개발 서버로 여세요. TS 타입 표기를 브라우저가 직접 실행한다고 가정하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. contracts.test.ts 파일에 정상 3건과 거부 3건 조건을 준비하세요.
2. 잘못된 상태·payload·플러그인에 기대 오류를 붙이고 정상 호출도 함께 작성하세요.
3. 정상 3건과 거부 3건 조건으로 실행하세요. 확인할 결과: 정상 3건은 컴파일된다. 거부 3건은 이유를 주석으로 기록하고 기대 오류로 검증한다. 예상과 실제 결과는 구분해 기록하세요.
