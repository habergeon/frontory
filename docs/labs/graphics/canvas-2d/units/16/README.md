## 핵심 개념과 설명

### 스냅샷

실행 취소는 이전 데이터 상태를 복구합니다. 참조만 저장하면 이후 수정이 과거 상태에도 반영될 수 있습니다.

### 명령 경계

드래그의 모든 move를 기록하면 취소 횟수가 지나치게 많습니다. 시작과 끝을 하나의 사용자 작업으로 묶을 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. 브라우저 버전과 viewport, DPR을 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-16.js와 index.html을 준비하세요. structuredClone으로 변경 전 장면을 history에 저장하고 undo 버튼을 연결하세요.
2. 드래그 종료 시에만 기록하며 삭제와 이동을 연속 실행한 뒤 역순 복구하세요.
3. 입력 조건 매 pointermove에서 출력을 저장한 뒤 pointerup 조건으로 다시 실행하세요. 예상: 한 번의 드래그가 한 번의 취소로 되돌아갑니다. 실제 화면·로그와 대조하고 day-16-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수      | 기준 조건      | 바꿀 조건 | 예상할 변화·검증 가설                        |
| --------- | -------------- | --------- | -------------------------------------------- |
| 기록 시점 | 매 pointermove | pointerup | 한 번의 드래그가 한 번의 취소로 되돌아갑니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
