## 선수 지식

선수 개념: 픽셀 배열, 직접 쓰기. 19단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 사전 렌더링

변하지 않는 복잡한 그림은 별도 캔버스에 한 번 그려 둘 수 있습니다. 매 프레임 경로를 구성하는 대신 drawImage로 복사합니다.

### 무효화

캐시는 크기나 색이 바뀌면 오래된 결과가 됩니다. 재생성 조건을 명시해야 선명도와 내용이 유지됩니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. 브라우저 버전과 viewport, DPR을 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-20.js와 index.html을 준비하세요. 격자 배경을 보조 canvas에 그리는 rebuildBackground 함수를 만드세요.
2. 움직이는 도형 위에 캐시를 사용하고 리사이즈 때만 배경을 다시 생성하세요.
3. 입력 조건 매 프레임에서 출력을 저장한 뒤 리사이즈 때만 조건으로 다시 실행하세요. 예상: 정적 경로 생성 횟수가 줄어듭니다. 실제 화면·로그와 대조하고 day-20-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 캐시 갱신 | 매 프레임 | 리사이즈 때만 | 정적 경로 생성 횟수가 줄어듭니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
