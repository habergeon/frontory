## 목표와 학습 후 역량

- 로더와 카메라 상태를 통합한다.
- GS picking의 의미를 명시한다.

## 선수 지식

13단위 결과물과 기록을 이어 사용합니다. 로딩과 카메라 통합 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 통합 경계

Spark의 형식 지원과 API는 설치 버전의 문서로 확인합니다. 기존 CPU 교육 뷰어에서 Spark 실행 성공을 추론하지 않습니다.

### 선택 계약

GS 선택은 사용할 렌더러의 picking 방식이나 별도 근사를 필요로 합니다. 일반 mesh raycaster가 Gaussian의 픽셀 기여도를 그대로 반환하지는 않습니다.

## 실습 준비

기존 gaussian-splatting-02 미리보기는 출발점입니다. 이후 과제 전체의 구현이나 검증을 대신하지 않습니다. 별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. integration.md에 설치 후보 버전과 공식 문서의 지원 형식·dispose·picking 항목을 정리하세요.
2. 별도 viewer.js에 Three.js 카메라와 로딩 상태를 연결하고 직접 만든 작은 fixture로 축을 검증하세요.
3. camera.json reset을 적용하고 지원하지 않는 형식 입력 시 오류 화면과 선택 정책을 확인하세요.
