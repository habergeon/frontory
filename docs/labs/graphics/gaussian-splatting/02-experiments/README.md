## 목표와 학습 후 역량

지원 형식과 오류 경로를 확인하고 GS picking을 mesh raycasting과 구별한다. 이를 자신의 말로 설명하고 작은 결과물로 재현하는 것이 목표입니다.

## 선수 지식

이 시리즈 1단위의 결과물과 기록.

## 핵심 개념과 설명

Spark는 Three.js 통합을 검토할 후보입니다. 형식과 버전별 API·좌표계·자원 수명은 실제 문서를 확인해야 합니다.

## 실습 준비

현재 단위에 연결된 예제를 실행하고 아래 과제를 진행합니다. 코드 편집기 자체는 JS/TS 모듈이며 JSX·Vue SFC를 직접 컴파일하지 않습니다.

## 실습 과제

1. 공식 참고에서 이번 개념과 API의 입력·출력을 찾아 필기에 요약합니다.
2. 작고 사용 허가된 로컬 GS 파일로 로딩·오류·카메라 reset을 설계하세요. 후보별 형식 지원 표를 작성하세요.
3. 아래 변수 중 하나만 바꾸기 전에 예상 결과를 적고, 실행 후 스크린샷·로그 또는 측정값과 비교합니다.
4. 원래 조건으로 되돌려 같은 결과를 재현하고 오류·지원 제한도 남깁니다.

## 관찰할 변수

파일 형식, 축, 데이터 크기. 비교 시 다른 변수와 브라우저·viewport 조건은 고정합니다.

## 연결된 예제와 실행 범위

[원본 실행 코드](../../../../../src/labs/gaussian-splatting-02/example.js) · 화면 단위 ID: `gaussian-splatting-02`

소형 .splat 및 ASCII GS PLY를 읽는 CPU Canvas 교육용 뷰어입니다. 최대 1 MiB·512 splat이며 binary PLY와 일반 mesh PLY는 지원하지 않습니다. Spark, GPU tile 렌더링, 고차 SH, GS picking은 구현 범위 밖입니다. 기본 장면은 직접 생성한 데이터이며 측정값은 이 CPU 예제에만 해당합니다.

기존에 저장한 코드가 있으면 그대로 유지합니다. 새 원본을 사용하려면 먼저 전체 JSON으로 백업한 뒤 **원본 코드로**를 선택하세요. 필기는 지워지지 않습니다.
