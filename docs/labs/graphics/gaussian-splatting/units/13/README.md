# Gaussian Splatting · 13 로더 상태와 취소

단계: 파일 검증과 뷰어 통합 · 편집 가능한 예제 · 저장 ID: `gaussian-splatting-step-13`

## 목표와 학습 후 역량

- 로딩 상태를 모델링한다.
- 늦게 도착한 결과를 차단한다.

## 선수 지식

12단위 결과물과 기록을 이어 사용합니다. 로더 상태와 취소 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 비동기 상태

읽기 완료와 데이터 검증 완료는 서로 다른 단계입니다. 상태를 구분해야 실패 위치를 사용자에게 알려 줄 수 있습니다.

### 최신 요청

이전 파일의 읽기가 늦게 끝나면 새 장면을 덮어쓸 수 있습니다. 요청 id로 최신 결과만 반영하고 취소된 결과를 폐기합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. loader.js에 idle·reading·validating·ready·error 상태를 정의하세요.
2. 지연을 주입한 두 fixture를 연속 선택하고 요청 id를 결과에 포함하세요.
3. 새 선택과 dispose 시 이전 결과 반영을 막고 상태 전이 로그를 출력하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 완료 순서 | A 다음 B | B 다음 A | 마지막 선택인 B만 화면에 남을 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 잘못된 파일 이후 정상 파일을 선택하면 ready로 복구한다.
