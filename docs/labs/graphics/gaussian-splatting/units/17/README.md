## 선수 지식

16단위 결과물과 기록을 이어 사용합니다. 정렬 갱신 간격 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 재사용

카메라가 멈추면 깊이 순서를 재사용할 수 있습니다. 카메라가 움직이는 동안 오래된 순서를 쓰면 합성 오류가 늘 수 있습니다.

### 지연 관찰

정렬 주기를 낮추면 CPU 작업은 줄지만 화면 반응이 늦어질 수 있습니다. 평균 시간만으로 이런 변화가 드러나지는 않습니다.

## 실습 준비

별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. scheduler.js에 매 프레임과 4프레임 간격 정렬 모드를 만드세요.
2. 같은 camera-path.json을 두 모드에서 재생하세요.
3. 정렬 횟수·CPU 시간·순서 갱신 시점의 이미지 차이를 기록하세요.

## 관찰할 변수
