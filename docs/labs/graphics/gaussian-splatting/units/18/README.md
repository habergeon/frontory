## 목표와 학습 후 역량

## 선수 지식

17단위 결과물과 기록을 이어 사용합니다. 해상도와 픽셀 작업량 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 픽셀 비용

화면 해상도를 줄이면 Gaussian 수가 같아도 평가할 픽셀 수가 줄어듭니다. 실루엣과 얇은 구조의 표현도 함께 달라집니다.

### 비교 조건

CSS 크기와 실제 drawing buffer 크기를 분리해 기록해야 합니다. 다른 카메라나 DPR을 섞으면 해상도 효과를 판단하기 어렵습니다.

## 실습 준비

별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. quality.js에 고정 CSS 크기와 render scale 입력을 추가하세요.
2. camera-path.json과 데이터 id를 고정하고 1.0·0.5 배율로 재생하세요.
3. 실제 buffer 크기·프레임 간격 중앙값·얇은 구조 이미지를 저장하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| render scale | 1.0 | 0.5 | 픽셀 수는 약 1/4이 되지만 세부 표현이 줄 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
