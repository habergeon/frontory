## 목표와 학습 후 역량

- 처리 단계별 비용을 측정한다.
- CPU와 GPU 시간 주장을 구분한다.

## 선수 지식

21단위 결과물과 기록을 이어 사용합니다. 프로파일 구간 분리 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 단계 비용

읽기·파싱·정렬·투영·합성은 서로 다른 병목을 가질 수 있습니다. 전체 로딩 시간만 보면 개선할 위치를 찾기 어렵습니다.

### 측정 범위

performance.now는 CPU 구간의 경과 시간을 측정합니다. GPU 렌더러를 사용할 때 이 값을 GPU 실행 시간으로 부르면 안 됩니다.

## 실습 준비

별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. metrics.js에 각 단계 시작·종료 표시를 추가하세요.
2. 같은 fixture를 예열 후 다섯 번 처리하고 단계별 표를 만드세요.
3. CPU 교육 뷰어와 별도 Spark 실험을 다른 결과 파일로 분리하세요.
