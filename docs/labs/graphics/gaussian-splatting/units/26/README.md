# Gaussian Splatting · 26 재현 가능한 카메라 벤치마크

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 측정 가능한 GS 전시 뷰어 · 편집 가능한 예제 · 저장 ID: `gaussian-splatting-step-26`

## 목표와 학습 후 역량

- 고정 경로 벤치마크를 구성한다.
- 프레임 분포를 해석한다.

## 선수 지식

25단위 결과물과 기록을 이어 사용합니다. 재현 가능한 카메라 벤치마크 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 고정 경로

입력 경로가 달라지면 같은 품질 설정도 다른 비용을 만듭니다. 시간별 카메라 변환과 데이터 id를 고정해 비교합니다.

### 프레임 분포

평균만 기록하면 드물게 긴 프레임이 숨겨집니다. 중앙값과 상위 지연 구간을 함께 남깁니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 프로젝트의 문서 안내 실습입니다. 직접 만든 소형 데이터 또는 사용 허가를 확인한 로컬 파일만 사용합니다. 기존 미리보기는 1 MiB·512개 이하 .splat/ASCII GS PLY를 다루는 CPU 교육 뷰어이며 Spark GPU 렌더러가 아닙니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. benchmark.js에 camera-path.json을 시간 기반으로 재생하는 함수를 만드세요.
2. 기준 설정과 해상도 감소 설정을 같은 길이로 각각 세 번 실행하세요.
3. 프레임 간격의 중앙값·95백분위·관심 시점 이미지를 결과 JSON에 저장하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 설정 | 해상도 1.0 | 해상도 0.5 | 픽셀 병목일 때 프레임 간격이 줄고 CPU 정렬 병목이면 변화가 작을 것으로 예상합니다. |
