# PixiJS · 14 Assets와 이벤트

단계: Ticker·Assets·포인터 입력 · 편집 가능한 예제 · 저장 ID: `pixijs-02`

## 목표와 학습 후 역량

- 실패와 재실행에서도 UI가 살아 있다.
- 선택 객체 제거 후 공유 텍스처의 형제가 깨지지 않는다.

## 선수 지식

선수 개념: 부모 좌표, 종료 이벤트. 13단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 오류와 기존 장면

새 atlas 로딩 실패가 현재 장면을 지울 필요는 없습니다. 검증된 새 자원이 준비된 뒤 교체하면 복구가 쉽습니다.

### 공유 텍스처 수명

Sprite 제거와 TextureSource 해제는 다릅니다. 다른 Sprite가 사용하는 소스를 함께 파괴하지 않아야 합니다.

## 실습 준비

기존 내장 예제는 출발점만 제공합니다. 확장 요구사항 전체가 구현된 예제가 아니며 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-14.js와 index.html을 준비하세요. 기존 pixijs-02의 로컬 atlas 예제를 읽고 실패·재시도·선택 삭제 UI를 외부 프로젝트에 구성하세요.
2. 선택 Sprite만 destroy({texture:false,textureSource:false})로 제거하고 형제 Sprite의 표시를 확인하세요.
3. 입력 조건 유효 atlas에서 출력을 저장한 뒤 프레임 없는 잘못된 atlas 조건으로 다시 실행하세요. 예상: 기존 Sprite가 유지되고 오류와 재시도가 표시됩니다. 실제 화면·로그와 대조하고 day-14-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 로딩 입력 | 유효 atlas | 프레임 없는 잘못된 atlas | 기존 Sprite가 유지되고 오류와 재시도가 표시됩니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
