## 핵심 개념과 설명

### 다차원 비용

필터 면적·텍스처 전환·객체 갱신은 서로 다른 비용입니다. Sprite 개수만으로 병목을 설명하면 개선 대상을 놓칠 수 있습니다.

### 측정의 한계

프레임 관찰은 체감 결과를 보여 줍니다. 내부 호출이나 GPU 시간은 직접 측정 근거가 없으면 미확인으로 남겨야 합니다.

## 실습 준비

기존 내장 예제는 출발점만 제공합니다. 확장 요구사항 전체가 구현된 예제가 아니며 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-28.js와 index.html을 준비하세요. 기존 pixijs-03의 필터·텍스처·DPR 비교를 편집기에 연결하고 같은 Sprite 목록을 유지하세요.
2. 변수 하나의 전후 기록과 품질 이미지, 재실행 후 자원 장부를 모아 최적화 제안과 한계를 작성하세요.
3. 입력 조건 없음에서 출력을 저장한 뒤 부모 BlurFilter 조건으로 다시 실행하세요. 예상: 품질과 처리 면적 비용이 달라지며 프레임 변화는 환경별로 측정해야 합니다. 실제 화면·로그와 대조하고 day-28-notes.md에 실제 결과와 차이의 원인을 남기세요.
