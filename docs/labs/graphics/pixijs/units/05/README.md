## 선수 지식

선수 개념: 도형 뒤 스타일, 객체 변환. 4단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 텍스트 생성

v8 Text는 text와 style을 가진 옵션 객체로 구성할 수 있습니다. 폰트와 크기는 텍스트 측정과 화면 품질에 영향을 줍니다.

### 갱신 비용

문자열이 바뀌면 텍스트 렌더 자원도 갱신될 수 있습니다. 매 프레임 같은 내용을 다시 설정하는 일을 피합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-05.js와 index.html을 준비하세요. new Text({text:'점수 0',style:{fontSize:24,fill:...}})로 점수판을 만드세요.
2. 점수가 달라질 때만 text를 갱신하고 긴 한글 문자열의 줄바꿈을 비교하세요.
3. 입력 조건 매 프레임에서 출력을 저장한 뒤 값 변경 시 조건으로 다시 실행하세요. 예상: 불필요한 텍스트 갱신 요청이 줄어듭니다. 실제 화면·로그와 대조하고 day-05-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건  | 예상할 변화·검증 가설                  |
| --------- | --------- | ---------- | -------------------------------------- |
| 갱신 주기 | 매 프레임 | 값 변경 시 | 불필요한 텍스트 갱신 요청이 줄어듭니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
