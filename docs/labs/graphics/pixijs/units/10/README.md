## 핵심 개념과 설명

### 캐시된 자원

Assets.load는 비동기 로딩과 캐시를 관리합니다. 같은 경로를 다시 요청해도 매번 독립 텍스처가 생긴다고 가정하면 안 됩니다.

### 오류 상태

로딩 실패는 UI의 정상적인 상태 중 하나입니다. 실패 문구와 재시도 경로가 있어야 빈 화면에서 복구할 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-10.js와 index.html을 준비하세요. Assets.load('/assets/hero.png')를 try/catch로 감싸 로딩·성공·오류 상태를 출력하세요.
2. 잘못된 URL과 정상 URL을 전환하고 성공 시에만 Sprite를 stage에 추가하세요.
3. 입력 조건 정상 로컬 경로에서 출력을 저장한 뒤 없는 이미지 조건으로 다시 실행하세요. 예상: 오류 상태가 표시되고 재시도 버튼은 유지됩니다. 실제 화면·로그와 대조하고 day-10-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| URL | 정상 로컬 경로 | 없는 이미지 | 오류 상태가 표시되고 재시도 버튼은 유지됩니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
