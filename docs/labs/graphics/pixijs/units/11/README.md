## 선수 지식

선수 개념: 캐시된 자원, 오류 상태. 10단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 공유 소스

atlas의 여러 Texture는 같은 TextureSource의 일부를 가리킬 수 있습니다. 프레임 수와 GPU 소스 수는 같은 개념이 아닙니다.

### 프레임 사각형

frame은 원본 이미지의 영역입니다. 잘못된 경계는 다른 그림이나 빈 영역을 보여 줄 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-11.js와 index.html을 준비하세요. 로컬 atlas PNG와 JSON을 Assets.load로 읽어 프레임 이름 목록을 출력하세요.
2. 두 프레임으로 Sprite를 만들고 하나의 source를 공유하는지 참조를 비교하세요.
3. 입력 조건 첫 영역에서 출력을 저장한 뒤 두 번째 영역 조건으로 다시 실행하세요. 예상: 원본 소스는 공유하면서 표시되는 부분만 바뀝니다. 실제 화면·로그와 대조하고 day-11-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 프레임 | 첫 영역 | 두 번째 영역 | 원본 소스는 공유하면서 표시되는 부분만 바뀝니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
