## 목표와 학습 후 역량

- 화면을 돌아와도 데이터 위치가 보존된다.
- 떠난 화면의 이벤트와 ticker가 제거된다.

## 선수 지식

선수 개념: 픽셀 밖 의미, 같은 명령. 15단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 장면 경계

Container를 화면별로 묶으면 전환 범위가 명확합니다. 데이터와 표시 객체를 분리하면 자원을 새로 만들어도 사용자 상태를 복원할 수 있습니다.

### 비동기 무효화

떠난 화면의 로딩이 나중에 끝날 수 있습니다. 세대 토큰을 검사해 오래된 결과를 붙이지 않도록 합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-16.js와 index.html을 준비하세요. 메뉴와 편집 화면을 별도 Container와 데이터 모델로 구성하세요.
2. 빠르게 화면을 전환하며 requestId를 검사하고 현재 화면에만 로딩 결과를 적용하세요.
3. 입력 조건 현재 요청 먼저에서 출력을 저장한 뒤 이전 요청 나중 조건으로 다시 실행하세요. 예상: 이전 결과가 새 화면에 Sprite를 추가하지 않습니다. 실제 화면·로그와 대조하고 day-16-notes.md에 실제 결과와 차이의 원인을 남기세요.
