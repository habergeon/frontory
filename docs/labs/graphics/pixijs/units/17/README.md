## 핵심 개념과 설명

### 프레임 순서

atlas 프레임 이름의 정렬이 재생 순서와 같다는 보장은 없습니다. 명시적인 배열로 순서를 관리합니다.

### 시간 인덱스

누적 시간과 fps로 프레임 인덱스를 계산할 수 있습니다. 프레임 수에 따라 증가시키면 표시 속도가 환경에 종속됩니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-17.js와 index.html을 준비하세요. atlas 프레임 배열과 누적 초를 만들고 floor(time*fps)로 Sprite.texture를 교체하세요.
2. 재생·정지·반복 입력을 추가하고 마지막 프레임에서 멈추는 모드도 구현하세요.
3. 입력 조건 6에서 출력을 저장한 뒤 12 조건으로 다시 실행하세요. 예상: 같은 프레임 배열이 두 배 빠르게 순환합니다. 실제 화면·로그와 대조하고 day-17-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                      |
| ---- | --------- | --------- | ------------------------------------------ |
| fps  | 6         | 12        | 같은 프레임 배열이 두 배 빠르게 순환합니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
