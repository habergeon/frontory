## 목표와 학습 후 역량

- 다시 들어온 객체가 올바른 위치에 보인다.

## 선수 지식

선수 개념: 경량 입자, 동적 속성. 23단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 보임과 계산

화면 밖이라도 앱의 update 루프는 객체를 계속 갱신할 수 있습니다. 표시 생략과 시뮬레이션 생략은 별도 정책입니다.

### 가시성 범위

경계 계산도 비용이 듭니다. 단순 장면은 컬링 검사 비용이 절약보다 클 수 있어 비교가 필요합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-24.js와 index.html을 준비하세요. 화면 경계와 Sprite bounds를 비교해 표시할 대상을 분류하세요.
2. 움직임 데이터는 유지하며 표시만 숨기는 방식과 갱신까지 중단하는 방식을 비교하세요.
3. 입력 조건 10%에서 출력을 저장한 뒤 90% 조건으로 다시 실행하세요. 예상: 표시 생략의 효과가 커질 수 있으나 검사 비용을 함께 측정해야 합니다. 실제 화면·로그와 대조하고 day-24-notes.md에 실제 결과와 차이의 원인을 남기세요.
