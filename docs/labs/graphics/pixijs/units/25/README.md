## 선수 지식

선수 개념: 보임과 계산, 가시성 범위. 24단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 상태 전환

텍스처·블렌드·도형 종류가 렌더 묶음에 영향을 줍니다. 텍스처 두 개를 번갈아 쓴다고 반드시 두 배 호출이 생기지는 않습니다.

### 기능 보존

정렬 최적화는 투명 겹침 결과를 바꿀 수 있습니다. 시각적 순서를 유지할 수 있는 객체만 재배치해야 합니다.

## 실습 준비

새 단원의 내장 실행 예제는 제공하지 않습니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-25.js와 index.html을 준비하세요. 겹치지 않는 Sprite와 Graphics 목록을 교차 순서와 종류별 순서로 구성하세요.
2. 같은 수와 위치를 유지하며 프로파일·프레임 간격을 기록하고 호출 수는 직접 확인 가능한 도구가 있을 때만 기재하세요.
3. 입력 조건 Sprite와 Graphics 교차에서 출력을 저장한 뒤 종류별 묶음 조건으로 다시 실행하세요. 예상: 상태 전환 비용이 줄 가능성이 있으나 실제 측정으로 확인해야 합니다. 실제 화면·로그와 대조하고 day-25-notes.md에 실제 결과와 차이의 원인을 남기세요.
