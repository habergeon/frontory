## 선수 지식

선수 개념: 상태 전환, 기능 보존. 25단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 시간 지표

ticker.elapsedMS는 프레임 간격 관찰에 쓸 수 있습니다. 이 값은 GPU 실행 시간이나 CPU 작업만의 시간이 아닙니다.

### 변수 통제

resolution·필터·객체 수를 한꺼번에 바꾸면 원인을 찾기 어렵습니다. 한 변수만 바꾼 뒤 품질 손실도 함께 기록합니다.

## 실습 준비

새 단원의 내장 실행 예제는 제공하지 않습니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-26.js와 index.html을 준비하세요. 고정 seed의 Sprite 목록에 측정 시작·종료 버튼을 추가하세요.
2. 워밍업 뒤 동일 표본 수의 elapsedMS를 저장하고 중앙값·95백분위수와 화면 이미지를 기록하세요.
3. 입력 조건 1에서 출력을 저장한 뒤 2 조건으로 다시 실행하세요. 예상: 버퍼 픽셀 수가 늘어 필터나 채우기 부담이 커질 수 있습니다. 실제 화면·로그와 대조하고 day-26-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| resolution | 1 | 2 | 버퍼 픽셀 수가 늘어 필터나 채우기 부담이 커질 수 있습니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
