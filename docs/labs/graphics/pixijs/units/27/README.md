## 목표와 학습 후 역량

- JSON 복원 뒤 id와 좌표가 유지된다.
- 실패 후 재시도와 종료가 정상 작동한다.

## 선수 지식

선수 개념: 시간 지표, 변수 통제. 26단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 데이터와 표시

JSON에는 객체 id·위치·프레임 이름을 저장합니다. Sprite 인스턴스 자체를 저장하는 방식과 구별해야 합니다.

### 수명 회귀

화면 전환과 실패를 반복하면 정리 누락을 찾을 수 있습니다. ticker·이벤트·관찰자·텍스처의 소유자를 함께 점검합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. pixi.js 8.x의 설치 버전을 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-27.js와 index.html을 준비하세요. atlas 선택·드래그·키보드 목록·JSON 저장을 갖춘 장면 편집기를 통합하세요.
2. 생성→삭제→저장→복원→로딩 실패→종료를 반복하고 콜백 수와 공유 자원 상태를 기록하세요.
3. 입력 조건 1회에서 출력을 저장한 뒤 5회 조건으로 다시 실행하세요. 예상: 정리가 맞으면 입력당 명령 수와 ticker 콜백 수가 증가하지 않습니다. 실제 화면·로그와 대조하고 day-27-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 재실행 | 1회 | 5회 | 정리가 맞으면 입력당 명령 수와 ticker 콜백 수가 증가하지 않습니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
