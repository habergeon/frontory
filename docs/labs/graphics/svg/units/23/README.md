## 핵심 개념과 설명

### DOM 규모

각 SVG 노드는 스타일·이벤트·레이아웃 작업의 대상입니다. 점 개수뿐 아니라 라벨과 필터도 비교 조건에 포함해야 합니다.

### 측정 구간

performance.now의 동기 구간만으로 화면 완료를 알 수는 없습니다. 프로파일에서 스타일과 렌더링 작업도 함께 확인합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. 브라우저 버전과 viewport, DPR을 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-23.js와 index.html을 준비하세요. 고정 seed로 100,1000,5000개 점 데이터를 생성하세요.
2. 생성·속성 갱신 시간과 다음 프레임 간격을 따로 기록하고 필터 없는 조건을 유지하세요.
3. 입력 조건 100에서 출력을 저장한 뒤 5000 조건으로 다시 실행하세요. DOM 생성과 스타일 갱신 부담이 증가할 가능성이 있습니다라는 가설을 화면·로그와 대조하고 day-23-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수  | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                                  |
| ----- | --------- | --------- | ------------------------------------------------------ |
| 점 수 | 100       | 5000      | DOM 생성과 스타일 갱신 부담이 증가할 가능성이 있습니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
