## 핵심 개념과 설명

### 병목 분리

draw call 감소와 픽셀 비용 감소는 서로 다른 개선입니다. 같은 장면에서 한 변수씩 바꿔야 효과를 해석할 수 있습니다.

### 반복 정리

종료 시 루프·컨트롤·관찰자와 소유 자원을 함께 해제합니다. renderer.info의 안정 추세는 참고 자료이며 전체 VRAM의 해제 증명은 아닙니다.

## 실습 준비

기존 내장 예제는 출발점만 제공합니다. 확장 요구사항 전체가 구현된 예제가 아니며 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. three와 addons를 같은 설치 버전으로 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-28.js와 index.html을 준비하세요. 기존 threejs-03 출발 코드에 장면 생성·삭제와 개별 Mesh/InstancedMesh 전환을 연결하세요.
2. 같은 카메라·수량·DPR로 전후 calls와 프레임 분포를 기록하고 geometry·material·texture·render target 정리 장부를 제출하세요.
3. 입력 조건 개별 Mesh에서 출력을 저장한 뒤 InstancedMesh 조건으로 다시 실행하세요. 예상: 동일 geometry와 material 조건에서 호출 수를 줄일 수 있으나 전체 프레임 효과는 측정해야 합니다. 실제 화면·로그와 대조하고 day-28-notes.md에 실제 결과와 차이의 원인을 남기세요.
