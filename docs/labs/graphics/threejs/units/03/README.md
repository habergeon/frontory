## 선수 지식

선수 개념: 버퍼 크기, 종횡비. 2단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 원근 투영

PerspectiveCamera는 먼 물체를 작게 표현합니다. near와 far는 보이는 깊이 범위를 제한합니다.

### 직교 투영

OrthographicCamera에서는 거리가 크기를 바꾸지 않습니다. CAD식 배치와 비교 도식에 유용합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. three와 addons를 같은 설치 버전으로 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-03.js와 index.html을 준비하세요. 같은 크기의 큐브 두 개를 서로 다른 깊이에 배치하세요.
2. 원근·직교 카메라 전환 버튼을 만들고 두 큐브의 화면 폭을 비교하세요.
3. 입력 조건 PerspectiveCamera에서 출력을 저장한 뒤 OrthographicCamera 조건으로 다시 실행하세요. 예상: 깊이가 다른 큐브가 같은 화면 크기로 보입니다. 실제 화면·로그와 대조하고 day-03-notes.md에 실제 결과와 차이의 원인을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 카메라 | PerspectiveCamera | OrthographicCamera | 깊이가 다른 큐브가 같은 화면 크기로 보입니다 |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
