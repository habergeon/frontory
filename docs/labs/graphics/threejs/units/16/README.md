## 선수 지식

선수 개념: 경계 상자, 카메라 프레이밍. 15단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 제어 상태

OrbitControls는 camera와 target을 함께 갱신합니다. 수동 카메라 변경 뒤 update로 동기화해야 합니다.

### 정지 장면

움직임이 없는 장면은 항상 렌더할 필요가 없습니다. damping이나 애니메이션이 있으면 정착할 때까지 프레임이 필요합니다.

## 실습 준비

새 단원의 내장 실행 예제는 제공하지 않습니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. three와 addons를 같은 설치 버전으로 고정하고 기록하세요.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-16.js와 index.html을 준비하세요. OrbitControls의 change 이벤트에서 render를 요청하는 함수를 작성하세요.
2. damping을 끈 정적 모드와 켠 연속 갱신 모드를 전환하고 렌더 횟수를 표시하세요.
3. 입력 조건 항상 루프에서 출력을 저장한 뒤 변경 시 요청 조건으로 다시 실행하세요. 예상: 정적 장면에서 불필요한 렌더 호출이 줄어듭니다. 실제 화면·로그와 대조하고 day-16-notes.md에 실제 결과와 차이의 원인을 남기세요.
