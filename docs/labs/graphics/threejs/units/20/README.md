## 선수 지식

선수 개념: 공유 드로잉, 인스턴스 버퍼. 19단위의 결과 파일과 관찰 기록을 준비하세요.

## 핵심 개념과 설명

### 인스턴스 식별

Raycaster 결과에는 instanceId가 포함될 수 있습니다. 이를 데이터 id와 매핑해야 개별 선택을 유지할 수 있습니다.

### 범위 갱신

인스턴스 위치가 바뀌면 경계 정보도 검토해야 합니다. 오래된 경계는 컬링이나 선택 판단에 영향을 줄 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. three와 addons를 같은 설치 버전으로 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-20.js와 index.html을 준비하세요. instanceId를 데이터 id로 변환하고 선택한 인스턴스에 setColorAt을 적용하세요.
2. 위치를 바꾼 뒤 instanceMatrix와 instanceColor 업로드 및 경계 재계산을 수행하세요.
3. 입력 조건 첫 인스턴스에서 출력을 저장한 뒤 마지막 인스턴스 조건으로 다시 실행하세요. 예상: 해당 항목만 강조되고 데이터 id가 일치합니다. 실제 화면·로그와 대조하고 day-20-notes.md에 실제 결과와 차이의 원인을 남기세요.
