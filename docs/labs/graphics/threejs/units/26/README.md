## 선수 지식

## 핵심 개념과 설명

### 통계 범위

renderer.info는 렌더 호출·삼각형·일부 자원 수를 보여 줍니다. 전체 GPU VRAM이나 정확한 GPU 실행 시간을 측정하는 도구는 아닙니다.

### 다중 패스

한 프레임에 여러 render가 있으면 초기화 시점이 중요합니다. autoReset을 조정하고 프레임 단위로 reset하면 합계를 비교할 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 로컬 HTTP 개발 서버의 HTML·ES 모듈 프로젝트에서 직접 구현합니다. three와 addons를 같은 설치 버전으로 고정하고 기록하세요.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 외부 실습 프로젝트의 day-26.js와 index.html을 준비하세요. 메인 화면과 미니맵의 렌더를 묶어 info.autoReset=false로 통계를 수집하세요.
2. 프레임 시작에 info.reset을 호출하고 calls·triangles·memory 항목과 CPU 프레임 간격을 따로 저장하세요.
3. 입력 조건 메인만에서 출력을 저장한 뒤 메인과 미니맵 조건으로 다시 실행하세요. 예상: 한 프레임의 호출·삼각형 합계가 증가할 수 있습니다. 실제 화면·로그와 대조하고 day-26-notes.md에 실제 결과와 차이의 원인을 남기세요.
