## 핵심 개념과 설명

WebGL은 브라우저에서 GPU에 그래픽 작업을 요청하는 API입니다. Three.js는 장면과 재질 같은 상위 표현을 제공하지만 GPU가 처리할 데이터를 준비하고 제출하는 과정은 여전히 필요합니다.

정점 처리 → 삼각형의 화면 투영과 래스터화 → fragment 처리 → 깊이 검사와 합성을 거쳐 화면이 만들어집니다. GPU는 같은 프로그램으로 많은 정점·fragment를 처리하기 좋고, React는 메뉴와 조작 상태를 담당합니다. React render와 renderer.render는 같은 과정이 아닙니다.

## 실행 준비

프로젝트 루트에서 pnpm install --frozen-lockfile, pnpm dev를 실행하고 http://127.0.0.1:5173 을 엽니다. 01 단위를 선택해 화면·코드·필기를 함께 확인합니다. 입력 후 600ms가 지나면 실행되며, 실패한 코드도 저장되므로 오류 메시지를 읽고 수정합니다.

## 실습 과제

1. 첫 예제에서 Scene/Camera/Renderer를 찾고 역할을 적습니다.
2. ROTATE를 false로 고정한 뒤 CUBE_COLOR를 바꾸고 실제 픽셀 변화가 보이는지 확인합니다.
3. 괄호 하나를 지워 구문 오류를 만든 뒤 복구하고, 오류 중에도 필기를 쓸 수 있는지 확인합니다.

화면 코드는 src/labs/01-scene/example.js 원본 또는 이 단위에 저장한 편집본입니다. Monaco에서 JavaScript/TypeScript를 선택하고 600ms 동안 입력이 없으면 문법·타입 검사 후 새 iframe에서 실행합니다. TypeScript는 JavaScript로 변환합니다. 오류 목록을 클릭하면 해당 줄로 이동합니다. 기존 createScene.ts와 SceneLab.tsx는 비교용으로 보존되어 있으며 현재 편집기의 실행 소스는 아닙니다.

TypeScript 실험: 언어를 TypeScript로 바꾸고 `const FOV = 50`에 `: number` 타입을 붙입니다. 숫자를 문자열로 바꾸어 타입 오류를 관찰하고 숫자로 복구해 장면 반영을 확인하세요. 원본 복원은 JavaScript로 돌아가며 필기는 유지합니다.

## 이어서 해 볼 카메라 과제

ROTATE를 false로 고정한 뒤 CAMERA_POSITION을 [3, 2, 5] → [0, 2, 5] → [5, 2, 0]으로 한 번씩 바꿉니다. 변경 전에 어느 면이 보일지 예상하고, 실제 결과와 축 방향을 비교하세요. FOV와 큐브 크기는 고정합니다. OrbitControls의 target은 원점이며 카메라 위치와 바라보는 목표는 서로 다른 값입니다. 자세한 설명은 [02 카메라](../02-camera/README.md)에서 이어갑니다.

## 관찰할 변수

CUBE_COLOR, ROTATE. 카메라·geometry·광원은 고정합니다.
