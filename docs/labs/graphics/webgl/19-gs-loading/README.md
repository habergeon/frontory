## 선수 지식

15~18, Promise와 오류 처리.

## 핵심 개념과 설명

일반 PLY 점군이 항상 GS 데이터는 아닙니다. 같은 .ply 확장자에도 필드와 색 표현이 다를 수 있으므로 renderer가 기대하는 파라미터와 비교합니다. 파일 크기와 파싱 후 GPU 메모리 비용은 같지 않습니다.

출처·라이선스·형식·버전·크기를 먼저 적고 작은 데이터 하나를 선택합니다. 현재 프로젝트는 GS 데이터를 포함하지 않으며 Spark도 아직 설치하지 않습니다. 실제 GS 로딩은 별도 로컬 소스 실습으로 추가할 예정이고, 네트워크가 차단된 현재 편집 iframe의 설정을 임의로 풀지 않습니다.

## 실습 과제

1. 공식 문서에서 지원 형식과 Three.js peer dependency를 확인합니다.
2. 작은 파일의 URL·라이선스·바이트 크기·형식을 기록하고 Git 제외 여부를 확인합니다.
3. 후속 로컬 실습에서 정상 파일, 없는 경로, 맞지 않는 PLY를 로드해 상태와 오류를 구분합니다.

## 연결된 예제와 실행 범위

[원본 실행 코드](../../../../../src/labs/19-gs-loading/example.js) · 화면 단위 ID: `19-gs-loading`

소형 .splat 및 ASCII GS PLY를 읽는 CPU Canvas 교육용 뷰어입니다. 최대 1 MiB·512 splat이며 binary PLY와 일반 mesh PLY는 지원하지 않습니다. Spark, GPU tile 렌더링, 고차 SH, GS picking은 구현 범위 밖입니다. 기본 장면은 직접 생성한 데이터이며 측정값은 이 CPU 예제에만 해당합니다.

기존에 저장한 코드가 있으면 그대로 유지합니다. 새 원본을 사용하려면 먼저 전체 JSON으로 백업한 뒤 **원본 코드로**를 선택하세요. 필기는 지워지지 않습니다.
