# WebGPU · 28 Compute와 Readback

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 복구·측정·통합 프로젝트 · 기존 예제에서 확장 · 저장 ID: `webgpu-03`

## 목표와 학습 후 역량

- Compute의 정확성과 전체 비용을 비교한다.
- GPU 사용 조건을 근거로 결정한다.

## 선수 지식

27단위 결과물과 기록을 이어 사용합니다. Compute와 Readback 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 종합 비교

배열 계산을 GPU로 옮길 때 데이터 이동이 전체 이득을 좌우할 수 있습니다. 계산 구간과 사용자에게 결과가 도착하는 지연을 함께 비교합니다.

### 채택 근거

GPU 경로가 빠르지 않은 입력 크기도 결과입니다. 정확성·지원 범위·복구 비용을 포함해 사용할 조건을 정합니다.

## 실습 준비

기존 webgpu-03 미리보기는 출발점입니다. 이후 과제 전체의 구현이나 검증을 대신하지 않습니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 최종 kernel과 CPU 함수를 65·1003·65536 원소에 같은 seed로 실행하세요.
2. readback 없음·최종 한 번·매 단계 세 정책의 전체 지연을 기록하세요.
3. report.md에 최대 오차·환경·선택한 workgroup·device loss 복구 결과와 채택 조건을 작성하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| readback 빈도 | 최종 한 번 | 매 단계 | 결과는 같지만 반복 전송·대기로 전체 지연이 늘 수 있다고 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
