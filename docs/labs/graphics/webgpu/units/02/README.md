## 목표와 학습 후 역량

- 장치 기능을 협상한다.
- 한도 기반 입력 검사를 작성한다.

## 선수 지식

1단위 결과물과 기록을 이어 사용합니다. 기능과 limits 협상 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 선택 기능

모든 adapter가 같은 선택 기능을 제공하지 않습니다. 필요한 기능은 지원 목록에서 확인하고 요청해야 합니다.

### 한도

자원 크기와 binding 수에는 장치 한도가 있습니다. 큰 값을 추정하기보다 device.limits에 맞춰 입력을 제한합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. capabilities.js에서 adapter.features와 limits를 필요한 항목만 표로 표시하세요.
2. 필수 기능과 선택 기능을 구분해 requestDevice descriptor를 작성하세요.
3. 지원되지 않는 선택 기능은 비활성화하고 최대 buffer 크기 입력을 검증하세요.

## 관찰할 변수

| 변수      | 기준 조건  | 바꿀 조건         | 예상할 변화·검증 가설                                                        |
| --------- | ---------- | ----------------- | ---------------------------------------------------------------------------- |
| 선택 기능 | 사용 안 함 | 지원 확인 후 요청 | 지원 장치에서만 기능이 켜지고 나머지는 기본 경로를 유지할 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
