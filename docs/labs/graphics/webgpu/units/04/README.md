## 목표와 학습 후 역량

- 명령 생명주기를 구성한다.
- 제출과 완료를 구분한다.

## 선수 지식

3단위 결과물과 기록을 이어 사용합니다. 명령 기록과 제출 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 기록 단계

command encoder는 작업을 즉시 완료하는 함수가 아닙니다. pass를 끝낸 뒤 command buffer를 만들어 queue에 제출합니다.

### 완료 시점

submit 호출 반환은 GPU 작업 완료를 뜻하지 않습니다. 완료를 기다리는 코드는 필요한 관찰 지점에만 둡니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. commands.js에 createCommandEncoder·beginRenderPass·end·finish·submit 순서를 작성하세요.
2. clear 색 두 개를 서로 다른 제출로 기록하고 화면의 마지막 색을 확인하세요.
3. submit 전후와 onSubmittedWorkDone 완료 시점을 로그로 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 제출 수 | 한 번 | 두 번 | 마지막 clear 결과가 보이며 제출 로그와 완료 로그가 구분될 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건
