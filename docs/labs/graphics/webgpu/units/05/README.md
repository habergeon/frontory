# WebGPU · 05 셰이더 모듈과 진단

## 목표와 학습 후 역량

- 셰이더 진단을 표시한다.
- 모듈과 pipeline 오류를 구분한다.

## 선수 지식

4단위 결과물과 기록을 이어 사용합니다. 셰이더 모듈과 진단 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 모듈 진단

WGSL 문법과 타입 오류는 shader module의 compilation info로 확인할 수 있습니다. 오류 메시지의 줄 위치를 소스에 연결합니다.

### Pipeline 검증

유효한 모듈도 entry point나 target 계약이 맞지 않으면 pipeline 생성에 실패합니다. 컴파일과 pipeline 검증을 별도로 기록합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. shader.wgsl에 최소 vertex·fragment 함수를 작성하세요.
2. getCompilationInfo로 메시지와 lineNum을 UI에 출력하세요.
3. 오타와 잘못된 entryPoint를 각각 넣고 복구 후 삼각형을 출력하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| entry point | 실제 함수 이름 | 없는 함수 이름 | 모듈 문법은 통과해도 pipeline 단계에서 실패할 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 문법 오류와 entry point 오류를 별도로 기록한다.
- [ ] 원래 소스로 복구하면 삼각형이 다시 나타난다.

## 자가 점검

1. 모듈에 오류가 없는데 왜 pipeline이 실패하나요?
2. 진단이 비동기일 때 이전 메시지가 새 코드를 덮지 않게 하려면 무엇이 필요한가요?
