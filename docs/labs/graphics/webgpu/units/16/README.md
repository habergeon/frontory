## 목표와 학습 후 역량

- 입출력 상태를 분리한다.
- 반복 계산의 데이터 의존성을 관리한다.

## 선수 지식

15단위 결과물과 기록을 이어 사용합니다. Storage와 ping-pong 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 쓰기 충돌

이웃 값을 읽으며 같은 배열을 갱신하면 실행 순서에 따라 결과가 바뀔 수 있습니다. 입력과 출력을 나눈 ping-pong buffer가 이전 상태를 보존합니다.

### 프레임 교체

한 단계가 끝나면 다음 단계의 읽기·쓰기 역할을 바꿉니다. bind group을 미리 두 개 만들어 교환할 수 있습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. simulation.wgsl에 이웃 세 값의 평균을 출력하는 kernel을 작성하세요.
2. A→B와 B→A bind group을 만들고 매 단계 교대하세요.
3. 세 단계 결과를 CPU의 별도 입력·출력 배열 계산과 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입출력 자원 | 분리한 A/B | 같은 배열을 읽고 쓰는 개념 검토 | 같은 배열 방식은 순서 의존성이 생길 수 있어 기준으로 사용하지 않을 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 각 단계의 읽기·쓰기 buffer id를 기록한다.
