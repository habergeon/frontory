# WebGPU · 21 Instancing과 데이터 구조

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: Compute와 데이터 이동 · 문서 기반 직접 구현 · 저장 ID: `webgpu-step-21`

## 목표와 학습 후 역량

- 인스턴스 렌더링을 구성한다.
- 호출 수와 처리량을 구분한다.

## 선수 지식

20단위 결과물과 기록을 이어 사용합니다. Instancing과 데이터 구조 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 인스턴스

같은 기본 도형을 여러 번 그릴 때 instance index로 개별 데이터를 조회할 수 있습니다. draw 호출 수와 화면 fragment 수는 서로 다른 비용입니다.

### 배열 구조

AoS와 SoA는 데이터 접근 방식에 따라 관리와 접근 패턴이 달라집니다. 구조 변경의 이점은 실제 커널에서 측정합니다.

## 실습 준비

별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. instance.wgsl에서 instance_index로 위치·색 storage 배열을 읽으세요.
2. 작은 quad를 256개 instance로 그리며 한 draw로 묶으세요.
3. 입자 수 64·256·512의 draw 수와 프레임 간격을 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| instance 수 | 64 | 512 | draw 수는 같고 정점·fragment 처리량은 늘 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 세 수량에서 draw 호출이 한 번이다.
- [ ] 각 instance가 고유 위치와 색을 읽는지 네 표식을 확인한다.
