# WebGPU · 22 Device loss와 재초기화

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 복구·측정·통합 프로젝트 · 편집 가능한 예제 · 저장 ID: `webgpu-step-22`

## 목표와 학습 후 역량

- 장치 손실을 처리한다.
- 자원 재생성 경로를 검증한다.

## 선수 지식

21단위 결과물과 기록을 이어 사용합니다. Device loss와 재초기화 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 손실 상태

device.lost는 장치가 더 이상 유효하지 않음을 알립니다. 이전 device의 자원은 새 device에서 그대로 사용할 수 없습니다.

### 재생성

복구에는 shader·buffer·pipeline을 다시 만드는 경로가 필요합니다. CPU 쪽 설정과 초기 데이터는 재생성 가능한 형태로 보관합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. device.js에 device.lost 처리와 렌더 루프 중단을 연결하세요.
2. 개발용 버튼으로 device.destroy를 호출하고 손실 사유를 표시하세요.
3. 사용자 재시도 동작에서 새 device와 자원을 만들고 저장한 설정을 복원하세요.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건             | 예상할 변화·검증 가설                                                |
| --------- | --------- | --------------------- | -------------------------------------------------------------------- |
| 장치 상태 | 정상      | destroy로 의도한 손실 | 루프가 멈추고 명시적 재시도 후 새 자원으로 복구될 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 손실 뒤 이전 device로 제출하지 않는다.
- [ ] 재시도 후 새 device로 동일 초기 장면을 생성한다.
