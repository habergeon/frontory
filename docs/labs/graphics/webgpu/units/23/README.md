# WebGPU · 23 비동기 오류와 작업 식별

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 복구·측정·통합 프로젝트 · 편집 가능한 예제 · 저장 ID: `webgpu-step-23`

## 목표와 학습 후 역량

- 비동기 오류를 작업에 연결한다.
- 낡은 결과의 반영을 차단한다.

## 선수 지식

22단위 결과물과 기록을 이어 사용합니다. 비동기 오류와 작업 식별 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 오류 통로

error scope와 uncapturederror는 서로 다른 오류 관찰 경로입니다. 예상한 검증 실패와 예상하지 못한 오류를 구분해 보여 줍니다.

### 세대 번호

재초기화 중 이전 비동기 작업이 끝날 수 있습니다. device 세대 번호로 낡은 결과가 새 상태를 바꾸지 못하게 합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. errors.js에 uncapturederror listener와 작업 label을 추가하세요.
2. pipeline 생성 중 재초기화를 요청하는 지연 fixture를 만드세요.
3. 완료 결과의 generation을 비교하고 이전 결과를 폐기한 기록을 남기세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 완료 순서 | 현재 세대 먼저 | 이전 세대가 늦게 완료 | 늦은 결과가 새 pipeline을 교체하지 않을 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 오류 로그에 작업 label과 세대가 표시된다.
- [ ] 두 완료 순서에서 현재 세대 자원만 사용한다.
