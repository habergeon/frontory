# WebGPU · 26 Workgroup 크기 실험

## 목표와 학습 후 역량

- 한도 안에서 커널 구성을 비교한다.
- 정확성을 유지하며 비용을 측정한다.

## 선수 지식

25단위 결과물과 기록을 이어 사용합니다. Workgroup 크기 실험 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 구성 제약

workgroup 크기는 장치 한도와 shader 선언을 함께 만족해야 합니다. 크기가 커질수록 항상 빨라지는 것은 아닙니다.

### 공정 비교

같은 입력·같은 연산·같은 readback 정책으로 비교해야 합니다. 커널 구성을 바꾸면서 알고리즘까지 바꾸면 원인을 분리하기 어렵습니다.

## 실습 준비

별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. tuning.js에 32·64·128 lane kernel 변형을 준비하고 limits를 검사하세요.
2. N=1003의 동일 입력을 각 구성에서 실행하세요.
3. 정확성 확인 후 전체 지연 다섯 회와 지원 구성 목록을 저장하세요.
