## 선수 지식

27단위 결과물과 기록을 이어 사용합니다. 상호작용과 비용 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 효과 통합

포인터·파동·noise·texture 샘플은 서로 다른 입력과 비용을 갖습니다. 효과를 끌 수 있게 분리하면 결과와 비용을 추적하기 쉽습니다.

### 결과 근거

빠른 설정의 선택에는 품질 손실과 지원 조건이 포함되어야 합니다. 실행하지 않은 환경의 성능을 추정 결과로 단정하지 않습니다.

## 실습 준비

기존 glsl-03 미리보기는 출발점입니다. 이후 과제 전체의 구현이나 검증을 대신하지 않습니다. 별도 localhost 프로젝트에서 WebGL2와 GLSL ES 3.00으로 직접 구현하는 문서 안내 실습입니다. 기존 예제의 GLSL 버전을 먼저 확인하고 1.00 문법을 혼용하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 최종 shader에 포인터 파동과 효과별 토글을 연결하고 preset 세 개를 재생하세요.
2. 해상도·반복 수·샘플 수를 한 번에 하나씩 바꿔 이미지와 프레임 분포를 기록하세요.
3. 컴파일 오류 입력과 복구를 확인한 뒤 report.md에 채택 설정과 남은 한계를 적으세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 반복 수 | 4 | 2 | 계산량과 미세한 세부가 함께 줄 수 있다고 예상하고 같은 입력에서 확인하세요. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
