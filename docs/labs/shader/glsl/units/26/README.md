# GLSL · 26 편집 실패와 Context 복구

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 상호작용·후처리·비용 평가 · 문서 기반 직접 구현 · 저장 ID: `glsl-step-26`

## 목표와 학습 후 역량

- 셰이더 편집을 안전하게 적용한다.
- GPU 자원 복구를 설계한다.

## 선수 지식

25단위 결과물과 기록을 이어 사용합니다. 편집 실패와 Context 복구 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 안전 교체

새 shader가 실패했을 때 마지막 정상 program을 유지하면 편집을 계속할 수 있습니다. 검증된 새 program만 활성 상태로 교체합니다.

### 컨텍스트 수명

WebGL context가 복구되면 이전 GPU 자원은 다시 만들어야 합니다. 소스와 CPU 입력을 저장해 재생성 경로를 준비합니다.

## 실습 준비

별도 localhost 프로젝트에서 WebGL2와 GLSL ES 3.00으로 직접 구현하는 문서 안내 실습입니다. 기존 예제의 GLSL 버전을 먼저 확인하고 1.00 문법을 혼용하지 않습니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. editor.js에서 후보 program을 compile·link한 뒤 성공한 경우에만 교체하세요.
2. 문법 오류 입력 후 오류 줄과 기존 화면 유지 여부를 확인하세요.
3. webglcontextlost·webglcontextrestored를 처리하고 재생성 목록을 README에 적으세요.
