# GLSL · 27 품질 기준과 회귀 기록

## 목표와 학습 후 역량

- 재현 가능한 시각 기준을 만든다.
- 국소 품질 손실을 기록한다.

## 선수 지식

26단위 결과물과 기록을 이어 사용합니다. 품질 기준과 회귀 기록 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 고정 입력

시간과 포인터를 고정하면 이미지 비교가 재현 가능해집니다. 렌더 환경이 다르면 픽셀 차이가 날 수 있어 허용 기준을 기록합니다.

### 관심 영역

전체 평균 차이는 작은 하이라이트나 얇은 경계의 손실을 숨길 수 있습니다. 전체 화면과 지정 영역을 함께 비교합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 프로젝트에서 WebGL2와 GLSL ES 3.00으로 직접 구현하는 문서 안내 실습입니다. 기존 예제의 GLSL 버전을 먼저 확인하고 1.00 문법을 혼용하지 않습니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. presets.json에 시간·포인터·해상도·효과 변수를 저장하세요.
2. 세 preset의 기준 이미지와 절반 해상도 이미지를 캡처하세요.
3. report.md에 경계·블러·하이라이트 ROI 차이와 환경을 기록하세요.

## 관찰할 변수

| 변수      | 기준 조건              | 바꿀 조건                 | 예상할 변화·검증 가설                                              |
| --------- | ---------------------- | ------------------------- | ------------------------------------------------------------------ |
| 품질 설정 | 전체 해상도와 4 octave | 절반 해상도와 같은 octave | 픽셀 비용이 줄지만 경계와 고주파 세부 손실이 늘 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 연결된 예제와 실행 범위

[예제 원본](../../../../../../src/labs/glsl-step-27/example.js) · [실행 환경과 제한](../../../../../examples.md)

브라우저 WebGL ShaderMaterial 실행. 640×360/320×180 비교이며 프레임 간격은 GPU 시간과 다릅니다. 제공된 선택은 전체/절반 해상도와 noise 보간식을 함께 바꾸며 4 octave는 유지합니다. 해상도만 바꾼 통제 비교로 해석할 수 없습니다. 보간식을 고정한 비교는 별도 과제입니다.

원본 코드·기록은 자동으로 덮어쓰지 않습니다. 기존 예제를 초기화할 때도 필기는 유지됩니다.
