# WGSL · 05 함수와 구조체 계약

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 타입과 셰이더 인터페이스 · 편집 가능한 예제 · 저장 ID: `wgsl-step-05`

## 목표와 학습 후 역량

- 타입이 명확한 계산 함수를 만든다.
- 구조체의 사용 목적을 구분한다.

## 선수 지식

4단위 결과물과 기록을 이어 사용합니다. 함수와 구조체 계약 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 함수 분리

순수 계산 함수를 분리하면 같은 수학을 vertex와 compute에서 검증하기 쉽습니다. 입력과 반환 타입을 구체적으로 선언합니다.

### 구조체

구조체는 관련된 필드를 묶지만 stage용 속성과 메모리용 규약은 사용 위치에 따라 다릅니다. 화면 입출력 구조를 그대로 storage 구조로 가정하지 않습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. functions.wgsl에 wave(x,time,amplitude)와 결과 구조체를 작성하세요.
2. compute entry point에서 다섯 x 입력을 함수에 전달해 출력하세요.
3. 같은 함수로 vertex 변위를 만들고 수치 출력과 최대 변위를 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 진폭 | 0.1 | 0.3 | 함수의 파장은 유지되고 최대 변위가 세 배가 될 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 다섯 입력의 CPU와 WGSL 함수 값 차이가 1e-5 이하이다.
- [ ] stage 함수와 순수 계산 함수의 입력을 분리한다.

## 자가 점검

1. stage 속성을 일반 계산 함수 인자에 붙여야 하나요?
2. 함수를 나누는 것이 GPU 호출 비용 증가를 항상 뜻하나요?
