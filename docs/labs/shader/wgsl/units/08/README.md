# WGSL · 08 주소 공간과 접근 모드

## 목표와 학습 후 역량

- 주소 공간을 선택한다.
- 자원 접근 권한을 지킨다.

## 선수 지식

7단위 결과물과 기록을 이어 사용합니다. 주소 공간과 접근 모드 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 주소 공간

function·private·workgroup·uniform·storage는 값의 수명과 공유 범위를 정합니다. 이름이 같아 보여도 접근 가능한 invocation 범위가 다릅니다.

### 쓰기 권한

uniform과 읽기 전용 storage에 값을 쓰는 코드는 계약을 위반합니다. storage의 read와 read_write를 실제 작업에 맞게 지정합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. spaces.wgsl에 읽기 uniform과 read storage, read_write output을 선언하세요.
2. 함수 지역 누적값과 private 변수를 구분해 주석을 달세요.
3. 읽기 전용 입력에 쓰는 오류를 만든 뒤 output 쓰기로 복구하세요.

## 관찰할 변수

| 변수      | 기준 조건 | 바꿀 조건        | 예상할 변화·검증 가설                                                 |
| --------- | --------- | ---------------- | --------------------------------------------------------------------- |
| 입력 접근 | read      | 입력에 쓰기 시도 | validation 또는 shader 진단에서 계약 위반이 드러날 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
