# WGSL · 11 행렬과 배열 Stride

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 자원 선언과 메모리 배치 · 편집 가능한 예제 · 저장 ID: `wgsl-step-11`

## 목표와 학습 후 역량

- 행렬의 열 배치를 계산한다.
- 배열 stride를 검증한다.

## 선수 지식

10단위 결과물과 기록을 이어 사용합니다. 행렬과 배열 Stride 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 행렬 배치

mat3x3f는 vec3f 열 세 개를 정렬 간격에 맞춰 저장합니다. 값은 아홉 개여도 저장 배치는 단순한 36바이트 연속 배열과 다릅니다.

### 배열 간격

배열 원소 stride는 원소의 size를 alignment에 맞춰 반올림해 결정됩니다. CPU에서 다음 원소로 이동할 때 같은 stride를 사용합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. matrix-layout.md에 mat3x3f 열 offset 0·16·32와 size 48을 적으세요.
2. 두 행렬을 48바이트 stride로 기록하고 각각 다른 벡터를 곱하세요.
3. 36바이트로 잘못 기록한 사례와 정상 readback 결과를 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 행렬 stride | 48바이트 | 36바이트로 잘못 가정 | 둘째 행렬과 각 열의 값이 어긋날 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
