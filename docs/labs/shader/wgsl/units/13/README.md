# WGSL · 13 런타임 배열과 Binding 범위

## 목표와 학습 후 역량

- 런타임 배열을 선언한다.
- binding 범위와 논리 길이를 구분한다.

## 선수 지식

12단위 결과물과 기록을 이어 사용합니다. 런타임 배열과 Binding 범위 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 런타임 길이

storage의 런타임 크기 배열 길이는 실제 binding 범위와 stride에 영향을 받습니다. buffer 용량 전체를 논리 데이터 길이로 착각하지 않습니다.

### 배치 위치

런타임 배열은 허용된 storage 선언 위치에 두어야 합니다. 구조체를 사용할 때 마지막 멤버라는 제약을 지킵니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. runtime.wgsl에 header 뒤 마지막 멤버로 array<f32>를 둔 storage 구조를 작성하세요.
2. arrayLength로 보이는 길이와 별도 logicalCount를 출력하세요.
3. buffer 용량은 유지하고 bindGroup의 size를 줄여 보이는 길이를 비교하세요.

## 관찰할 변수

| 변수         | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설                                      |
| ------------ | --------- | --------- | ---------------------------------------------------------- |
| binding 범위 | 전체 배열 | 절반 범위 | arrayLength가 노출된 범위에 맞춰 줄어들 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 논리 길이가 실제 접근 가능 길이를 넘는 입력을 호스트에서 거절한다.
