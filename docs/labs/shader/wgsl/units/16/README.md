# WGSL · 16 경계 검사와 빈 입력

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 병렬 계산과 동기화 · 편집 가능한 예제 · 저장 ID: `wgsl-step-16`

## 목표와 학습 후 역량

- 독립 kernel의 경계를 처리한다.
- 빈 입력을 명확히 정의한다.

## 선수 지식

15단위 결과물과 기록을 이어 사용합니다. 경계 검사와 빈 입력 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 남는 lane

dispatch는 workgroup 단위라 입력 길이보다 invocation이 많을 수 있습니다. 독립 원소 kernel은 접근 전에 범위를 검사합니다.

### 빈 작업

길이 0인 입력은 CPU 경로에서 제출을 생략할 수 있습니다. 실제 buffer 최소 크기와 논리 원소 수를 분리해 처리합니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. bounds.wgsl에 id.x>=count일 때 return하는 독립 계산 kernel을 작성하세요.
2. 호스트에 count=0이면 dispatch를 건너뛰는 분기를 두세요.
3. 0·1·63·64·65 길이를 돌리고 마지막 원소와 canary 영역을 검사하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 길이 | 64 | 65 | 유효 lane 한 개를 가진 추가 workgroup이 필요할 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 다섯 길이 모두 CPU 기준과 일치한다.
- [ ] 빈 입력은 제출 생략 상태를 표시하고 canary 값이 유지된다.

## 자가 점검

2. 범위 밖 읽기의 결과에 의존하면 왜 알고리즘이 취약해지나요?
