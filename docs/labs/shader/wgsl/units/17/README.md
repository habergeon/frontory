# WGSL · 17 Workgroup 메모리와 협력

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 병렬 계산과 동기화 · 문서 기반 직접 구현 · 저장 ID: `wgsl-step-17`

## 목표와 학습 후 역량

- 공유 메모리를 초기화한다.
- 그룹 내부 협력을 구현한다.

## 선수 지식

16단위 결과물과 기록을 이어 사용합니다. Workgroup 메모리와 협력 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 공유 데이터

workgroup 배열은 해당 그룹의 invocation들이 협력할 때 사용합니다. 전역 storage를 매번 읽는 횟수를 줄이는 데 쓰일 수 있습니다.

### 초기화와 사용

각 lane의 값이 준비된 뒤 다른 lane이 읽어야 합니다. 부분 그룹의 비활성 lane도 중립값을 쓰고 동기화에 참여합니다.

## 실습 준비

별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. shared.wgsl에 var<workgroup> tile:array<f32,64>를 선언하세요.
2. 유효 lane은 입력을, 나머지는 0을 넣고 workgroupBarrier 뒤 이웃 값을 읽으세요.
3. 길이 65에서 그룹 경계의 출력과 CPU 기준을 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 남는 lane 값 | 0으로 초기화 | 중립값 아닌 1 | 부분 그룹 합이나 평균에 잘못된 값이 섞일 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
