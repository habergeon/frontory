## 목표와 학습 후 역량

- 협력 감소 연산을 작성한다.
- 그룹 간 계산 단계를 나눈다.

## 선수 지식

19단위 결과물과 기록을 이어 사용합니다. 부분합 Reduction 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 트리 계산

감소 연산은 여러 원소를 단계적으로 합칩니다. 각 단계에서 읽기와 쓰기의 의존성이 있으므로 공유 메모리와 barrier 위치를 맞춥니다.

### 다중 단계

workgroup별 부분합을 얻은 뒤에는 추가 dispatch나 CPU 합으로 마무리합니다. 그룹 사이에서 같은 dispatch의 완료를 기다리지 않습니다.

## 실습 준비

예제 화면의 실행 범위 안내를 먼저 확인하세요. 다음은 과제를 별도 프로젝트로 확장할 때의 준비 환경입니다. 별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며, 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. reduce.wgsl에 64 lane 공유 배열과 32·16·8·4·2·1 감소 단계를 작성하세요.
2. 각 단계의 조건부 덧셈 뒤 공통 barrier를 배치하세요.
3. 1003개 입력의 부분합을 readback해 CPU 합과 비교하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 입력 수 | 64 | 1003 | 여러 부분합과 마지막 불완전 그룹을 처리해야 할 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 마지막 그룹이 0 padding을 사용한다.
- [ ] 전체 결과가 사전에 정한 abs/relative 오차 기준을 만족한다.
