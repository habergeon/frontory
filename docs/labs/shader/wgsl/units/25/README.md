# WGSL · 25 커널 테스트와 Sentinel

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 수치 검증과 커널 설계 · 문서 기반 직접 구현 · 저장 ID: `wgsl-step-25`

## 목표와 학습 후 역량

- 경계 중심 테스트를 구성한다.
- 수치 실패를 재현 가능한 정보로 보고한다.

## 선수 지식

24단위 결과물과 기록을 이어 사용합니다. 커널 테스트와 Sentinel 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 검증 자료

무작위 입력만으로는 경계 오류를 찾기 어렵습니다. 빈 배열·한 원소·배수 전후·음수·반복값을 포함한 고정 사례를 만듭니다.

### 쓰기 범위

출력 뒤 sentinel 영역을 두면 의도하지 않은 쓰기를 탐색하는 데 도움이 됩니다. sentinel이 유지된다는 사실만으로 모든 메모리 안전성을 증명하지는 않습니다.

## 실습 준비

별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. cases.json에 길이 0·1·63·64·65·1003과 값 분포를 적으세요.
2. 출력의 논리 범위 뒤에 sentinel 값을 초기화하고 실행 후 검사하세요.
3. kernel별 CPU 기준·최대 오차·최초 실패 index를 report.json에 저장하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 길이 | 64 | 63과 65 | 경계에서 누락 또는 범위 오류가 있으면 기준 비교나 sentinel 검사에 드러날 것으로 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
