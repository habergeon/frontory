# WGSL · 26 Workgroup 구성과 측정

[시리즈 목차](../../README.md) · [전체 기술 지도](../../../../README.md)

단계: 수치 검증과 커널 설계 · 문서 기반 직접 구현 · 저장 ID: `wgsl-step-26`

## 목표와 학습 후 역량

- 커널 구성 후보를 검증한다.
- 측정 범위에 맞게 결과를 해석한다.

## 선수 지식

25단위 결과물과 기록을 이어 사용합니다. Workgroup 구성과 측정 실험에 앞서 이전 입력과 기준 출력을 보관합니다.

## 핵심 개념과 설명

### 구성 선택

workgroup 크기는 병렬 배치와 공유 메모리 사용량을 바꿉니다. 장치 limits를 넘지 않는 후보만 pipeline으로 만듭니다.

### 비교 범위

명령 제출부터 readback까지의 시간은 kernel만의 시간이 아닙니다. GPU 구간을 측정하지 못하면 전체 지연으로 이름 붙입니다.

## 실습 준비

별도 localhost 또는 HTTPS 프로젝트에서 직접 구현하는 문서 안내 실습입니다. secure context, navigator.gpu, adapter 요청 결과를 확인하고 미지원 안내를 제공합니다. device.lost 처리와 자원 해제를 유지합니다.

이 단위에는 내장 실행 예제가 없습니다. 아래 절차에 따라 별도 실습 파일을 만들고 실행 결과를 필기에 남기세요. 코드 파일은 작업 폴더에서 따로 보관하고 Frontory 필기는 JSON 또는 Markdown으로 백업하세요.

## 실습 과제

1. tune.wgsl에 override 기반 32·64·128 workgroup 후보를 작성하세요.
2. 호스트에서 limits를 확인하고 동일 1003개 입력으로 정확성을 먼저 검사하세요.
3. 예열 뒤 다섯 번의 전체 지연과 공유 배열 바이트 수를 기록하세요.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| workgroup 크기 | 64 | 32와 128 | 장치별 비용은 달라져도 계산 결과는 오차 범위 안에서 같아야 한다고 예상합니다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.
