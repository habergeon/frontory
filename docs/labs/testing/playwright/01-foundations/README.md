# Playwright · 01 사용자 관점의 테스트

[시리즈 목차](../README.md) · [전체 기술 지도](../../../README.md)

단계: 사용자 흐름과 Locator · 외부 실행 예제 · 미리보기 안내 · 저장 ID: `playwright-01`

## 목표와 학습 후 역량

- 학습 결과: 사용자 계약의 역할을 설명한다. 입력 사례: 목차 선택과 문서 열기 버튼.
- 산출물: 선택 제목·dialog 표시 assertion 결과. 자동 대기 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

DOM 역할·비동기, 테스트 기본를 이해하고 기존 시작 예제의 입력과 출력을 읽을 수 있다.

## 핵심 개념과 설명

### 사용자 계약

role과 label은 사용자가 이해하는 UI 의미를 따른다. 내부 클래스 이름보다 행동의 목적을 드러낸다.

### 자동 대기

locator action과 재시도 assertion은 상태를 기다린다. 고정 sleep으로 준비 시점을 추측하지 않는다.

## 실습 준비

모든 테스트는 별도 Node 프로젝트의 @playwright/test와 테스트 전용 로컬 origin에서 작성·실행한다. 기존 playwright-01·02·03 미리보기는 테스트 소스를 보여줄 뿐 iframe에서 Playwright를 실행하지 않는다. 새 테스트 파일은 과제에서 직접 작성하며 통과 여부는 실제 runner 출력으로만 판단한다. 사용자 profile·실사용 저장소를 사용하지 않고 CSP·격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 tests/day-1.spec.ts에 별도 Node 프로젝트에 @playwright/test를 설치하고 Frontory 목차·문서 열기 테스트를 작성한다. 기존 1·14·28단위 예제는 출발점으로만 참고한다.
2. 입력 조건: 목차 선택과 문서 열기 버튼. 기준: 1280×800. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-1.md에 남긴다.
3. 변경 변수: viewport, 변경값: 390×844. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 선택 제목·dialog 표시 assertion 결과. 확인할 가설: 두 크기에서 같은 사용자 흐름을 검증한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| viewport | 1280×800 | 390×844 | 두 크기에서 같은 사용자 흐름을 검증한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 선택 제목·dialog 표시 assertion 결과. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 사용자 계약, 자동 대기. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 사용자 계약 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 목차 선택과 문서 열기 버튼.
2. 변경 변수: viewport. 확인할 가설: 두 크기에서 같은 사용자 흐름을 검증한다. 실제 결과가 가설과 일치했는가? 자동 대기 관점에서 근거를 설명하라.
