- 산출물: 왕복 후 필기와 오류 보존 결과. 격리 처리의 근거를 코드와 연결해 설명한다.

## 선수 지식

13단위 「항목별 저장 격리」의 식별자 및 왕복 이동 실습 결과를 준비한다.

## 핵심 개념과 설명

### 왕복 계약

백업 파일은 다시 가져와 같은 데이터를 만들 수 있어야 한다. 파일 생성과 저장소 복원을 함께 확인한다.

### 격리

실사용 origin을 테스트 대상으로 삼지 않는다. 파일과 저장소는 테스트별로 분리한다.

## 실습 준비

모든 테스트는 별도 Node 프로젝트의 @playwright/test와 테스트 전용 로컬 origin에서 작성·실행한다. 기존 playwright-01·02·03 미리보기는 테스트 소스를 보여줄 뿐 iframe에서 Playwright를 실행하지 않는다. 새 테스트 파일은 과제에서 직접 작성하며 통과 여부는 실제 runner 출력으로만 판단한다. 사용자 profile·실사용 저장소를 사용하지 않고 CSP·격리를 유지한다.

연결된 예제는 출발점입니다. 아래 과제 전체가 완성된 코드는 아니며 예제의 지원 범위를 넘는 작업은 별도 프로젝트에서 수행하세요.

## 실습 과제

1. 별도 실습 프로젝트의 tests/day-14.spec.ts에서 테스트 전용 Frontory origin을 사용한다. 필기 작성→전체 644단위 v3 JSON 다운로드→필기 수정→같은 전체 파일 가져오기→검증 확인 화면→전체 교체하여 복원 버튼 클릭→reload 순서를 작성한다.
2. 입력 조건: 빈 메모·한글·오류 파일. 기준: 유효 백업. 기준 조건에서 실행한 뒤 관찰값과 오류를 notes/day-14.md에 남긴다.
3. 변경 변수: 파일, 변경값: 잘못된 JSON. 같은 입력 경로로 다시 실행한다. 저장할 산출물: 왕복 후 필기와 오류 보존 결과. 확인할 가설: 정상 파일은 복원하고 오류 파일은 기존 값을 보존한다. 실제 결과와 비교해 일치 여부 및 차이의 원인을 기록한다.

## 관찰할 변수

| 변수 | 기준 조건 | 바꿀 조건 | 예상할 변화·검증 가설 |
| --- | --- | --- | --- |
| 파일 | 유효 백업 | 잘못된 JSON | 정상 파일은 복원하고 오류 파일은 기존 값을 보존한다. |

표의 예상은 측정 결과가 아닙니다. 한 번에 한 조건만 바꾸고 실제 결과가 다르면 원인을 기록하세요.

## 완료 조건

- [ ] 필수 산출물: 왕복 후 필기와 오류 보존 결과. 기준 및 변경 조건 각각의 결과가 있어 총 2조건을 비교할 수 있고 입력값과 실행 환경을 함께 기록했다.
- [ ] 두 조건의 차이에 관한 설명에 다음 개념을 모두 연결했다: 왕복 계약, 격리. 예상과 다른 항목은 원인 또는 미해결 이유를 1개 이상 적었다.

## 자가 점검

1. 이번 실습에서 왕복 계약 개념은 어느 처리 단계에 영향을 주는가? 입력 사례: 빈 메모·한글·오류 파일.
2. 변경 변수: 파일. 확인할 가설: 정상 파일은 복원하고 오류 파일은 기존 값을 보존한다. 실제 결과가 가설과 일치했는가? 격리 관점에서 근거를 설명하라.
