# 성능 실험 기록

현재 **성능 측정을 수행하지 않았습니다.** 초기 코드의 DPR 상한 2, 작은 큐브 한 개 등은 시작 설정이며 최적화 성과가 아닙니다. 빌드 성공과 렌더링 속도를 구분합니다.

## 관찰할 값

- 프레임 시간(ms)의 분포, 긴 프레임과 끊김. 평균 FPS 하나로 판단하지 않습니다.
- CPU 작업: React 업데이트, 장면 업데이트, 데이터 파싱·정렬 등. 브라우저 Performance 패널로 구간을 관찰합니다.
- GPU 비용: 해상도·화면을 덮는 픽셀·shader 복잡도 등의 영향을 가설로 확인합니다. JS 프레임 시간만으로 GPU 시간을 확정하지 않습니다.
- `renderer.info.render.calls / triangles`, `renderer.info.memory.geometries / textures`: Three.js의 일부 카운터이며 전체 GPU 메모리 사용량이 아닙니다. GS workload도 삼각형 수만으로 설명할 수 없습니다.
- 로딩: 전송 / 파싱 / 첫 화면까지의 시간을 분리합니다.
- 장면 전환 반복: canvas, listener, context, geometry, texture가 계속 늘어나는지 확인합니다. 브라우저·드라이버 메모리는 즉시 줄지 않을 수 있습니다.
