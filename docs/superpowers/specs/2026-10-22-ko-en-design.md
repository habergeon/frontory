# Frontory 한국어·영어 지원 설계

2026-10-22 · 조사 기준 `6ebe3cb` · 상태: 2026-10-22 사용자 승인 설계, 실행 계획 작성

사용자는 한국어와 영어 지원의 범위·대상을 전체적으로 파악하고 서브에이전트로 필요한 작업을 진행하도록 요청했다. UI·저장, 콘텐츠·예제, URL·검색·배포를 `gpt-6.1-sol`·`medium` 서브에이전트 세 명이 각각 조사했다. 사용자는 이 제안서를 검토한 뒤 전체 644개를 목표로 대표 강의 네 개부터 검증하는 방향에 동의했다. 이 문서는 승인된 설계를 정리하며 구현 완료를 뜻하지 않는다.

최종 목표는 영어 사용자가 한국어 사용자와 같은 23개 시리즈·644개 학습 단위를 이용하는 것이다. 대표 강의 네 개에서 전체 학습 흐름을 먼저 검증하고 나머지 시리즈로 확장한다. 네 개만 마친 상태를 전체 영어 지원 완료로 표시하지 않는다.

## 지원 대상

| 구분 | 대상 | 번역·변경 경계 |
| --- | --- | --- |
| 앱 화면 | 홈, 탐색·필터, 학습 단계, 실습 가이드, 편집기, 필기, 문서 창, 백업·복원 | 버튼·도움말·상태·오류 안내·접근성 이름·날짜·개수 표시 |
| 시리즈·강의 | 23개 시리즈 소개 + 644개 강의 = 667개 학습 문서 | 제목·목표·개념·과제·관찰 변수 설명·완료 조건·질문·실행 환경 |
| 학습 메타데이터 | 92개 단계명, 분야·선수 지식, 예제 실행 설명 | 기술·제품명은 원어를 유지하고 설명을 번역 |
| 예제 | `example.js` 644개, 추가 파일 233개 | 화면·도움말·설명 주석·사용법을 조사. 추가 파일에는 binary도 있어 233개 전부가 번역 대상은 아님 |

| 저장소 안내 | README, CONTRIBUTING, 예제 companion README 5개 | 영어 사용자가 실행·기여하는 데 필요한 안내. 내부 설계·작업 이력 전체 번역은 제외 |
| 검색·배포 | 홈·목차·강의·안내·404, 메타데이터, 내부 링크, 사이트맵 | 언어별 정적 HTML을 실제 생성하고 직접 진입·새로고침 검증 |

콘텐츠 원본은 22개 커리큘럼 JSON의 616개 단위와 수동 관리하는 WebGL 문서 29개다. 현재 생성기는 638개 학습 Markdown, 카탈로그, 확장 예제 색인 등 640개 파일을 만든다. 생성물만 번역하면 재생성 때 사라지므로 원본과 생성기를 함께 다뤄야 한다.

`content/examples/*.json`의 메타데이터는 추가 예제 550개이며 전체 644개를 뜻하지 않는다. 기존 예제에는 `curriculum.ts`의 별도 설명도 있다. `docs/**/*.md` 688개에는 내부 계획과 검증 문서가 포함되어 있으므로 이를 모두 번역량으로 계산하지 않는다. 수량은 JSON 파싱과 파일 열거로 확인했다. 생성 관계의 근거는 `scripts/build-curricula.mjs`, 실행 공급원의 근거는 `src/app/curriculum.ts`다.

## 그대로 유지할 것

학습 ID, 시리즈 ID, 코드 식별자, URL·참고 문헌 주소, 파일 경로, DOM id, 상태 enum, 날짜 저장 형식은 번역하지 않는다. 사용자 code·notes·progress와 기존 백업 v1/v2/v3도 그대로 사용한다. UI 언어를 바꿨다는 이유로 저장 내용을 다시 쓰거나 한국어 필기를 영어로 바꾸지 않는다.

실험 입력·출력의 숫자와 key, 인코딩·정렬·문자열 길이 학습에 쓰이는 한글, 과제 자체가 비교하는 `lang: ko → en`은 학습 조건이다. 문맥을 확인해 보존한다. 컴파일러·브라우저·사용자 코드의 원문 오류는 그대로 보여 주고 앱이 붙이는 설명만 번역한다.

AdSense는 검토 요청 준비 상태다. 영어 지원 추가를 광고 승인·운영 개시로 표현하지 않는다. 이번 다국어 작업으로 기존 한국어 네 경로의 광고 태그 범위를 확대하지 않는다.

## 확정한 구조

### 1. 한국어 주소 유지, 영어는 `/en/`

| 화면 | 한국어 | 영어 |
| --- | --- | --- |
| 홈 | `/` | `/en/` |
| 실습 | `/#react-step-03` | `/en/#react-step-03` |
| 공개 강의 | `/learn/react/react-step-03/` | `/en/learn/react/react-step-03/` |
| 목차 | `/learn/` | `/en/learn/` |
| 소개·개인정보 | `/about/`, `/privacy/` | `/en/about/`, `/en/privacy/` |

URL이 표시 언어를 결정한다. 기존 `/`를 한국어 주소로 유지하므로 저장된 선호 언어가 영어라는 이유로 `/` 방문자를 자동 이동시키지 않는다. 언어 선택은 같은 학습 ID로 이동하며 앱 안에서는 Context와 history를 갱신해 편집기를 다시 만들지 않는다. URL에 이미 언어가 있으므로 별도 localStorage 언어 설정은 첫 구현에 필요하지 않다. 브라우저 뒤로 가기·앞으로 가기에서도 pathname과 상태를 함께 갱신한다.

언어별 URL과 명시적 전환 링크는 Google의 다국어 사이트 권고에 맞춘 선택이다. [Google 다국어 사이트 관리](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites)

### 2. 두 언어용 작은 메시지 사전

UI는 타입을 검사할 수 있는 ko/en 메시지 사전과 React Context로 처리한다. 문장 전체를 key로 관리하고 숫자·제목 등의 값을 인자로 넣는다. 정적 생성기는 같은 순수 메시지 모듈을 사용한다. 두 언어의 key·인자 일치와 0·1·복수 표기를 검사한다. 새 번역 라이브러리는 현재 두 언어 요구만으로 추가하지 않는다.

상태나 저장 경고를 완성된 한국어 문자열로 보관하는 부분은 상태 code와 표시 문구를 분리한다. 그러면 이미 떠 있는 경고도 언어 전환에 따라 바뀌며, 다시 저장하거나 코드를 재실행할 필요가 없다.

### 3. 콘텐츠는 안정 ID에 연결하고 생성은 한 경로로

한국어 원본 구조를 유지하면서 영어 산문을 안정 ID별 별도 데이터로 관리한다. 영어 데이터는 제목·설명·과제 등 번역 필드만 가진다. 숫자·ID·파일 경로 등 공통 구조를 복제해 따로 수정하지 않는다. 배열 길이와 참고 문헌 URL을 대조하고 원문 hash로 오래된 번역을 찾는다.

22개 시리즈의 영어 문서·카탈로그는 동일 생성기로 만든다. WebGL 29개 수동 문서는 번역 문서 쌍으로 관리한다. 공개 학습 문서와 앱의 문서 창이 같은 번역을 읽어야 한다. 현재 모든 Markdown을 eager import하므로 영어 644개를 같은 초기 번들에 그대로 추가하지 않고 학습 문서를 필요할 때 읽는 로더로 나눈다. 요청·캐시는 `(locale, docPath)`로 구분하고 이전 요청의 늦은 응답은 버린다. 문서 로딩이 학습 기록 저장을 유발하지 않아야 하며 로딩 실패·빠른 강의 전환을 검증한다.

실습 가이드와 빈 기록 서식 제거는 현재 한국어 제목 문자열에 의존한다. 생성 템플릿과 파서가 ko/en 공통 heading 명세를 사용하도록 바꾼다. 단순한 두 언어 지원 때문에 별도 콘텐츠 관리 시스템을 만들지는 않는다.

### 4. 예제 알고리즘과 저장 코드는 공통

실행 원본 644개를 수동으로 두 벌 관리하지 않는다. runtime의 mount context에 선택 언어를 전달하고 예제용 표시 문구를 공통 원본에서 제공한다. 기존 `mount({container})`는 추가 필드를 무시하므로 구형 예제도 실행되어야 한다. 메시지는 예제에 필요한 범위만 포함하고 다운로드한 코드에도 기본값이 있어야 한다.

설명 주석은 생성 템플릿에서 만든 영어 읽기용 원본으로 제공하고 현재 편집·실행 중인 코드와 구분한다. 언어 전환이나 읽기용 원본 다운로드로 사용자 초안을 바꾸지 않는다. 원본 복원은 현재처럼 사용자가 명시적으로 선택할 때만 수행하며 필기는 보존한다. 외부 Node·Playwright·HTML·Svelte 등의 companion은 iframe runtime을 거치지 않으므로 각각 실행 안내·fixture·텍스트 selector를 함께 검토한다. 주석의 타입 검사 지시문과 실험 입력은 보존한다.

앱의 언어는 즉시 바꾸되 실행 중인 iframe은 유지한다. 예제 내부 언어는 다음 코드 반영 또는 ‘다시 실행’ 때 적용한다. 이렇게 하면 언어 선택만으로 카메라·애니메이션·입력 상태가 초기화되지 않는다. 사용자가 수정한 예제는 언어 전환으로 새 원본을 덮어쓰지 않으므로 기존 한국어 문구가 남을 수 있다.

### 5. 필기와 진도는 두 언어에서 공유

`Draft.language`는 JavaScript/TypeScript를 뜻하므로 UI locale과 구분한다. 기존 저장 key와 백업 버전을 유지한다. 새 필기 템플릿만 실제 학습을 처음 시작하는 언어로 만들고 이후 전환에서는 바꾸지 않는다. 홈에서 진도를 읽는 동작이 모든 미작성 단위에 한국어 템플릿을 미리 확정하지 않도록 저장소 읽기와 최초 템플릿 결정을 구분한다.

### 6. 영어 문서가 있는 주소만 공개

영어 페이지는 자기 URL을 canonical로 사용하고 ko/en 페이지가 서로 hreflang을 연결한다. 페이지마다 자신도 포함한다. 단일 사이트맵에 공개된 두 언어 URL을 넣고 hreflang은 HTML에서만 관리한다. [Google 언어별 페이지 안내](https://developers.google.com/search/docs/specialty/international/localized-versions)

전체 공개 페이지를 두 언어로 대응시키면 현재 671개에서 1,342개 canonical URL이 된다. 단계 공개는 `671 + 실제 공개 영어 페이지 수`로 검사한다. 미번역 본문을 한국어로 채운 뒤 영어 페이지라고 색인하지 않는다. 영어 목록에 미제공 상태를 표시하고 한국어 원문 링크를 명확히 제공한다. 없는 영어 주소는 실제 404로 응답한다.

| 순서 | 작업 | 검증 가능한 완료 기준 |

| 7 | 검색·접근성·모바일·운영 검증 | 양언어 링크·canonical·hreflang·404·사이트맵, 320/375/768/1280px, 키보드·dialog·tab·스크린리더 이름 확인 |

4번은 구현을 검증하는 첫 묶음이다. 네 개를 마쳤다고 644개 전체 지원이 끝난 것으로 보고하지 않는다. 5·6번은 시리즈 단위로 작업자를 분리하고 각 시리즈 안에서는 소수 단위씩 번역·대조한다. 생성기·runtime·공용 메시지 모듈은 담당자 한 명이 수정해 충돌을 막는다. 번역 담당자는 공용 계약이 정해진 뒤 독립 파일에서 작업한다.

기존 검증은 `pnpm test`, `pnpm check:curricula`, `pnpm build`, `pnpm check:deploy`다. 추가 검증은 저장 내용 원문 비교, 언어별 콘텐츠 완전성, 번역 fixture 보존, 정적 URL 전수 검사, 실제 브라우저의 전환·편집·저장 경로다. GPU·외부 실행 환경을 확보하지 못한 검사는 미검증으로 따로 남긴다.

## 조사 완료와 구현 인계

UI·저장 조사, 전체 콘텐츠 수량과 원본 관계 조사, 라우팅·검색·배포 조사를 마쳤다. 기존 검색 페이지 테스트 5개는 통과했다. 제품 코드·번역 콘텐츠·의존성은 이번 조사에서 바꾸지 않았다. 앞선 광고 안내 수정 `6ebe3cb`는 CI와 Cloudflare 배포를 마쳤고 운영 `/about/`·`/privacy/`에서 승인 전 문구를 확인했다.

확정한 구현 정책은 전체 644개 영어 지원, 대표 강의 네 개부터 검증, 기존 한국어 URL 유지, `/en/` 추가, 코드·필기·진도 공유, 실행 중인 예제는 다음 실행에 언어 반영이다. 실행 계획은 이 계약을 바탕으로 작성하며 공개 범위를 임의로 축소하지 않는다.

조사 근거 파일: `src/app/App.tsx`, `src/app/guideContent.ts`, `src/shared/drafts.ts`, `src/shared/backup.ts`, `src/preview/runtime-entry.ts`, `scripts/build-curricula.mjs`, `scripts/search-pages.mjs`, `scripts/build-search.mjs`, `vite.config.ts`.

한국어 문체는 `humanize-korean` 룰북으로 검토했다. 사실 확인과 설계 제안이며 원문 윤문 작업이 아니므로 변경률이나 윤문 등급을 산출하지 않았다.
