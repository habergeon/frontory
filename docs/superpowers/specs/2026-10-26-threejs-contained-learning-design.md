# Three.js 자체 완결 학습 환경 설계

작성일: 2026-10-26. 상태: 검토용 설계. 구현과 배포는 아직 시작하지 않았다.

## 목적과 사용자 결정

Frontory 안에서 Three.js 개념을 읽고, 코드를 작성하고, 실행 결과를 관찰하고, 원인을 설명하는 과정을 마칠 수 있게 한다. 필수 과제를 수행할 때 외부 편집기·터미널·개발 서버·공식 문서를 열 필요가 없어야 한다. 공식 자료는 출처와 심화 학습 경로로 남긴다.

사용자는 HTML·CSS·JavaScript 기초를 다른 Frontory 시리즈에서 다루고, Three.js에는 그 기초를 배운 학습자가 들어온다고 정했다. Three.js 초반 과정을 먼저 완성하고 검증한 구조를 다른 시리즈로 확장하는 접근도 선택했다. 이전에 선택한 단일 HTML 문서 방식은 유지한다.

아래 첫 4개 단원 범위, 단계별 학습 구성, 모듈 공급 방식은 이 요구를 구현하기 위한 작성자의 제안이다. 공식 문서 전체나 Three.js의 모든 API를 이번 작업에 담겠다는 약속은 아니다. 먼저 정한 단원의 학습 목표와 필수 과제를 빠짐없이 지원한다.

## 현재 상태와 확인한 문제

배포된 `https://frontory.pages.dev/#threejs-01`은 첫 단원의 실습 절차에서 외부 `day-01.js`·`index.html`과 별도 기록 파일을 요구한다. 로컬 `content/curricula/threejs.json`도 별도 HTTP 개발 서버와 ES 모듈 프로젝트를 전제로 삼고 있다. 28개 단원과 4단계가 있고, 첫 단원은 장면 그래프와 카메라다.

`src/editor/CodeEditor.tsx`는 JS/TS만 편집한다. `src/preview/runtime-entry.ts`는 `mount({ THREE, OrbitControls, container, ... })`를 호출하며 반환한 정리 함수를 관리한다. `src/preview/document.ts`가 문서와 canvas CSS를 미리 정한다. 이 구조에서는 학습자가 HTML·CSS를 직접 구성하거나 공식 예제의 `import`를 그대로 사용하는 데 제약이 있다.

단원 자료에는 목표·절차·변수 비교·완료 조건·질문·참고 링크가 이미 있다. 이를 버리고 새 학습 시스템을 만들기보다 설명의 깊이와 실제 실행 가능한 과제를 보완한다. 첫 단원의 실행 코드는 부모 회전과 자식 좌표를 보여 주지만, 설명에서 요구하는 입력·출력과 실습 전부를 갖추지는 않았다.

저장은 단원 ID별 코드 문자열·언어·필기·진도로 구성된다. 백업은 알려진 단원 집합을 검증한다. 생성기에는 28개 단원·644개 전체 ID 검사가 있으므로 파일과 단원을 무작정 추가하면 저장·백업·생성 검사를 함께 바꾸게 된다.

WebGL 강의 이수와 행렬 계산을 입장 조건으로 요구하지 않는다. 좌표·축·각도·벡터의 의미는 필요한 시점에 작은 도식과 실험으로 설명한다. 행렬의 유도와 셰이더 구현은 심화 연결로 둔다. HTML의 canvas·input·output, CSS 크기, JS 함수·이벤트·모듈 지식이 부족하면 해당 Frontory 기초 단원으로 연결하고 현재 실습은 그대로 보존한다.

기존에 저장한 JS/TS 예제는 그대로 열린다. 새 HTML 시작 예제는 미저장 상태의 기본값으로만 사용한다. 저장된 코드가 있으면 새 실습으로 바꿀 수 있다는 안내와 명시적 불러오기 동작을 제공한다. 사용자 코드·필기·완료 상태를 자동 덮어쓰거나 초기화하지 않는다.

## 단원 내용의 공통 계약

각 단원은 아래 내용을 갖춘다. 항목이 있다는 이유만으로 완료 처리하지 않고 실제 학습 과제와 연결됐는지 검토한다.

1. 목표와 필요한 선수 지식: 이번 단원에서 만들 결과, 익혀야 할 개념, 내부 기초 단원 연결.
2. 개념 설명: 왜 필요한지, 객체 사이 관계, 수식이 등장한다면 각 기호의 의미와 수치 예시. 설명만 읽어서는 모호한 부분은 도식이나 조작 가능한 예제로 보완.
3. 단계별 코드: 시작 코드, 바꿀 위치를 찾을 수 있는 함수·요소 이름, 예상 결과. 줄 번호만으로 위치를 안내하지 않음.
4. 실험: 한 변수씩 바꾸고 실행 전 예상과 실제 결과를 필기에 기록. 시작 예제는 실행되지만 실험의 답을 모두 완성해 두지 않음.
5. 도움말: 흔한 오류의 증상·가능한 원인·확인 방법. 단계적 힌트와 해설·완성 예제를 별도로 열 수 있게 함.
6. API 참고: 단원에서 사용하는 API의 역할·인자·단위·기본값·반환값 또는 부수 효과·주의점·최소 예제. 메서드와 생성자의 차이를 정확히 표시하고 실제 사용하는 멤버까지 범위를 명시.
7. 완료 확인: 관찰 가능한 실행 조건과 학습자가 설명할 질문을 함께 제공. 사용자가 완료를 표시하며, 실행 성공을 이해도 자동 판정으로 취급하지 않음.

해설과 완성 예제는 읽기만 해서는 편집 코드가 바뀌지 않는다. ‘이 코드로 실습하기’를 명시적으로 실행하고 교체를 확인했을 때만 현재 코드와 언어를 바꾼다. Undo로 직전 코드를 복원할 수 있어야 하며 필기와 진도는 유지한다. 단계 이동이나 참고 설명 열기도 코드를 바꾸지 않는다.

첫 단원 예를 들면 `scene.add(mesh)`를 제거해 빈 장면을 만들고, camera 위치와 near/far를 바꾸어 물체가 보이지 않는 원인을 구별하며, 부모만 회전시켜 local과 world 좌표를 비교한다. 단순히 완성된 애니메이션을 보는 것으로 끝내지 않는다.

## 편집·정렬·실행

### 단일 HTML 문서

새 HTML 문서는 표준 `canvas`, `style`, `script type="module"`을 사용한다. `import * as THREE from 'three'`와 명시적으로 지원하는 addons import가 동작해야 한다. 첫 과정의 addon은 `three/addons/controls/OrbitControls.js`로 한정한다. 학생 코드에는 Frontory 전용 `mount`를 강요하지 않는다.

원래 JS/TS `mount` 실행은 기존 강의와 저장된 초안의 호환 경로로 유지한다. 실행 계약은 코드 언어만으로 추측하지 않고 단원 자료의 기본 언어·실행 종류와 현재 초안 언어를 함께 사용한다. 기본 언어는 자료의 `sourceLanguage`, 실행 프로필은 `runtimeProfile`로 명시하는 최소 확장안을 제안한다. HTML·JS/TS 외 문법은 이번 과정에 추가하지 않는다.

HTML 오류 복구는 브라우저의 동작을 따르며 ‘타입 검사 통과’라고 표시하지 않는다. JS/TS의 마지막 정상 실행 유지 정책은 유지한다. 오래된 컴파일·정렬 결과가 새 단원·모델·언어에 적용되지 않아야 한다. UI 언어만 바꾸면 실행 중인 iframe과 사용자가 입력한 값은 유지한다.

### 정렬

공통 Prettier 옵션을 재사용하고 명시적인 정렬 버튼과 편집기 명령을 제공한다. 타이핑·저장 때 자동으로 코드를 재작성하지 않는다. 파싱 오류가 나면 원문을 그대로 두고 위치와 원인을 안내한다. 성공한 정렬은 한 번의 Undo로 되돌리고, 결과가 같으면 불필요하게 저장하지 않는다.

HTML 문서의 들여쓰기만 바뀌어서는 부족하다. 내부 `<style>`과 지원하는 JavaScript `<script>`도 읽기 좋게 정렬해야 한다. 기존 공용 `embeddedLanguageFormatting: off`는 셰이더·HTML tagged template 값 보존 때문에 유지한다. 문서 정렬기는 파서의 위치 정보로 해당 style/script 본문을 찾아 각 parser와 같은 옵션으로 정렬한 뒤 HTML 바깥 구조를 정렬하는 제한된 방식을 우선 검증한다. 정규식으로 script 경계를 잘라내지 않는다. JSON import map은 JSON parser로 처리하고 미지원 script MIME은 보존한다. 본문 하나라도 실패하면 전체 변경을 적용하지 않는다.

공백이 의미를 갖는 HTML 본문·pre·textarea, JS 문자열·정규식·template, CSS 문자열이 유지되는지 검사한다. 이 계약이 검증되지 않으면 옵션을 바꿔 조용히 출시하지 않는다.

### 모듈 공급과 격리

현재 설치 버전은 `three@0.186.1`이다. 첫 구현에서는 이를 유지하고 core·addon·설명·예제를 같은 버전에 맞춘다. 공식 사이트의 최신 설명은 출처로 참고하되 설치된 패키지 소스와 타입을 대조해 API 계약을 확정한다. 패키지 업그레이드는 별도 변경이다.

우선 검증할 구현안은 기존 esbuild를 이용해 Three.js core와 OrbitControls를 사이트 소유 ESM으로 준비하고, iframe 내부에서 blob 모듈과 import map을 생성하는 방식이다. addon의 core import는 같은 Three.js 모듈 인스턴스로 해석돼야 한다. bootstrap과 import map을 사용자 module script보다 먼저 설치한다. 외부 CDN에서 코드나 패키지를 다운로드하지 않는다.

이 조립 방식은 아직 구현·검증하지 않았다. 구현 첫 단계에서 full HTML과 fragment, import 순서, 모듈 중복, 오류 표시, CSP를 확인하는 제한된 검증을 선행한다. 기존의 단순 prefix 방식은 head 속성을 잃는 사례가 이미 확인됐으므로 그대로 채택하지 않는다. DOM 실행을 일으키지 않는 HTML 파서의 위치 정보를 사용한 삽입을 후보로 삼으며, 부모 DOMParser 선파싱과 정규식 head 삽입은 사용하지 않는다. 파서 선택과 코드 분할은 구현자가 결정하되 아래 보존 조건을 충족해야 한다.

사용자 html/head/body 속성·lang·title·meta, 사용자 script 실행 순서, CSS 선택자 의미를 보존한다. iframe은 기존 `allow-scripts`와 CSP의 외부 통신 차단을 유지한다. 부모 DOM 접근, form 이동, 중첩 iframe 권한을 넓히지 않는다. 미지원 module import는 사이트 안에서 이해할 수 있는 오류로 표시한다. 사용자 import map과 공급 모듈의 충돌은 조용히 덮어쓰지 않고 지원하지 않는 설정임을 알린다.

오류와 제한된 `console.log/info/warn/error` 출력을 실습 화면 안에서 확인한다. 메시지는 현재 frame과 실행 token을 확인하고 텍스트로 렌더링한다. 순환 객체·너무 큰 출력은 안전하게 요약하며, 최근 200개 항목만 보관하고 항목당 4,000자로 제한하는 초기값을 제안한다. 콘솔 보존을 백업 데이터에 추가하지 않는다. 편집 코드 위치를 알 수 있으면 HTML 줄·열로 안내하고, 브라우저가 위치를 제공하지 않으면 추측한 줄 번호를 표시하지 않는다.

재실행과 단원 이동은 이전 frame을 종료하고 소유 blob URL을 해제한다. 문서 생명주기 이벤트로 정상 정리를 시도하되 마지막 경계는 iframe 제거다. 정리 함수 등록을 첫 장면의 필수 선수 개념으로 만들지 않는다. 기존 Monaco Canceled 오류의 원인 수정도 편집기 작업에 포함하며 전역 오류 무시로 숨기지 않는다.

## 자료·저장·번역

콘텐츠 원본은 `content/curricula/threejs.json`과 단원별 추가 학습 자료에 둔다. 기존 생성기에서 문서와 catalog를 만들며, 생성된 README를 따로 편집해 다음 실행에 사라지는 구조를 만들지 않는다. 공통 계약은 단계 배열, 단계별 시작 코드 경로, 힌트·해설, API 참조 ID, 선수 단원 ID 정도로 한정한다. 정확한 TypeScript 인터페이스와 파일 분할은 구현 계획에서 정한다. 다른 시리즈는 새 필드가 없어도 현재대로 동작해야 한다.

API 참고는 중복 본문을 복사하기보다 시리즈 내 API ID로 연결한다. 각 항목에 검증한 package 버전, 원문 URL, 확인일을 기록한다. 필요한 설명을 한국어로 직접 작성하고 공식 본문 전체를 복제하지 않는다. 복사한 코드나 자산이 있다면 그 항목의 출처와 라이선스를 함께 확인한다.

기존 한국어·영어 지원을 유지한다. 첫 4개 단원의 설명·힌트·실행 안내·오류·API 참고·시작 예제를 양언어에서 사용할 수 있게 한다. 코드의 API 이름과 식별자는 바꾸지 않는다. 기존 sourceHash 기반 번역 freshness 검사와 companion 원본 provenance를 유지한다.

단원 ID·초안 저장 키·Draft version 1·backup version 1/2/3을 유지한다. `html` 언어와 단원의 기본 언어 해석만 확장한다. 과거 language 생략은 JavaScript이며, 빈 문자열은 유효한 사용자 코드다. 기본 HTML은 저장 기록이 없는 경우에만 선택한다. 원본 복원은 새 단원 기본 소스와 그 언어를 복원하고, 기존 JS 시작 예제도 별도 읽기·불러오기 경로로 보존한다. 복원 버튼은 어떤 코드로 바뀌는지 확인 문구에 표시한다.

단원 내 단계별 코드를 자동 저장 버퍼로 늘리지 않는다. 사용자가 현재 편집하는 단일 코드와 필기·진도를 저장한다. 단계의 예제는 자료이고, 사용자 초안은 하나다. 여러 단계 결과를 보존하려면 기존 전체 JSON 백업과 필기를 사용한다. 초기 단계에서 계정·서버 저장·공유 프로젝트·협업 편집은 추가하지 않는다.

## 범위 밖과 후속 확장

첫 4개 단원은 기본 도형만 사용하므로 외부 이미지·모델이 필요 없다. 자산 기능 없이도 네 단원의 필수 과제가 완결돼야 한다. 임의 URL·npm 패키지·다중 파일 프로젝트·TS를 HTML module script에 직접 작성하는 기능은 첫 범위에 포함하지 않는다. 단일 HTML 안의 CSS·JavaScript와 기존 독립 JS/TS 편집을 지원한다.

후속 순서는 기하·법선·공유 자원 → 조명·재질·색 공간·텍스처 → 모델 로딩·선택 → 애니메이션·성능·자원 정리다. 전체 28개 단원과 공식 매뉴얼 주제의 대조표를 만들어 각 항목을 완료·보완 필요·후속으로 표시하되, API 전체 수록을 완료 기준으로 삼지 않는다.

텍스처·모델 단원에 들어가기 전에는 샘플 자산과 로컬 파일 선택, 경로·형식·용량 오류, 필요한 loader와 addon을 지원해야 한다. 외부 프로젝트에서 하라는 문구만 남긴 채 해당 단원을 자체 완결이라고 표시하지 않는다. 다중 파일과 자산 저장 방식은 그 단계에서 별도 설계한다. 첫 과정에 추측성 파일 시스템을 미리 만들지 않는다.

첫 과정 검증 후 HTML·CSS 시리즈에 같은 문서 실행·정렬·저장을 적용한다. React·Vue·Svelte 등은 각 문법과 실행 계약을 확인한 뒤 별도 적용하며 HTML 실행으로 모두 해결됐다고 간주하지 않는다.

## 구현 계획에서 정할 사항

학습 내용을 저장할 세부 JSON/TypeScript 구조, HTML 파서 패키지 선택, 파일 분할, 출력 창의 구체 배치는 구현자가 이 설계 안에서 결정한다. 모듈 공급과 문서 조립의 브라우저 검증 결과가 보존 조건을 만족하지 못하면 원인과 대안을 문서에 반영한 뒤 본 구현을 진행한다. 검증하지 않은 방식을 확정 구현처럼 보고하지 않는다.

제품 코드를 바꾸기 전에 이 설계를 검토하고, 승인된 범위를 파일 단위 작업과 검사 명령으로 나눈 실행 계획으로 옮긴다.
