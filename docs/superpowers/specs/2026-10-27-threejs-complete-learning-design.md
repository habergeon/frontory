# Three.js 28개 단원 자체 완결 학습

2026-10-27 요청에 따라 검증된 현재 상태를 운영 배포한 뒤 나머지 24개 단원을 개편한다. [기존 학습 환경 설계](2026-10-26-threejs-contained-learning-design.md)의 한 화면 학습·실습·기록 방식을 유지하고, [28개 단원 로드맵](2026-10-26-threejs-learning-roadmap.md)의 05~28을 실제로 구현한다. 이전 계획의 ‘후속 24개는 목록만 제공’이라는 범위 제한은 이번 요청으로 끝난다.

## 완료 기준

모든 28개 단원에서 설명을 읽고 코드를 바꾸고 결과를 관찰하고 필기할 수 있어야 한다. 외부 개발 서버나 별도 프로젝트 없이 로드맵의 필수 과제를 끝낸다. 기존 ID·URL·학습 순서와 저장 데이터를 유지한다. 14번 ID는 `threejs-02`, 28번은 `threejs-03`이다.

새 단원마다 개념을 나눠 가르치는 단계, 독립 실행 가능한 시작 코드, 예상 결과, 힌트, 완성 코드와 해설, 자가 점검 질문을 제공한다. 한 단계에서 바꿀 값과 관찰할 결과를 구체적으로 설명한다. 시작 코드와 완성 코드가 같은 과제를 해결한 상태여서는 안 된다. 시작 코드가 의도적으로 잘못된 경우에는 그 증상과 복구 목표를 명시한다.

핵심 API는 사이트 안에서 매개변수·반환값·주의점·짧은 사용 예를 확인한다. 공식 문서 링크는 더 읽을 자료이며 필수 과제의 유일한 설명으로 대신하지 않는다. 설치된 `three@0.186.1` 및 같은 버전의 addons와 공식 자료를 대조하고 확인 날짜를 남긴다.

한국어와 영어의 설명·코드 주석·HTML 조작 UI·오류 복구 안내를 함께 제공한다. 코드의 동작·숫자·ID·예상값은 언어별로 같아야 한다. 원문 해시와 번역 freshness 검사를 유지한다. 한국어 산문은 humanize-korean 룰북으로 최종 검토한다.

## 실행과 자산

현재 단일 HTML·inline CSS·module JavaScript 실행을 재사용한다. 새 모듈은 `three/addons/loaders/GLTFLoader.js`를 추가한다. core와 addon은 같은 Three.js 인스턴스를 사용한다. 외부 CDN과 원격 코드 로딩을 추가하지 않는다.

샘플 이미지와 모델은 프로젝트에서 직접 만든 작은 자산을 HTML 안에 포함한다. 이미지의 색 공간과 모델의 구성·애니메이션을 설명한다. 실제 TextureLoader와 GLTFLoader로 읽으며, 가짜 로딩 상태나 손으로 만든 결과 숫자로 대신하지 않는다. static·animated·empty·내장 이미지 GLB와 잘못된 입력을 재현할 수 있어야 한다.

로컬 PNG/JPEG와 비압축 self-contained GLB를 예제의 파일 입력으로 받는다. GLB 안의 PNG/JPEG도 지원한다. 다중 파일 glTF, 외부 URI 자산, DRACO·Meshopt·KTX2 decoder와 worker/WASM 압축 해제는 이번 범위에 넣지 않는다. 확장자만 믿지 않고 실제 파싱 오류를 표시하며 기본 샘플로 복구할 수 있게 한다.

iframe은 `allow-scripts`를 유지한다. Three.js module을 공급하는 HTML 실행에서만 `connect-src blob: data:`를 허용해 로컬 자산을 읽는다. `http:`, `https:`, `'self'`는 허용하지 않는다. 다른 실행 profile의 정책은 유지한다. 실제 브라우저에서 로컬 자산 성공과 외부 요청 차단을 함께 검사한다.

선택한 파일은 실행 중에만 사용하며 draft와 JSON 백업에 파일 내용을 추가하지 않는다. 파일 입력 옆에 이 제한과 다시 선택하는 방법을 KO/EN으로 안내한다. 기본 샘플은 파일 선택 없이 실행된다. 모델 교체·실패·늦은 완료가 기존 UI를 없애지 않도록 한다.

## 보존할 계약

- 단원 ID·초안 저장 키·Draft version 1·backup version 1/2/3을 유지한다.
- 과거 language 생략은 JavaScript이며, 빈 문자열은 유효한 사용자 코드다.
- 사용자 코드·필기·완료 상태를 자동 덮어쓰거나 초기화하지 않는다.
- 기존 JS 예제는 남겨 두고 새 기본 예제를 HTML로 연결한다. 예제 불러오기는 기존 확인·Undo 흐름을 따른다.
- 기존 첫 4개 단원과 학습·코드·결과·필기의 반응형 배치를 보존한다.
- 참고 문서 왕복과 UI 언어 전환은 단계·초안·필기·실행 화면을 불필요하게 초기화하지 않는다.
- 공용 `embeddedLanguageFormatting: off`와 Svelte P01 adapter를 유지한다.
- 자원 정리는 예제 안에서 설명하고 실행한다. iframe 종료가 모든 GPU 자원의 명시적 정리를 대신한다고 가르치지 않는다.

## 검증과 상태 표시

구현 상태와 사용자의 학습 진도는 별개다. 실제 실습과 내용 검토를 끝낸 단원만 `verified`로 바꾼다. 구현 중인 단원은 기존 자료를 계속 열 수 있다.

모든 새 starter·solution을 KO/EN 실제 browser preview에서 실행하고, 단계별 편집이나 입력이 기대한 결과를 만드는지 확인한다. 최소한 단원별 한 조건 변경은 실제 코드 편집→컴파일→iframe을 거친다. 결과는 화면·HTML output·실제 API 값으로 확인하며 기대값을 반복 출력한 테스트를 성공 근거로 삼지 않는다.

모든 28개 단원의 한국어·영어 진입과 1440/390 폭의 주요 조작을 확인한다. 관련 묶음마다 자산 오류·resize·선택·자원 정리 등 해당 목표를 검증한다. 마지막에 기존 첫 과정 회귀, 저장·백업·언어·문서 왕복, 전체 테스트·형식·빌드·배포 파일 한도 검사를 수행한다. Chromium/SwiftShader 확인을 실제 기기·모든 GPU·실제 학습자 평가로 표현하지 않는다.

기존 운영 배포 완료를 먼저 확인한다. 이번 확장 구현을 마쳤다는 이유만으로 새 원격 배포가 완료됐다고 보고하지 않는다. 배포한 커밋과 확장 구현 커밋을 구별해 기록한다.
